# ADR-248：未跟踪部署副本不随 merge-back 落地，真身修改后人工刷新登记

date: 2026-10-07
status: accepted

## Context

`bin/*.py` 是 git 跟踪的真身，`.fenix/bin/` 是其部署副本——但 `.fenix/*` 被 gitignore、该目录未被跟踪。实现车道在 worktree 内工作，worktree 从不含 gitignored 文件，merge-back 只回传跟踪文件：agent 对部署副本的任何改动（含删除）在主树必然空跑；而真身修改合入主树后，部署副本也不会自动跟上，两者静默漂移。

## Decision

部署副本的刷新是主树专属写操作，agent 不可交付：真身修改合入主树后，以登记在案的人工步骤承接（`.fenix/todo.md` 或 docs help 人工步骤节），注明「未跟踪文件不随 merge-back 落地，需主树手工同步或重启部署机制」。后续任何触碰 `bin/` 真身的 SPEC 都必须把该登记列为交付项，不得把部署副本当可交付目标，也不得为绕过而把 `.fenix/bin` 纳入跟踪（改变部署模型属另行立项）。

## Consequences

交付边界诚实：agent 声明面与实际可达面一致，不再产生「改了部署副本」的假交付；真身与副本的同步责任人明确为人。代价是每次 bin 真身变更多一道人工环节，漏做则运行实例继续跑旧副本——症状是「改了没生效」，排查时先核对副本与真身的漂移。
