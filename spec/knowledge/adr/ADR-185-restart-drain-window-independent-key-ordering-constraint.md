# ADR-185：restart 排水窗口独立键——新时间窗必须显式声明与既有协调窗口的次序约束

date: 2026-09-28
status: accepted

## Context

restart 触发的在飞 run 排水曾复用常规停机的 1800s 窗口：在飞 run 多数不会在窗内自行收尾，重启白等半小时，且一次重启仍杀掉 3 个在飞 40-70 分钟的实现 run——窗口长度既拖慢重启又没保住 run。supervisor 的 SIGKILL 等待已与排水窗口联动（窗口 + 固定余量），引入新窗时若不声明次序，监督者可能先于 daemon 排水动作强杀（历史上发生过 60s 宽限截断 1800s 排水的错配）。

## Decision

- restart 排水等待用独立配置键（缺省与监督者现状一致的短窗），常规停机窗口维持不变——规划性重启与停机语义不同，禁一键两义。
- 新增时间窗配置必须显式声明与既有协调窗口的不等式约束（新窗 ≤ 既有窗），保证监督者必然后于 daemon 排水动作、不截断排水，不等式由配置校验承载；对齐 ADR-022 的成对阈值纪律——同语义成对阈值仍派生自锚点旋钮，独立键仅用于语义不同的窗。
- restart 流程固定：收到信号 → 停新派发 → 向在飞 run 广播 checkpoint 信号（写 run 控制文件；有响应语义的车道收尾落盘进度，无则 best-effort 忽略）→ 等待排水至多新窗 → 超窗强杀走既有路径。
- supervisor 侧不改：联动量已由不等式保证。

## Consequences

- 排水过短杀掉本可收尾的 run 由 checkpoint 广播（提高窗内收尾率）+ 配置可调大兜底；「延长监督者宽限去匹配长排水」方向被否——重启等待本身就是要治的病。
