# ADR-175：code-fix 自动修复车道——框架编排批循环，合回铁律与双重白洗防线

date: 2026-09-28
status: accepted

## Context

仓库级代码审查入台账后 `open` 条目数百条，人工逐条勾选生成修复 SPEC 不可扩展。需要一条自动修复车道，但修复类 agent 直接改码：若无结构性防线，未经验证或零改动的批会被合回主树，仍然存在的问题被置成「已解决」且台账永不复原。

## Decision

- 批循环由框架编排，一批一次 agent run：选批 → run 修复并提交 → 框架在该 worktree 跑全量回归 → 通过才 merge-back 并把该批条目置终态。禁单个长 run 内自循环（断线全丢、失败不隔离、进度不可观测）；批间全量回归即天然节流。
- 运维车道纪律：与 code-review/regression 同理不走 spec 执行路径、不占 spec 预算与每日计数，框架自建 worktree 直跑。
- 合回铁律：未过全量回归不得合回、不得置条目终态；回归执行根在 worktree、主机级锁根锚定主树（执行根与锁根分离，防两套全量测试并行互扰），快照随执行根落盘、分面呈现以主树快照为准。
- 白洗双重防线：run exit 0 但产物行缺失/零有效 → 判失败；批内零有效修复（产物行全 skipped，或分支相对创建点零提交）同样不得合回不得置终态——merge-back 对「分支已是 HEAD 祖先」返回成功，「零改动 + 回归必过」会把问题批量置成已解决。skipped = 未修复，保持 open；条目终态只能由合回成功驱动。
- 回归契约缺失 fail-closed：契约整体缺失与仅缺回归段分信号分流起草（用错信号会令起草者重写有效且在服务的既有段），起草后下一轮再试；无回归证明即不合回是本车道唯一铁律。
- 批收尾必须释放 worktree（只有显式 cleanup 释放锁登记，漏释放则第二批创建直接失败、车道在首批后即死）；失败批保留现场 + 告警 + 台账人工项，后续激活对同批条目集合跳过防重复派发。
- 进度分母定格：激活链身份持久化，链内 total 不随 open 集缩小重算（否则出现「已处理 0/40」倒退），done 只计实际置终态数；自驱动链经再投递串联、周期扫描是链断裂兜底，两路激活幂等守卫（总开关/单飞/无 open/契约）任一命中不投递。

## Consequences

- 不替代人工「生成修复 SPEC」通道，两者并存；agent 类型四处注册缺一即退化（提示词文件/run 前缀/已知类型集/配置模板），模型链逐级回退至显式配置。
