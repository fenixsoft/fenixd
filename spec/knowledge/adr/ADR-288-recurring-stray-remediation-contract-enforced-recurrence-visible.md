# ADR-288：复发型散件根治义务挂处置契约铁律，复发计数随告警下发不做代码硬拦截

date: 2026-10-27
status: accepted

## Context

同文件散件反复触发 maintree_stray_wip_stale、反复以「仅提交」收尾的确定性复发已在无人值守下实证烧钱（三天两度处置各烧一条 admin run），而根治方案早已写明却无人消费——「留给人类决策」在无人值守框架里永不到来，被动挂账同样无人落 SPEC。处置质量属 agent 判断域，代码侧无法机械判定「哪些文件该根治」（误摘实为需共享的源件会丢基线）。

## Decision

根治义务挂在 admin 处置契约铁律层（agents/administrator.md）：同文件第 2 度处置起 MUST 当场根治（untrack 或等效）或挂显式跟踪项，MUST NOT 以仅提交第三次收尾；首次处置维持「提交+建议」不强制，保留一次判断窗口。代码侧职责限定为两件保证：根治路径一键可达（裁决选项 untrack_stray_wip），复发可见（复发计数以 AdminStore 既有同文件 SIGNAL 记录为台账检索、随告警 evidence 与 recommended_action 下发，不另建台账文件，检索失败按 0 轮退化为首发口径不阻断发射）。不实现代码硬拦截。

## Consequences

无人在场时根治决策材料在处置时点自足（义务可判定，不依赖 agent 考古历史记录），生成物类敞口一次 untrack 后由 .gitignore 自然止损；契约无代码拦截，理论上仍可能第三次仅提交——复发计数使违反可见，后续可按实效数据加硬闸，加闸前须先复盘契约运行数据。计数按文件路径匹配，文件改名后计数断档属接受代价（改名后的文件本质是新敞口，从 1 重计不放大风险）。后续为处置质量类义务加代码强制（拦截/熔断）须显式 supersede 本裁定。
