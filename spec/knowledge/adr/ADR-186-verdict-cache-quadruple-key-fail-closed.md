# ADR-186：verdict 缓存四元组全等才采信——存疑 fail-closed，PASS 同样入缓存

date: 2026-09-28
status: accepted

## Context

verdict 缓存机制已建但实测条目数为 0：写侧只持久化非 PASS 判定且每轮整体重写，读侧「通过场景采信缓存」根本无数据可采信——修复轮被迫全场景重验，验证工作占全历史 221h。缓存的另一风险是误采信：场景定义、被测构建、验证配置任一变化后旧判定失真。

## Decision

- 缓存采信键 =（场景 id，场景内容指纹，被测构建指纹，验证配置指纹）四元组全等才采信；存疑 fail-closed：出处标注缺失或指纹不全的场景不采信、照跑。
- 失效条件固化三条：场景定义变化（内容指纹不匹配）；修复 diff 触碰场景出处关联文件（出处 file:line 所在文件与 diff 文件集求交非空）；验证配置变化（配置指纹）。
- 写侧必须让 PASS 判定同样入缓存（否则读侧无据可采），条目补齐四元组分量（写入时计算），写入时机沿用判定采纳点；无分量可算的存量缓存条目不采信。
- 重验场景集 = 失败场景 ∪ 受影响场景 ∪ 其 depends_on 前置链（下游纳入防修复波及依赖方而漏验）；其余场景采信缓存判定写报告，报告中区分实跑与采信来源。

## Consequences

- 质量红线由四元组全等 + 出处交集 + 存疑 fail-closed 三重防线承担；缓存误采信是最大风险，宁可命中率为零也不放宽采信判据。
