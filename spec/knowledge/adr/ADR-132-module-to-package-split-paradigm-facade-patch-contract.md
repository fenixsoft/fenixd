# ADR-132：巨型文件包化拆分范式——改名入包、门面补丁契约与参数注入

date: 2026-09-21
status: accepted

## Context

巨型模块（dashboard/data 5297 行/227 处消费、agent_runner/runner 5087 行/164 方法、pm_engine/verification 6304 行/495 处回引）需要拆分，但三个结构性陷阱并存：① Python 同名包遮蔽同名模块——包目录一落地旧文件立即不可达，先建空包会让未搬移符号瞬间全部消失；② 门面 `from .mod import X` 是一次性值拷贝，`mock.patch("门面.X")` 只改门面绑定、子模块调用点读自己的全局——patch 静默失效（可变对象原地操作仍有效，重绑定/替换无效）；③ 测试以实例属性打桩替换方法，内部调用点若绕过门面直呼新模块函数，打桩静默空转、真逻辑生效。

## Decision

包化拆分按以下范式执行（已被三次拆分验证，适用于后续一切同类拆分）：

1. **改名入包再逐组摘出**：先把旧模块 `git mv` 为包内 `_legacy.py`（内容不动），包 `__init__` 显式逐条 re-export 全部公开名/私有名/模块级常量（禁 `import *`，它不携带下划线名），保证首个 commit 即全绿；此后每阶段从 `_legacy` 摘出一组、门面同步改指向，`_legacy` 空壳后删除。
2. **补丁缝隙是一等契约**：被测试以字符串路径 patch 的模块级名字在阶段 0 清点登记（如 `subprocess`、`commit_wip_checkpoint`、常量、结果类），拆分后必须仍可从原路径 patch 命中——受影响调用点改为经门面延迟解析（函数体内 `import 门面` 后取用），名字必须保留在门面绑定；「全量 pytest 通过」不能代替「patch 后断言 patch 生效」的专测。
3. **依赖参数注入，禁模块级回引**：提取到新模块的函数以宿主实例作显式参数接收门面依赖，MUST NOT 模块级回引宿主（循环 import）；被提取代码消费、且宿主其它代码也引用的模块级常量/辅助名随消费者同迁并由门面 re-export，维持既有导入路径。
4. **内部调用点走一行委托**：宿主保留同名方法一行委托且签名逐字不变，内部调用继续 `self.<方法名>(...)`——保住实例属性打桩的运行期替换有效性。
5. **子模块单向依赖**：子模块间互不 import，跨层引用在函数内延迟 import 或经组合根注入的组件引用完成；依赖注入的 context 只承载跨出该域的外部依赖，域内方法调用改经组合组件直呼，不经门面私有方法绕行。
6. **符号名锚定**：任务与交付物以函数名/模块名/import 路径锚定，MUST NOT 用绝对行号（后续 SPEC 会继续修改这些文件）。

## Consequences

- 全部消费点 import 路径零修改；搬移顺序按依赖度先叶子后中枢，「先注入（行为敏感、单文件内做）后搬移（纯结构）」使回归可定位。
- 阶段粒度 = commit 粒度 = 回滚粒度；新增巨型文件拆分直接复用本范式，不必重新踩坑。
