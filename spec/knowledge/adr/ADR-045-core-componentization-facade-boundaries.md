# ADR-045：core 组件化——组合提取 + 门面，组件单向回引，锁与状态同迁

date: 2026-09-07
status: accepted

## Context

`pm_engine.py`（4879 行）与 `agent_runner.py`（3068 行）各混杂 8 类职责，占 core 总量 51.5%；外部 API 面极小但测试触达 40+ 私有方法。Mixin 物理拆分只做物理分散，self 状态共享与归属问题依旧，组件不可独立测试。`verify_engine/` 的「包内拆分 + 主类导出」是 repo 内可行先例。

## Decision

- 巨文件拆分采用组合提取 + 门面：组件持有自己领域的状态与行为，门面（PMEngine/AgentRunner）只负责组装组件与生产编排（事件回调、handle_event）。拒绝 Mixin 物理拆分。
- 依赖方向单向：门面单向持有组件，组件内回引门面方法/状态一律 `self._pm.xxx`，禁止组件之间互相引用。
- 状态同迁纪律：锁与被保护状态必须整体同迁到同一组件，禁止两把锁或锁与状态分离；无状态依赖（config/state_machine/logger/project_root）构造注入。
- 巨方法不再细分，类间拆分为限；拆分保持行为等价，发现的 bug/死代码只记录清单不顺手修。
- 测试两步走：拆分期门面保留一行委托保测试零修改；随后测试调用点全部迁移为组件直调，门面收缩——仅被测试引用的委托删除，有生产调用者的方法一律保留（grep 全仓库零调用者才删）。测试模块粒度与 core 组件对齐（`test_<组件>.py`）。

## Consequences

- 新功能有明确归属边界，组件可独立测试；测试紧贴组件真实边界，比隔委托层诚实，但组件内部重构须同步改测试调用点。
- 增量测试选择（import 链推导 + 显式映射）是加速器不是全量替代：SPEC 的 verify 阶段仍全量跑，作为漏召回的锚点。
- 重构类 SPEC 的验收口径 = 行为等价 + 不引入新失败（基线环境性失败除外），回滚粒度为阶段 commit。
