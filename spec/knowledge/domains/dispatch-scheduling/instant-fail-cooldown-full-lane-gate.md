# 秒挂冷却全车道门控与到期复诵

<!-- knowledge: capability=instant-fail-cooldown-full-lane-gate rev=1
     sources=spec/archive/2026-10-30-evo-add-instant-fail-cooldown-full-lane-gate -->

进程启动类基础设施故障（秒挂）的熔断机制：门控面按故障面覆盖（出题/验证/管理员 spec 作用域派发全部过闸），到期恢复带故障复诵与翻倍——熔断在其故障面内真实生效、不再到期即重进故障循环（ADR-061 进程存活时长判秒挂）。

## 规则

- **判定口径**：进程存活低于 60 秒判秒挂；同一 spec 连续 3 次秒挂进入 300 秒冷却窗口；计数与冷却状态按 spec 维度、纯内存（daemon 重启即清）。框架主动 SIGTERM 的 run 不计入秒挂。
- **门控面按故障面覆盖**：implementer/fast-track/repair 派发（既有）+ planner-plan 与 verifier 派发判定（经 `_entry_dispatchable` 两个入口过闸，禁旁路）+ 管理员 spec 作用域处置唤起（与既有 signal-kill 冷却检查同点位并列判定）全部受秒挂闸门；daemon_errors 全局信号（spec=null）唤起恒放行——不锁死故障期的自救通道。`spec-review` 条目不入闸（其秒挂仍按既有 count≥3 续写冷却语义，属已知范围裁剪）。
- **命中语义**：冷却生效期的派发请求被跳过——不 pop 队列条目、不耗预算，冷却到期后自动重入调度。
- **跳过留痕可核验**：每次闸门跳过记 INFO 级日志（spec 名、被拦车道、剩余冷却秒数），门控生效可从生产日志直接核验、无需靠行为反推。
- **到期复诵与翻倍**：冷却到期恢复前先复诵判定——冷却窗内该 spec 仍有新秒挂记录（末次失败时刻严格晚于冷却起点；引发本次冷却的失败批次与起点同刻、不触发复诵）则不清零：翻倍次数 +1（上限 3 次、独立于秒挂连击 count），冷却时长按 min(当前×2, 2400 秒) 续写并重排恢复定时器（共用排程器按「截止时刻变化即重排」适配）；窗内零新失败或故障指纹消失才清零恢复。翻倍判定在查询侧状态清除前完成消费；查询侧读改写持锁临界区。翻倍上限保证最坏 40 分钟后必恢复派发，与悬空超时兜底保持足够代差。

## 关键行为

非门控车道的秒挂失败仍推高计数（触发更早的全车道暂停）——门控扩展后窗内非门控车道不再新派，计数爬升源头同步收敛。故障形态：连续秒挂 → 冷却窗（全故障面车道静默）→ 到期复诵（窗内有新失败即翻倍续冷，最多 3 次/2400s 封顶）→ 窗内干净才恢复派发。
