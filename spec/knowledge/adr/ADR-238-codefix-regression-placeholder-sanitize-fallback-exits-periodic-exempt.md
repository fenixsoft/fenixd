# ADR-238：code-fix 回归占位符消毒挂全部回退执行路径——判别读原件、执行用消毒副本，周期回归通道显式豁免

date: 2026-10-06
status: accepted

## Context

ADR-227 确立的批收尾回归两段式把 `{test_targets}` 定向化建在 fail-open 回退之上，但只有定向分支调用占位符替换：三类回退出口（链末批恒全量、触碰面映射空集、定向配置关）与定向重试轮（mapped 真假两态共用 ctx 原件 spec）都把含占位符的命令原样交给 Popen，而回归门面对字面占位符 fail-closed 无从替换。字面占位符传给 pytest 必挂（exit 4 无 JUnit XML → parse_error 进重试 → 用原 spec 重跑仍挂 → 耗尽定向重试预算整批弃），链末批挂则整链无法核销。定向判别又依赖原件里的占位符声明，入口盲替会杀掉判别——消毒与判别因此必须在层的两侧分工。

## Decision

三段裁定，约束后续一切触碰 code-fix 回归执行链的实现：(1) 消毒义务挂「回退执行」而非「定向执行」：凡批回归从定向退回全量（现有三类回退出口及未来新增出口）或进入定向重试轮（mapped 真假两态统一），命令含 `{test_targets}` 时执行前必消毒为缺省 `tests/`（str 与 list 两态、返回副本不改写原件），无占位符命令逐字不变；新增回退出口必须沿用同一消毒包装，否则视为放弃该保证。(2) 判别读原件、执行用消毒副本：定向判别永远以 ctx 原件 spec 的占位符声明为准，消毒只发生在回退出口返回值与重试轮执行侧，MUST NOT 在 ctx 入口盲替。(3) 周期回归通道显式豁免：该通道定义上即全量、无 targets 概念，参数位占位符属配置错误而非框架义务，由 config.template 安全样例与 MUST NOT 参数位警示兜底；该通道未来如需定向化必须另立条目，不得借消毒义务顺带扩面。

## Consequences

回退路径不再被字面占位符引爆，整链核销不再因回退出口挂死；消毒后 `tests/` 成为可替换收集目标，定向重试轮 mapped 态子集语义随之恢复。代价：配置了占位符的项目其「回退全量」被消毒缺省定义为 `tests/` 树收集，项目须保证 `tests/` 是其全量代表（config.template 安全样例承载该契约；env 缺省展开 + 注释位的 fenixd 自身安全形态消毒后为无害 no-op）；消毒包装对含占位符但语义上不该替换的命令无豁免通道，特殊写法只能走 env 展开形态规避。
