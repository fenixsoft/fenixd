# ADR-204：WIP 等待标志生命周期不变式与「自愈先于召唤」

date: 2026-10-02
status: accepted

## Context

spec 车道合回被 WIP 重叠闸门拦截后，现场只剩 error 文本（无结构化等待载体）、无运行期消费者、`_merge_retry_pending` 无读取点：主树 WIP 清掉后 spec 仍卡在 implementing+error，15 分钟后叠加 orphaned_state major，兜底是「两次 admin 召唤」（实证 2026-09-23 一次阻断烧一条 major 加一轮 48 轮 admin 处置 run）。修复方向是等待标志 + daemon 周期自动合回，但这引入两个新的架构约束需要裁定：标志的生命周期如何保证消费者不与在飞 run 竞态；等待期条目如何不被孤儿探测当真孤儿召唤 admin。

## Decision

- **暂态阻断必须落结构化等待标志**：布尔 + 重试计数 + 首阻时刻，随 `update_spec` 持久化往返；error 文本只作取证，禁作唯一现场标志（无载体则无消费者，一切自动合回无从谈起）。
- **标志生命周期不变式：implementing 且带标志 ⇒ 无在飞实现 run**。不变式由三类清账写点构造性保证——合并成功清账、boot 保留续做复位、boot 清空重建复位；周期消费者凭此免查活动 run。后续任何新增标志写点的 SPEC 必须同步补齐复位写点，否则不变式破产。
- **自愈先于召唤，豁免与降级同源**：周期消费者节拍必须短于 orphaned_state 阈值（120 秒 vs 15 分钟），使「WIP 清了自动合回」先于探测生效；等待期豁免与停止重试降级必须消费同一超限判据（同一组常量跨模块导入，禁两处独立阈值），保证「豁免失效」与「降级告警」严格同步，admin 只见真冲突与超限。
- **既有重试入口守卫只放宽不收紧**：merge-only 重试入口的状态守卫只拦「status 非 implementing」（跳过并清账），禁收紧为「须带 wip 标志」——不破坏既有只带顺延标记的调用链；带标志的严格筛选放扫描层。

## Consequences

- 最贵失效形态是漏清 boot 保留续做写点：重启后陈旧标志会在恢复 run 在飞期间把半成品分支过早合入主树，并与在飞 run 收尾竞态——两类复位写点缺一不可。
- 豁免与降级若双源阈值，漂移后果是「一边已停重试一边继续豁免」（真孤儿被遮蔽）或反向（等待期照常成条重复召唤 admin）；单源常量是防漂移的唯一手段。
- 等待计数与 spec 目录顺延共用记账，同一 spec 先后经历两种阻断时窗口/轮数混合累计、wip 降级预算可能被顺延轮数加速消耗——已知接受，不引入第二套计数。
- 真内容冲突不属等待范畴：清标志交回既有失败通道，不尝试自动解决内容冲突。
