# ADR-262：STATE 类型字段复位写类型零值、布尔清单不纳非布尔字段、写侧形状拒绝优先于静默归一

date: 2026-10-09
status: accepted

## Context

STATE.md 以 Python 字面量序列化、跨进程往返读回。spec attrs 的 `_verify_parallel_override` 契约为 int|None（降档并行度或复位），人工裁决复位点把它与布尔标记一起清成 False 后：该字段不在布尔归一清单（只在 null 清单），False 整段字符串化落盘、读回字符串 'False'，读端 int() 解析失败降档告警；且两个处置动词每次执行都重写，复发确定。写入路径（update_spec/_apply_updates_entry）无逐字段类型校验，任何非法形状都能静默序列化进 STATE.md。ADR-155 只覆盖布尔字段的读侧归一化，类型化字段（int 覆盖值/计数器）无对应纪律。

## Decision

- STATE 持久化字段按类型契约管理：非布尔类型字段的复位一律写类型零值（覆盖类字段写 null 表复位语义），不写布尔值；布尔归一清单只接纳登记过的布尔字段——把非布尔字段注册进布尔清单是反模式（会把合法降档值字符串 '2' 误转 False）。
- 写入侧对有类型契约的字段设单字段形状守卫：布尔/字符串/浮点等非法形状拒绝写入并告警留痕，不静默序列化进 STATE.md；拒绝优先于静默归 null（归一过宽会掩盖真实坏值）；只剥违规字段，同批其余更新照常应用（bool 是 int 子类，判定先排 bool）。
- 解析侧按类型登记归一（int|None 等，null 兼容）兜存量坏值首读清洗，须幂等；归一带来的可观察类型变化（字符串 "2" → int 2）须同轮更新既有断言，不静默留红。
- 读端对不可解析值降级到安全缺省（沿用配置并行度）并告警留痕值 repr 与字段来源；禁止把布尔语义映射为特定领域值（布尔→并行度 1、int(False)=0 均为对写方复位意图的扭曲）。

## Consequences

人工处置不再向 STATE.md 注入类型外形状，复位语义一次写对、无复发面；存量字符串化坏值首读自愈；坏值在写入边界被拒并留痕而非静默污染；同批处置不被单字段牵连。代价：新增类型字段须同步登记解析归一与（如可被外部写路径触达）写侧守卫，登记缺位由读端告警留痕兜底暴露。
