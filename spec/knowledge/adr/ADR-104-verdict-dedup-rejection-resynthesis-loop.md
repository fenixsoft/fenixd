# ADR-104：裁决查重拒绝必有出口回路，按场景子集回炉

date: 2026-09-18
status: accepted

## Context

归因查重门拒绝后原本无出口：不落盘违规、不重派、不升级，spec 卡 testing 直到 stuck 阈值触发全量重跑——$10+ 级单轮产出整体废弃。「judge 下轮修文后自然通过」的注释声称的回路并不存在。门本身行为正确（批量模板归因拦对了），缺的是拒绝之后的机制。

## Decision

- 任何校验 / 查重拒绝必须闭合出口回路：拒绝事实落盘（违规清单含场景 id 与重合成指令）→ 定向重试 prompt 注入（只重写清单内场景的归因字段、其余原样、禁止复现 / 调查 / 改判定）→ 重合成 run 返回后同一入口再过全链校验（不走旁路）→ 连续拒绝有界升级（blocked + escalation 告警）。
- 重合成复用既有轻量 judge 重试通道，不新开 agent 类型：免费继承冻结门、取消旗标、stale-result 防护与产物硬门的全部防御语义；新 agent 类型要在四处同源扩展且丢防御，收益不抵复杂度。
- 回炉粒度按场景子集：归因逐场景条目落盘（同一产物文件内组织、读侧兼容旧整块结构），查重命中置 requeue、其余 accept；部分重复静默回炉子集，全量重复保留整批拒绝的 escalation——查重防御本意（拦模板化归因）不因粒度细化而弱化。
- 归一化指纹细分 + 级联豁免：步骤序号 / 断言清单进指纹；同分类且共享根因短语、但失败步骤与断言各异的合法级联形态不计入查重；纯模板复制（连步骤引用都相同）仍拦。

## Consequences

- 拒绝成本从「整轮废弃 + stuck 全量重跑」降为分钟级轻量重合成（只读既有报告改归因字段）；连续拒绝两轮即升级止损。
- 单根因级联失败不再被误拦；「拒绝必有出口」成为一切查重 / 校验门的标配形态。
