# ADR-122：已实现未合并窗口——锚点随 run 终态落盘，待合并以 git 事实为据

date: 2026-09-19
status: accepted

## Context

「已实现/已修复、未合并」窗口对恢复链与巡检双双失明：STATE 的 branch 只在 merge-back 成功后写入，repair 通道全程不写，daemon 重启后叫不出分支名只能清空重写；排水正常完成时保护集退化为空集，orphan 清理删掉仍在 git 注册表里的 worktree。消费侧同样误判：recovery watch 在该窗口（状态不在进度集、worktree 已清、非 ready 不重派）报 dispatch_stalled，产出无效 admin run。

## Decision

- branch/implementer_run 写入时机从「merge-back 成功」提前到「run 终态成功」，字段语义为「本轮实现分支」；不新增平行字段——双字段并存必然漂移，「哪个是真的」成为新 bug 温床。写入点定序在全部 merge 前置闸门早退之后，且新轮次派发前失效旧锚点（否则上一轮已放弃的分支会在重启时压过本轮在飞成果）。
- 该窗口的活性判据 = 分支存在**未并入 main 的提交**（rev-list 计数）；「分支存在」禁作判据——实现成功路径保留分支（库存量上千历史分支），恒真判据会把真实 stale 永久洗成健康。
- 候选归属用「完整 spec 名 + 分隔符边界」全等比较，禁 glob 前缀匹配（spec 名互为前缀，实测跨 spec 误配）；枚举前缀与分支**创建端**同源——配置值不是创建端事实源，仅按配置枚举会扫空命名空间、回落静默失效。
- 豁免必须有界：宽限自过渡起点（max(最新未合并提交时间, 收工痕迹时间)，提交年龄会预消耗宽限）起算，超时回落既有 stale 判定；宽限必须短于复查间隔，使回落在下一次复查即可观测。
- 停机保护集由 STATE 状态驱动（遍历在飞 spec 的在册载体），不由事件可见性（排水是否超时）驱动——收口是否完成与排水超时是两件事。
- 与 ADR-114 同链：ADR-114 的「只改读取方容错、不改写入语义」收窄为「在飞不写」这一不变量保持不变；run 终态成功即写锚点是本裁定的修订口径。

## Consequences

- daemon 重启可从 git refs 找回「已实现未合并」的成果并续做合并；真实 stale 在宽限到期后照常告警。
- branch 非空不再隐含「已合并」，合并事实以 git merge-base 判定（消费点已普查，唯一相关点本就问 git）；保护集扩大由在飞 spec 数量有限自然约束。
