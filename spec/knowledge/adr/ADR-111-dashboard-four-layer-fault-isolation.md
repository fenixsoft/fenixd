# ADR-111：dashboard 多项目管线四层故障隔离

date: 2026-09-18
status: accepted

## Context

单个不可读目录（磁盘 EIO）穿透发现 → 聚合 → 缓存 → 前端四层，整页 500 且每请求重炸：`is_file()` 吞 ENOENT 不吞 EIO、发现循环无异常隔离、ignored 过滤位于探测之后（逃生通道失效）、缓存异常不推进时间戳（TTL 恒过期导致每请求重跑注定失败的发现）、前端请求失败清空已展示数据。

## Decision

- 探测显式捕获 OSError 并按 errno 分流：ENOENT 是正常业务分支（无 STATE.md）静默跳过；EIO 是故障写 WARNING——os.path.isfile 的黑盒吞异常无法区分二者，不可用。
- ignored 过滤前移到一切可能抛异常的探测之前（基于规范化路径匹配）：「过滤先于探测」是可断言的契约。
- 发现层容错只做「跳过 + 日志」，不构造 degraded 条目（UI 静默）；不可读目录从列表消失仅日志留痕，ignored 通道是逃生口。
- 聚合层逐项目隔离：单项目失败降级为该项目卡片的 error 字段（复用既有 schema 键），不累加其对 totals 的任何贡献；不在 handler 层做一次性兜底——那只能把整页 500 换成整页降级，无法定位坏项目。
- 缓存异常保留上次成功结果且时间戳无条件推进：只在成功时推进会让 TTL 恒过期、每请求重炸；失败后按 TTL 节奏自然重试，兼顾恢复速度与故障期负载。
- 前端请求失败不清空已成功数据：保留 stale 快照 + 错误提示 + 重试入口；仅首屏即失败才渲染纯错误页。

## Consequences

- 单个（乃至多个）坏目录不再打挂概览、不再放大故障期负载；一次刷新失败不再整页空白。
- 代价：目录整体不可读的真实项目会静默从列表消失（日志可查）；聚合层宽 except 可能吞编程错误——错误文本进 error 字段 UI 可见，不静默丢失。
