# 能力规格：蒸馏重试台账欠账龄期升级与节流

## 概述

规范蒸馏重试台账（.fenix/todo.md 未勾选蒸馏重试行）中未处置欠账的告警行为：龄期展示、超期升级、升级对现行持久节流的穿透。节流的持久化与跨重启语义本身已由 evo-fix-distill-retry-ledger-auto-close 落地，本 SPEC 不重建该机制。

## 行为规格

1. 发射条件：维护检查点发现台账存在登记超过 24 小时（按行归位日期节本地零点起算）的未处置欠账时发 knowledge_distill_retry_stale 信号（kind=SIGNAL）——现状语义保持。
2. 龄期展示：信号 description/evidence 必须包含欠账条目登记时刻（现行日期节零点口径，天粒度）、当前龄期（小时/天）与对应归档 spec 名；recommended_action 不得再指向已排除的模型拒识（unrecognized_model）假说。
3. 超期升级：同一欠账龄期超过 72 小时仍未处置时，信号在同一 kind=SIGNAL 通道内升级为 severity=major（不使用 kind=ESCALATION），升级态信号同样携带龄期；台账条目处置（勾选/移除）后发射自然停止。
4. 节流语义：同一欠账的重复发射受现行持久节流约束（.fenix/knowledge-distill-retry-state.json，日粒度 + stale 集合指纹口径），节流期内不重发；节流状态跨 daemon 重启有效，不得依赖进程内存态幂等。本 SPEC 不引入第二条节流机制、不放宽现行「至多每日一条」节奏。
5. 升级穿透节流：龄期跨过 72 小时门槛后的首次发射不被节流吞掉，立即发出升级态信号；穿透仅在级别提升边沿触发一次，其后同级发射回到现行日粒度节流。

## 验收

- 龄期字段存在且与台账登记日期节零点同源一致。
- 72 小时边界前后发射级别符合规格（<72h warning、≥72h major）。
- daemon 重启后节流期内不出现重复发射（现行持久节流语义不回归）。
- 升级首射穿透节流；穿透后同级后续发射仍受节流。
