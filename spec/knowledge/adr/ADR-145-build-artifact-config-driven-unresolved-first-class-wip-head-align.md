# ADR-145：构建产物判定完全由项目配置驱动，未裁决为一等状态

date: 2026-09-23
status: accepted

## Context

merge-back 链路需要把产物（可再生的构建投影）与语义内容分开处理：产物不该进冲突预演闸、不该在 WIP 重叠闸门里触发 stash 与 pop 冲突误报。产物判定若内置任何写死的默认路径集合，描述的是某一个仓库的产物形态：对被管项目既漏判真实产物、又把无关路径当产物豁免区，还掩盖配置缺口（判定「照常工作」而配置从未被设置），且无法表达「该项目没有产物」。

## Decision

- 判定器为实例持有的可配置匹配器：项目显式声明产物根前缀（`/` 结尾）与产物文件通配（匹配完整相对路径不匹配 basename）；显式配置而非从构建命令自动探测——产物根是项目结构事实，从构建命令反推会把产物下手写文件误判为产物。框架不内置任何路径默认值，判定恒假不再承担「缺省」语义。
- 三态判定表以「未裁决」为一等状态：未裁决 / 已声明有产物 / 已声明无产物三者可区分——空列表不当哨兵用（无法区分未裁决与声明为无）；布尔或列表非法一律落未裁决。
- fail-safe 方向 = 判定不放宽：配置解析任何异常落未裁决（判定恒假）并照常触发起草信号，MUST NOT 出现「因配置形态非法而既不判真也不告警」的静默中间态。
- WIP 重叠闸门对产物子集在 stash 之前对齐 HEAD（产物是 src 投影、merge 后由构建重建，纳入重叠集合只会制造必然的 pop 冲突与误报告警）；对齐只作用于重叠子集——主树独有、分支未触碰的产物脏改动 MUST NOT 被对齐（那会把用户本地构建成果静默抹掉）；对齐失败逐路径回落既有 stash 语义，不阻塞 merge-back、不改宽判定。
- 未裁决的兜底信号放在「需要区分产物与语义」的唯一上游咽喉处触发（下游分类点更早但属结果侧），复用既有 admin 起草信号全链路；setup 尽力探测填写、已显式配置不覆盖，两者并存不冲突。

## Consequences

- 产物语义由项目声明，merge-back 不再产生纯产物形态的 stash pop 冲突误报；默认行为收敛为显式声明的保守侧。
- 去默认值对存量项目是 BREAKING 语义切换，部署顺序必须先回填存量配置再升级 daemon；「产物重建触发作用域」与「产物判定口径」是两回事，前者可继续限定框架自身范围。
