# 裁决缓存复验

修复轮重验的场景集裁剪与 verdict 缓存采信契约：只跑「失败场景 + 受修复影响场景 + 前置依赖链」，缓存键四元组全等、失效条件固化、存疑 fail-closed。

## 现行规则

- 缓存键与失效条件：verdict 缓存条目的键为四元组（场景 id, 场景内容指纹, 被测构建指纹, 验证配置指纹）的全等匹配，任一分量不同即视为失效。失效条件固化为三类：① 场景定义变化（内容指纹不匹配）；② 修复 diff 触碰场景出处关联文件（场景 description 末尾标注的出处 `文件:行号` 所在文件，与本轮修复 diff 触碰文件集求交非空）；③ 验证配置变化（配置指纹不匹配）。
- 出处标注缺失或任一指纹不可计算的场景视为不可缓存：不采信其缓存判定、照常执行（fail-closed）；被测构建指纹变化本身不自动失效全部缓存（文件级判据以出处关联文件交集为准）。
- 写侧同步扩展：PASS 判定条目与四元组分量（被测构建指纹、验证配置指纹，写入时计算）一并持久化；写入时机沿用 verdict_cache 机制（judge 判定采纳后落盘），格式改动落 `core/verdict_check.py`。
- 重验场景集裁剪：修复轮（bug-found 后的重验、gate 重试重验）进入场景执行前，实际执行场景集 = 本轮失败场景 ∪ 受修复影响场景（失效条件命中者）∪ 其 `depends_on` 前置依赖链（递归）；未入集且缓存有效的通过场景采信缓存判定写入验证报告（标注来源为缓存），MUST NOT 重复执行。
- 裁剪边界：首轮验证与场景集冻结复用轮不受裁剪影响（全量执行）；裁剪后实际执行场景集为空（理论边界：全部通过且无失效）时按零执行、直接出报告处理，不视为异常。
- 缓存消费零新增打回：缓存读取、指纹计算、裁剪判定的任何异常（缓存文件损坏、指纹字段缺失、依赖环）MUST fail-open 回落全量执行，记 WARNING 后继续；MUST NOT 判验证轮失败、MUST NOT 新增任何打回/重试门禁。
