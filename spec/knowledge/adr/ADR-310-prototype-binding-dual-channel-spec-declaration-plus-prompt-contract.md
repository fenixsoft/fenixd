# ADR-310：原型绑定力双通道——SPEC 声明为主通道、派发契约段为对照通道

date: 2026-11-02
status: accepted

## Context

批准的原型必须对 AI 实现产生实际约束力，纯视觉参照无约束力等于白做。约束力要同时覆盖两个读者：读 SPEC 正文的实现/评审 agent，以及派发提示词本身。只改 SPEC 声明则评审缺乏强制对照点，只改派发提示词则声明游离于 SPEC 真相源之外、用户裁决无处落账。

## Decision

原型绑定力由双通道共同承载：第一通道是 SPEC Scenario 显式声明 `specs/<spec>/prototype/` 为 UI 真相源，与「数值以 Scenario 为准」同纪律等级；第二通道是 `agents/implementer.md` 与 `agents/code-review.md` 的条件式契约段，开关恒为 SPEC 内声明本身。冲突仲裁顺序固定：实现与原型冲突时，有用户裁决记录以裁决为准并把裁决记入 SPEC；无裁决以原型为准并升级用户，评审对冲突 MUST NOT 自行放行。契约段为条件式措辞，对未声明原型的 SPEC 零影响。

## Consequences

- 原型批准流程必须回填 SPEC 声明，否则契约段整体不触发——「声明缺失」等价于「无绑定力」，这是设计内语义而非遗漏。
- 条件开关使全部无原型 SPEC 行为零变化，代价是契约段生效性依赖声明回填步骤的纪律。
- 后续任何「以派发提示词承载跨车道契约」的扩展（新的真相源类型、新的对照维度）应沿用「SPEC 声明为主通道 + 条件式契约段」同构模式；要单通道化或改仲裁顺序须显式 supersede 本 ADR。
