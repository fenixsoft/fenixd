# ADR-154：新终态事件必须写读两侧同步登记，缺任一侧即永生 running

date: 2026-09-25
status: accepted

## Context

run 产物终态类型的判定散布两处：写侧权威终态集合（在跑判定、删除/归档保护的存活依据）与读侧状态映射（时间轴着色、归档集、活跃计数）。新增终态类型只登记一侧，另一侧把它判 running：时间轴永显在跑，或删除/归档被「有进行中的运行」误拦、有界等待超时后删除失败。

## Decision

- 写侧新增终态事件类型 MUST 同时登记：读侧状态映射与写侧终态集合，两处各有用例锁定。
- 新终态的下游消费点逐处复核：归档判定集合由映射派生（自动纳入，用例锁定）；活跃计数只认 running/empty（自动正确）；预算计数只认末行 `type == "error"`——非 error 终态（门禁拒绝等）计入已耗预算、MUST NOT 豁免；存活探测不再把该文件作存活依据（文件已无写入者），与「弃置行故意排除存活」的差异必须写代码注释，防后人统一口径时踩雷。
- 门禁路径终止 attempt MUST 在该 attempt 文件末行写终态事件（对齐终态后置不变量；指标行尾随终态行属既有常态）；reason 按分支穷举取值，禁一个值糊过所有分支。
- 被接管的让位分支 MUST NOT 写门禁终态——其弃置原因是接管而非门禁拒绝，误标会产生同次失败双失败节点；中间弃置行保持中性呈现，失败归因由紧随的终态节点承担。

## Consequences

终态枚举扩展成为「两侧登记+下游清单复核」的机械义务；时间轴呈现、删除/归档保护、预算对账三面对同一终态判定一致。
