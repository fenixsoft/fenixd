# 审查遗留缺陷修复消化

<!-- knowledge: capability=deferred-findings-fixes rev=1
     sources=spec/archive/2026-09-22-fix-deferred-findings -->

对历史重构/审查遗留疑点清单的清算批治理：逐条显式处置、证据齐全、与在飞作业面隔离。

## 规则

- 遗留疑点清单中未修复且不在在飞重构 SPEC 作业面内的条目必须逐条处置：每条显式标注为「零行为变化」或「有意修复行为」，并给出可验证的测试证据；确认为「记录不修」的观察项必须在 design 中显式登记并给出理由，不得静默丢弃。
- 真 bug 修复必须带回归测试，并同步更新把旧错误行为锁死的 characterization 测试——新测试断言修复后的行为结果而非异常。
- 性能修复必须保持结果集语义逐元素一致（如端口探测改造前后的 `pre` 端口集合完全相等），不得改变下游输入语义。
- 标注「零行为变化」的条目修复后可观测行为不变：全量测试失败集合相对基线不新增失败。
- 与在飞重构 SPEC 的作业面文件严格隔离：落在其作业面内的疑点条目显式登记为「转移清单」由对应重构 SPEC 承接，本变更不得修改；变更 commit 的改动文件集与在飞作业面清单无交集。
- 任务与交付物以函数名/符号名锚定，不得使用绝对行号。
