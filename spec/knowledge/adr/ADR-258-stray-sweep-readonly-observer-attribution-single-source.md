# ADR-258：主树散件盘点为只读观察者车道——占用归因单源复用、无空闲预检、零触碰仅报告

date: 2026-10-08
status: accepted

## Context

主树散件 WIP 周期盘点需要回答「这批未提交改动归谁」：在飞实现车道持有则等待，无主才升级。占用车道判定在合回 WIP 协调能力中已有机械实现（`identify_wip_occupant`：在飞 run 分支相对主树 HEAD 的三点式 diff 与改动集求交，数据源为 worktree 注册表真相），盘点若自建第二套求交逻辑，两处归因口径必然漂移。同时盘点挂在 daemon 主循环上、与 merge-back 的 stash→merge→pop 写临界区共享主树，接线不当会要么互相踩踏、要么把在飞车道全部误判成无主刷屏升级。

## Decision

- 主树 WIP 占用归因单源：一律复用 `identify_wip_occupant`（`WipOccupantInfo`），禁重造求交/注册表探测逻辑；后续新的占用判定消费者同样收敛到该单源。
- 观察型归因消费者禁设「无在飞 run」空闲预检：加了预检就永远看不到在飞车道、全部按无主误升级；必须把在飞实现车道 run_ids 传入归因。空闲预检属于「要不要做某事」的闸门语义，不属于只读观察者。
- 盘点为旁路只读观察者：主树锁非阻塞 acquire、锁忙弃轮，绝不与写临界区并发、绝不阻塞主循环；git 子进程限于只读白名单，禁 stash/pop/checkout/clean/reset；框架仅报告，处置权完全留给人工程序。不改动 autostash 路径、reclaim「脏不抢」语义与 WIP overlap 闸门任何现行行为。

## Consequences

- 归因口径全框架单一：合回协调与散件盘点对「谁持有主树 WIP」的判定不会分叉；盲区（主树直改形态必零命中、按无主走宽限）随之共享，误判影响有界（升级仅为告警）。
- 观察者零互扰的代价是时效：锁忙弃轮、持有者命中即 defer，散件浮出依赖周期重试，不追求一次性全量盘点。
- 处置自动化诉求（代提交/代 stash 等）不得在本车道内实现，须走人工程序/人工裁决通道；若后续要赋框架自主动处置能力，以显式新裁定 supersede 本条。
