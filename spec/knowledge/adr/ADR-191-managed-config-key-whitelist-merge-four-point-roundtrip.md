# ADR-191：受管配置键必须走白名单合并全链路——四处必改点、禁挂只透传子键的既有段、读写往返验收

date: 2026-09-17
status: accepted

## Context

Dashboard 配置保存走受管键白名单合并：patch 中未显式列出合并分支的键不报错、被静默丢弃。本仓已两次同型事故（成本预算键、daemon lifecycle 键缺合并分支）——保存返回成功但值消失；且既有段存在只透传部分子键的合并分支，其余子键一律吞掉。新增配置键若只加界面不补合并链路，「保存成功、值蒸发」结构性必现，且只在下次读取时才暴露。

## Decision

- 受管键（dashboard 可写配置）新增必须四处同步：白名单合并分支、写入口前置校验、键来源映射（缺则「继承自用户级」标注失真）、缺省回显基线（缺则界面回显为空）。
- 新键禁挂进只透传部分子键的既有段（会被该分支吞掉），必须自立顶层段并自带合并分支与前置校验。
- 验收必须含读写往返断言（保存 → 重新 GET → 值仍在），禁只断言保存返回 200——两次历史事故均为保存成功但值消失，往返断言是该事故类的最小有效验收件。
- 作用域纪律：项目级键的设置卡片沿用既有 scope 约定——用户级作用域只读、collect 返回空补丁，仅项目级可写；禁把项目级键写进用户级配置。
- 配置键与界面能力同步交付：新增配置项必须带 Dashboard 设置界面与文档同步，禁产生无界面的孤儿键。

## Consequences

- 配置面扩张的静默丢弃通道被结构性封堵；「保存成功」不再是生效证明，往返断言成为配置类 SPEC 的标准验收件。
- 代价：每新增一个受管键的接线成本固定为四处 + 一条往返用例；跳过任一处的省略都会在验收期（而非用户报障时）暴露。
