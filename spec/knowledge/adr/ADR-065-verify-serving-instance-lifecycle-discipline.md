# ADR-065：被测实例按 run 生命周期管理，收割单点收口，绝不静默回退主树实例

date: 2026-09-11
status: accepted

## Context

验证被测服务（dev-server、command 型被测实例）的生命周期若靠逐终态分支清理必然遗漏——异常、冻结早退、熔断拦截、日限等任意路径都可能跳过清理（已被事故实证），孤儿累积最终耗尽端口段；端口耗尽若再静默回退主树常驻实例，验证流量会打到旧码上，验证形态被污染。跨轮常驻复用看似省启动成本，实则拉长进程寿命放大孤儿概率，且常驻实例本身就是旧码污染源。

## Decision

- **不跨轮常驻复用**：被测实例按 run 生命周期创建与收割（worktree 目录可复用，进程不保）。
- **进程组原语**：spawn 一律 `start_new_session`，停止原语内置 killpg 杀整树（SIGTERM → 等待 → SIGKILL → 单进程兜底），未来 serve 换 shell 包装形态不再出现「只杀 shell 不杀孙进程」。
- **子进程 ppid 轮询自灭**：绑定守护进程生命周期，不用 PDEATHSIG——per-dispatch 线程 spawn 场景下父线程退出会误杀存活服务。
- **收割单点收口**：run 作用域 try/finally 对本 run 使用且未显式 hand-off 的实例统一收割（幂等），叠加 dispatch worker 级兜底；逐终态分支补调用被禁止。主循环周期清扫兜底 + 登记制（运行时状态文件）使泄漏可见窗口 ≤ 一个周期。
- **孤儿豁免判定必须过滤 agent 自身进程**：否则同 worktree 双孤儿互为「存活引用」互相豁免、永不清扫。
- **端口耗尽回退系统临时端口**并告警，**绝不静默回退主树常驻实例**——宁用随机端口也不让验证在未察觉下打到旧码。

## Consequences

- 任意终态（含异常）后无实例残留；daemon 被杀后孤儿自灭，残余由周期清扫兜底。
- 每轮新建实例的秒级启动成本是接受的代价；登记文件与真实进程可能漂移，故登记制只是增强而非唯一防线。
