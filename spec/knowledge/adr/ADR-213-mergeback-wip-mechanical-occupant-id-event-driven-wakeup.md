# ADR-213：合回 WIP 阻断的占用者机械识别与事件驱动唤醒

date: 2026-10-03
status: accepted

## Context

合回被主树 WIP overlap 挡住后只能被动轮询等待（实测一批 47 分钟才合回），且框架不知道占用者是谁——「在飞车道正常工作」与「陈旧无主 WIP」全靠人猜，后者同样静默等待。scheduling_kick 单槽位存在 conflict 写入假成功缺陷，不能作为唯一唤醒通道。

## Decision

- 占用者识别纯机械：overlap 文件集 × 在飞实现车道分支改动集（三点式 diff）求交，run 前缀过滤（impl-/code-fix-）+ code-fix 固定 spec 名桥接；禁 LLM 推导路径名。已知盲区（持有者直接改主树不入分支）一律按无主走宽限升级，误判影响有界（仅为告警），禁为覆盖盲区引入主树写探测。
- 唤醒以事件为主、轮询兜底：在飞持有者的 run 终态事件为重试主唤醒；per-run 终态监听注册挂 agent_runner 终态收口（现状无通用 per-run 订阅 API，event_bus 是 STATE.md 文件监视器非 pub-sub），注册先查已终态立即触发防死监听，attempt 形态归一 base run_id。禁依赖 scheduling_kick 单槽位作唯一唤醒。
- 事件重试复用既有单一重试入口（锁内 already_running 守卫后），禁回调线程旁路直调（不可重入锁重入即自锁死）；秒级让位于正确性。
- 无主宽限（可配置，缺省 30 分钟）耗尽升级专用 major 告警——触发点从「挡住即发」后移到「确认无主 + 宽限耗尽」降噪（在飞持有者场景不打扰人工），禁自动 stash/丢弃/代提交主树改动（autostash 事故族红线）。

## Consequences

- 在飞持有者收尾后合回从 47 分钟级被动等待降到秒级；轮询保留为事件丢失防线，且轮询时重算识别（有主↔无主随之更新）。
- agent_runner 由此提供唯一的 per-run 终态订阅点，后续需要「run 收尾即动」的能力应注册此处，而非各自发明轮询。
- 识别结果与盲区注记随台账 owner_* 字段留痕，人工告警附证据可审计。
