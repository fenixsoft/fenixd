# ADR-294：验证证据入库治理走契约软约束——框架不设证据 git 闸门

date: 2026-10-30
status: accepted

## Context

agent 在契约外手工把大二进制验证证据（录屏 mp4 等）提交入库，单个项目 verify-evidence/ 已累计约 690MB（仓库 size-pack 641.42MiB）。框架自身从不执行 `git add` 证据——证据入库完全发生在 agent 的自主 git 操作中，框架没有任何环节可以在「证据将要入库」时拦截，硬闸门既无挂载点也无必要。而超阈值二进制的逐字节一致性论证可由 sha256 sidecar 与哈希旁证承载，本体入库无增量证明价值。

## Decision

- 验证证据入库治理采用「契约声明 + prompt 指引」软约束：阈值唯一来源是 verify 契约可选声明 `evidence_retention.max_binary_bytes`（缺省 10MB，非法值静默回退），落位指引渲染分级条款——文本/小文件入库，超阈值二进制以 sha256 sidecar + 复现命令 + 存放路径登记替代。框架不为证据入库新增执行闸门。
- 已跟踪证据的体积普查观测归 stray_wip 信号侧（告警升级通道），不进落位契约——治理走软约束、观测走信号，两者分工不混在同一机制。
- 存量已跟踪大证据不做框架自动迁移外置（涉及 git 历史改写），须人工评估。

## Consequences

- 证据分级对 agent 是可违背的软约束：契约外手工提交仍可能发生，框架只能事后经体积观测信号发现，不能事前拦截——接受这一残余风险，换取零新增打回循环与零 git 钩子侵入。
- 契约解析保持静默容错范式（仿 `_positive_int_or_default`），坏声明值不阻断契约加载；阈值缺省保守取 10MB，新项目缺省行为即受分级条款约束。
- 后续任何「拦截证据入库」类诉求不得在框架内造 git add 拦截环节，须在软约束条款或观测信号侧扩展。
