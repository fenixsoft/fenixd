# verdict-cache-reverify 能力增量（add-verify-lane-throughput）

> verdict 缓存消费契约：修复轮重验只跑「失败场景 + 受修复影响场景 + 前置依赖链」，通过场景采信缓存判定；缓存键四元组全等 + 失效条件固化 + 存疑 fail-closed。

## ADDED Requirements

### Requirement: 缓存键与失效条件（固化）

verdict 缓存条目的键 MUST 为四元组（场景 id, 场景内容指纹, 被测构建指纹, 验证配置指纹）的全等匹配，任一分量不同即视为失效。失效条件固化为三类：①场景定义变化（内容指纹不匹配）；②修复 diff 触碰场景出处关联文件（场景 description 末尾标注的出处 `文件:行号` 所在文件，与本轮修复 diff 触碰文件集求交非空）；③验证配置变化（配置指纹不匹配）。出处标注缺失或任一指纹不可计算的场景 MUST 视为不可缓存：不采信其缓存判定、照常执行（fail-closed）。

#### Scenario: 四元组全等才采信

- **WHEN** 修复轮重验某通过场景，其场景 id 与内容指纹匹配，但被测构建指纹已变（修复产生了新构建）
- **THEN** 该条缓存判定失效，场景照常执行（构建指纹变化本身不自动失效全部缓存——以出处关联文件交集为文件级判据，见下一条）

#### Scenario: 修复触碰出处文件使缓存失效

- **WHEN** 本轮修复 diff 修改了场景 S 出处标注指向的源文件，重验时检查 S 的缓存条目
- **THEN** S 的缓存判定失效，S 被列入本轮实际执行的场景集

#### Scenario: 出处缺失 fail-closed

- **WHEN** 某通过场景的 description 无出处标注（历史场景集或 planner 漏标）
- **THEN** 该场景不采信缓存、照常执行；系统不因出处缺失报错或中断验证轮

### Requirement: 重验场景集裁剪

修复轮（bug-found 后的重验、gate 重试重验）进入场景执行前，验证管线 MUST 计算实际执行场景集 = 本轮失败场景 ∪ 受修复影响场景（失效条件命中者）∪ 其 `depends_on` 前置依赖链（递归）；未入集且缓存有效的通过场景 MUST 采信缓存判定写入验证报告（报告须标注来源为缓存），MUST NOT 重复执行。首轮验证与场景集冻结复用轮不受本裁剪影响（全量执行）。裁剪后实际执行场景集为空（理论边界：全部通过且无失效）时按零执行、直接出报告处理，MUST NOT 视为异常。

#### Scenario: 修复轮只跑三个场景

- **WHEN** 某验证轮 20 个场景中 1 个失败，修复 diff 仅触碰该失败场景出处文件，该场景 depends_on 1 个前置场景
- **THEN** 本轮实际执行 = 失败场景 + 其前置场景（2 个），其余 18 个通过场景采信缓存写入报告（标注缓存来源）

#### Scenario: 修复轮计数与报告完整

- **WHEN** 裁剪重验执行完成，2 个实跑场景通过
- **THEN** 验证报告包含全部 20 个场景的判定（2 个实跑 + 18 个缓存），失败计数为 0，验证轮按通过收敛

### Requirement: 缓存消费零新增打回

缓存读取、指纹计算、裁剪判定的任何异常（缓存文件损坏、指纹字段缺失、依赖环）MUST fail-open 回落全量执行，记 WARNING 后继续，MUST NOT 判验证轮失败、MUST NOT 新增任何打回/重试门禁。缓存写入时机与格式沿用既有 verdict_cache 机制，本能力不改变写入侧。

#### Scenario: 缓存损坏回落全量

- **WHEN** 修复轮进入时 verdict_cache.json 损坏不可解析
- **THEN** 记一条 WARNING 后本轮全量执行全部场景，验证轮正常收敛，不产生失败终态
