# Design: remove-aged-spec-archive

## Context

`evo-spec-changes-archive-drain`（2026-11-02 归档）在 `core/dashboard/data/spec_archive.py` 建立了五规则结构：R1 阈值排水（>= threshold 触发，排水至低于阈值）、R2 时效归档（终态+verification-report.md+mtime >= 72h，archived_by=auto）、R3 孤儿接管（同判据，archived_by=auto-orphan）、R4 每日滞留盘点（纯信号）、R5 安全边界（非终态永不归档）。R2/R3 共用 `_archive_aged_specs` 实现，调用点单一（`run_auto_archive` 主流程 threshold > 0 分支）。

R2 的设计依据是「归档后触发知识蒸馏」——时效归档保证归档事件定期发生，蒸馏管线随之持续运转。`move-distill-trigger-to-push` 已把蒸馏触发迁至 `approve_push` 推送成功转移（蒸馏输入双态解析：changes/ 优先、archive/ 兜底），归档不再是蒸馏的前置。当前活跃区 20 目录 / 18 终态未归档，即 R2 持续排水的结果——阈值（50）形同虚设。

用户裁决（2026-11-04）：移除时效驱动归档，活跃区水位维持在阈值（默认 50）左右；R3 孤儿接管保留。

## Goals / Non-Goals

**Goals:**

- 终态 SPEC 归档收敛为纯阈值水位驱动：仅 R1（>= threshold 排水）触发终态归档
- R3 孤儿接管保留（孤儿卫生兜底，不计入水位）
- R4 盘点语义随 R2 移除联动调整（水位观测化），避免常态噪音
- threshold=0 语义自洽收敛，配置面（设置页控件/热更新）零改动

**Non-Goals:**

- 不改 R1 排水语义（触发条件/排序/target 计算全部维持现状）
- 不改归档执行链（archive_spec / commit_archive_move / 自动提交）
- 不改蒸馏管线（触发在 push，输入双态解析已覆盖终态 SPEC 长留 changes/ 的形态）
- 不迁移存量终态未归档 SPEC（当前 18 条 pushed 等水位自然达到阈值）
- 不更新知识页（`auto-spec-archive.md` 由归档蒸馏管线随本 SPEC 归档自动回填，真相源纪律）

## Decisions

### 决策 1：R2 整体移除，R3 保留（用户裁决）

R2（终态路径）与 R3（孤儿路径）共用 `_archive_aged_specs` 与同一时效判据，但服务对象不同：终态 SPEC 是水位管理的正常组成（应由阈值统一驱动）；孤儿目录是 STATE 无条目的异常脏目录，不计入水位、永不被 R1 覆盖，R3 是其唯一自动清理通道——移除 R3 会让孤儿永久滞留且 R4② 每 24h 反复列示升级（告警噪音）。备选「一并移除求极简」被否：噪音与滞留风险由人工兜底不划算。实现上：`_archive_aged_specs` 保留孤儿分支，移除终态分支；函数与返回键（`orphan_archived`）可沿用，`age_archived` 语义消失需同步 `run_auto_archive` 返回结构与消费方。

### 决策 2：R4①③ 合并为终态水位观测

R2 移除后「终态+报告+72h」从「R2 失灵的异常信号」变为预期常态（等阈值排水），原①按单目录列示会对同一批终态目录每 24h 发一条常态 INFO——违背既有告警降噪偏好（合成兜底/常态信号静默化）。原③（终态无报告目录单列）的存在理由是「R1 阈值未触发且 R2 不接管的无报告死角」，而 R1 排水本就不以 verification-report.md 为前置，该死角不存在——③并入①。合并后的①输出聚合水位（终态未归档计数 + 最老终态目录滞留天数），把「时效归档告警」改造为「水位可观测」，保留「防新形态滞留无声积压」的初衷。

### 决策 3：threshold=0 语义随通道集自然收敛

现语义「0 = 禁用 R1/R2/R3 全部自动归档动作」。R2 移除后收敛为「禁用 R1/R3」，R4 盘点与存量回填仍不受开关约束。设置页控件（非负整数输入、0=禁用文案）无需改动。

### 决策 4：存量终态 SPEC 不迁移

当前 18 条 pushed 直接等待水位自然增长至阈值后由 R1 排水。备选「部署时一次性批量归档」被否：违背「维持在阈值左右」的裁决本意（这正是用户想看到的水位形态），且迁移动作无增量价值。

## Risks / Trade-offs

- [终态积压期活跃目录数增长，spec 列表/扫描性能回归] → 水位有阈值封顶（>= 50 即排），增量上限约 30 目录；`resolve_spec_dir` 已有归档清单 memo（nlink+TTL 失效键），活跃目录计数不进该热路径的风险面有限；R4① 水位观测提供可见性。
- [蒸馏原料可及性] → 无风险：蒸馏触发在 push 时刻，彼时 SPEC 目录尚在 changes/（双态解析 changes/ 优先）；归档延后只影响「重启续跑/补蒸」场景的原料路径，兜底态（archive/）依旧成立。
- [终态 SPEC 长期滞留，Dashboard 活跃列表认知负担] → 活跃列表本就含状态列（pushed 可辨），且这是用户明确选择的水位形态；如观感不佳可调低项目级 `archive.auto_threshold`（配置热更新即时生效）。
- [R2 用例反转遗漏（测试只删不反）] → 测试任务显式要求把 3 天边界用例改写为「不归档」断言而非删除，保留判据构造逻辑作为回归锚。

## Migration Plan

单轮部署，无数据迁移：合并后下一轮 `auto_archive_check` 周期即按新规则运转（存量终态目录不再被时效归档）。回滚策略：revert 单提交即恢复 R2 分支与原 R4 语义，无持久化状态需要清洗（归档动作不可逆但本变更不触发任何新归档）。
