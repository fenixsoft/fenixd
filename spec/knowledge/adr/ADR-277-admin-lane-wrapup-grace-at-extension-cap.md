# ADR-277：非实现车道扩容封顶点一次性收尾宽限，判据取 run 流内任务观测

date: 2026-10-15
status: accepted

## Context

实证事故：管理员 run 深诊断 21 组实验、环境定版执行完毕后，在写最终处置记录的瞬间被轮数上限击杀——初步处置记录已写、最终记录与修复计划未落盘，告警悬置 pending、spec 冻结转人工。轮数/墙钟续期判据只看分支提交增量与尾窗工具流量，任务完成度仅观测注记；非 impl 车道无收尾预算保护；administrator 提示词只有「先写初步记录/终了写最终记录」软契约，无次序硬规则，收尾动作集中在最后一刻。

## Decision

轮数扩容封顶点（extension 用满、原无条件击杀处）与墙钟监督扩容次数封顶点，对非实现车道（独立车道集合 `WRAPUP_GRACE_AGENT_TYPES`，与 `IMPL_LANE_AGENT_TYPES` 不相交）且 run 内自建任务清单全部 completed 的 run，发放一次性收尾宽限（默认 20 轮，`agents.wrapup_grace` 可配）；轮数侧与墙钟侧共用同一配置开关键与「是否已发放」状态槽，墙钟侧按该 run 近期平均每轮墙钟折算秒数一次性抬升墙钟上限。任务未清零或清单为空（run 无 TaskCreate 记录）不发放，维持既有击杀路径；宽限耗尽仍无终态按既有击杀路径落终态。判据数据源为 run 产物 TaskCreate/TaskUpdate 观测（沿 ADR-275 数据源选型），spec tasks.md 的 remaining_tasks 不纳入任何车道的续期/宽限判据；本裁定的宽限门是 run 流内任务完成态观测新增的判定消费点，ADR-275「观测面只注记」的语义限定其停滞观测面自身、不因此改变。宽限发放/耗尽的观测信息只进 evidence 不进 reason，reason 文案不得改动既有豁免匹配子串（budget 豁免按 reason 子串匹配）。本裁定收窄 ADR-103 的封顶 kill 分支，非取代。配套 administrator 提示词硬契约：诊断闭环判定后先覆盖写最终处置记录再执行长恢复动作、自建任务全 completed 后禁开新实验、最终记录不得留作最后一个动作。

## Consequences

非 impl 车道 run 不再死于收尾半途，最终处置记录与告警收口有预算保障；最坏增幅有界（一次性 20 轮量级，误触发时最坏情形与现状相同）。实现车道预算 sizing 与早停语义不变（两车道集合不相交、不互相触发）。后续新增车道必须归入 impl / 收尾宽限两个车道集合之一，封顶点行为由所属集合决定；后续框架代收尾类机制受 reason 子串契约面约束（观测只进 evidence）。
