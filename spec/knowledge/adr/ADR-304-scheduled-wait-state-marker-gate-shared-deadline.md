# ADR-304：排程等待态共源截止+来源标记同原子写，恢复豁免以标记为门

date: 2026-10-30
status: accepted

## Context

验证链需要排程「等待到某时刻再执行」的动作（如场景修复预算耗尽后安排一次未来重验）。截止时刻已有共用退避字段 `_dispatch_backoff_until` 落 STATE，但该字段被 dispatch 锁冲突退避、instant-fail 退避、env 阻塞升级等多机制共用，排程本身无来源标记，恢复路径无法把「排程等待」与其他机制的退避等待区隔开；daemon 全扫恢复路径的孤儿判定只看 run 指针与在飞 run，看不到一切不落指针的等待态，曾把合法等待排程重验的 testing 态误判孤儿重置，排程窗口被吞。同族先例：ready 恢复的 `_ready_hold_blocks` 有意等待早退、`_cancelled_hold` 持久标记恢复豁免（ADR-086）。

## Decision

- 「等待到某时刻再执行」类机制遵守三位一体契约：
  - **截止单源**：复用共用退避字段 `_dispatch_backoff_until`，MUST NOT 另立第二截止字段——恢复判定、探测静默（`spec_is_undriven` 条件③）、派发退避门读的是同一字段，双源必然漂移（等待期被派发 / 完成后被陈旧窗口阻塞）。
  - **来源专用标记字段与截止字段同一原子写落盘**（如 `_reverify_pending`/`_reverify_reason`），MUST NOT 仅存在于 error 文本或进程内存。
  - **到期消费读 STATE 截止字段**：内存定时器只能作准点主通道，不得作唯一载体；周期扫描兜底消费保证重启后到点仍执行。
- 恢复路径对「有意等待态」的豁免**以来源专用标记字段为门**，MUST NOT 裸读多机制共用的截止/退避字段作门——裸读会把非本机制的等待态误纳入豁免，改变真孤儿态既有恢复行为。
- 恢复路径到期分支只清标记不派发，实际派发单源走既有周期扫描消费通道，靠队列去重与派发退避门兜底幂等；MUST NOT 在恢复路径自行派发（双触发源）。
- 标记与截止的清零点必须成对收口（执行落定 + 人工解冻 + 恢复拾起），经单点清零集同一原子写同步清标记与仍未来的截止残留——只清标记不清截止会把已收口 spec 留在探测静默/派发退避窗内。
- 后续新增「等待态」机制按同一模式扩展：专用标记 + 共源截止 + 周期扫描消费 + 成对清零；触碰恢复判定顺序的改动须逐位保持真孤儿态既有行为（以非排程退避等待态的回归用例钉住）。

## Consequences

- 恢复路径能区分「合法等待」与「真孤儿」：排程等待态跨重启存活、到点被执行；真孤儿态恢复行为零回归。
- 共用退避字段继续多机制共用（探测静默/派发门同源消费），新增机制除标记外零新字段面。
- 代价：任何触碰恢复路径的新等待态必须带标记字段并在全部清零点接线；清零遗漏会使等待态悬挂（恢复路径永远跳过重置），由单点清零集与回归用例约束缓解。
