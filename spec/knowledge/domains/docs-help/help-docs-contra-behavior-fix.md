# 帮助文档反偏差纪律

<!-- knowledge: capability=help-docs-contra-behavior-fix rev=1
     sources=spec/archive/2026-10-04-fix-help-docs-contra-behavior -->

docs/help 帮助文档的一致性纪律：每一处「描述框架行为」的断言必须与当前代码实现一致，防止文档停留在旧世界口径、读者按文档处置做出错误动作（按已废止的旧流程等待人工、按旧调度模型误判并发、按旧超时形态误判故障）。

## 规则

- 反偏差断言口径：docs/help 各章中每一处「描述框架行为」的断言 MUST 与当前代码实现一致。文档偏差按三档分类——P0「描述与现行为相反」（照做会做错动作）、P1「重要机制零记载」、P2「结构与校准」；反偏差修正只承载 P0（把说错的改对），不新增机制描述。被修正点的具体业务口径（verdict 流向、调度模型、autostash 处置、分段超时等）由各业务域能力页承载，不在本页重复。
- 修正单元与分工边界：改动单元是「句子/表格行的替换」，判定标准为「原表述与现行为矛盾」；只改说错的句子，不新增小节骨架。「原表述没错但没讲全/没讲」的内容一律不进反偏差修正，由机制覆盖类 SPEC 承载；两者涉及同一文件时，后行者以合并后最新文档为基线、只增不删已立新口径。
- 数值锚点复核：写进文档的每个缺省值、秒数、上限 MUST 以权威代码锚点（file:line）实读为准，禁止从 SPEC 文本转抄后不再核对；锚点实读值与记载不符时以代码为准。文档数值与代码常量/缺省值逐一相等，无凭记忆书写的漂移。
- 旧表述清零：修正偏差时旧表述关键词 MUST 无残留，含交叉引用处（如 FAQ 条目引用其它章的旧口径）；验证采用文本核对——grep 不到旧表述、且新口径关键值在场，以文件内容为准。
- 交叉引用保有效：改写优先改段内文字、不动标题（改标题会改锚点 id，致相对链接断裂）；改后各篇相对链接与锚点指向的标题必须仍然有效。
