# ADR-303：协作拓扑派生单源在后端，前端零推导、聚合零复写

date: 2026-10-30
status: accepted

## Context

SPEC 协作图数据有三个消费面：单 SPEC 大屏的管线视图与协作时序泳道视图、跨项目协作图谱聚合。角色归列（run_id 前缀 → 七阶段）、attempt 归并、重试边判定、KPI 口径等派生逻辑若在消费侧各自实现，视图间边集与归属会分裂；实测也证明派生数据层的 bug 是大头——spec-review run_id 恒插 6 位 uuid 段致需求评审节点全 SPEC 丢失、daemon 日志单个 6.6MB 巨型行令状态转移派生恒 0，这些都是「先数据后视图」分层下数据层未治时视图层无从修复的实证。

## Decision

- **派生引擎唯一落点在后端**：`core/dashboard/data/topology.py` 的 `derive_topology` 是协作拓扑图数据的唯一派生引擎，以既有 timeline/runs 数据源为唯一输入；前端零拓扑推导，管线视图、泳道视图、跨项目聚合全部消费同一派生结果。
- **角色归列以 run_id 前缀表为权威**：`core/agent_runner/run_files.py` 的 `RUN_ID_AGENT_PREFIXES` 是角色归列唯一前缀真源；跨语言不强行单源（前端常量仅服务渲染），但派生侧禁复制第二套前缀映射。
- **聚合复用而非复写**：跨项目聚合逐 SPEC 调用 `derive_topology` 在其结果上聚合，禁为聚合另立一套归并/归列实现；派生层的归属修复（如 spec-review uuid 段剥除）随单源修自动治愈全部消费面。
- **边语义修正在派生层**：handoff/retry/dispatch 边的语义规则（如并行无伪串行边、重试边仅连 attempt 链）在派生层实现——前端过滤会造成视图间边集分裂；视图特有需求以派生字段扩展（如 `dispatch_anchor`）承载，不改写既有端点字段语义。

## Consequences

- 派生层 bug 全视图同步受益、也同步放大——`derive_topology` 的回归测试是全部拓扑消费面的唯一闸口；其输出结构（nodes/edges/kpis 及扩展字段）成为冻结契约，演进需同步评估全部消费方。
- 新增拓扑类消费方（新视图、新聚合）零新增派生代码，代价是视图侧无法做「只属本视图」的数据语义裁剪——确需特有派生时，以新增可选字段进派生层，禁前端改写。
- 数据源缺陷（timeline 丢轮次、日志窗口破洞）会同时表现为全部视图的缺失，取证时先查派生层与数据源、再查视图层。
