# 提案：蒸馏重试台账欠账龄期升级与节流

## 背景

归档 SPEC 的知识蒸馏失败会登记重试台账（knowledge-distill-pending.json 与 todo 勾选项），并由 knowledge_distill_retry_stale 信号提醒欠账。2026-10-30 dsh-plugins 项目归档 spec 2026-10-30-add-dsh-dashboard-bridge 的知识页产出因三轮链接校验违规被放弃（fenixd.log 三轮 run 均报链接越出知识真相源目录，模型拒识假说已排除），台账条目登记后 13 天无人处置，期间该信号发射 26 次全部零消费。其中 17 次落在 daemon 重启后约 5 分钟：发射幂等靠进程内当日标记，重启即清零重发。信号自带的排查指引还指向已排除的模型拒识假说，误导人工处置。

## 目标

1. 龄期展示：信号正文携带台账条目登记时刻、当前龄期与对应归档 spec 名，人工一眼看到欠账挂了多久。
2. 超期升级：欠账超 72 小时未处置时信号升级（按 admin_store 既有升级通道 major/ESCALATION 择一），使欠账进入更高优先级视野；major 信号自然进入每日自省数据摘要信号段，无需额外注入代码。
3. 持久化节流：把进程内当日幂等标记替换为跨重启的持久节流（复用 AdminStore 既有 latest_signal 判窗 / append_if_absent 原语），同条目未处置且窗口未过时不重复发射。

## 非目标

- 不自动处置台账条目（处置仍是人工动作）。
- 不修改知识页链接校验规则：三轮违规是模型产出未收敛，重试预算机制本身有效（同日姊妹 spec 第 3 轮即改合规）。
- 不改动蒸馏批次调度与观测聚合（fix-distill-observation-gaps 在途件管辖）。
