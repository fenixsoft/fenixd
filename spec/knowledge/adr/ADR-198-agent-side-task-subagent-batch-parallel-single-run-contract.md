# ADR-198：车道批内并行放 agent 侧 Task 子代理，框架维持单 run 契约

date: 2026-09-29
status: accepted

## Context

code-fix 批内为单 agent 串行处置，agent 段是批全程耗时的主要构成，提速需要批内并行。框架侧并行（派 N 个 agent 进程）需要 N 条 run 流、N 份 provider 注入、事件落盘与汇总机制，改造面大且与单 run / 单 out_path / 单次回归合回的既有契约冲突。审查车道（code-review）已实测验证 orchestrator 经 Task 工具在一条消息内多调用派子代理即为真并发，模式成熟。

## Decision

车道批内并行一律放 agent 侧：主 agent 以 orchestrator 身份用 Task 子代理并发处置（CLI 原生承载并发），框架视角仍是一个 run——单 run 流、单 out_path、一次回归一次合回的契约零改动。产物落盘、验证与提交责任集中在 orchestrator（单写者），子代理不得写产物文件、不得验证、不得提交。并发上限保守（防网关限流放大），具体数值由框架按批规模注入提示词，不设配置键。

## Consequences

框架侧零改动即获得批内并行；提示词每次派发现读、合回即生效，无重启成本。条级进度依赖结果行随组增量落盘保持实时。代价：编排轮次上升（≈组数/波次）；并发放大网关限流压力（靠保守上限与失败兜底缓解）；并行语义约束写在提示词内、依赖 agent 遵守（违约由兜底重做与产物硬门接住）。后续车道需要批内并行时默认沿用此模式，而非框架侧多 run 并行。
