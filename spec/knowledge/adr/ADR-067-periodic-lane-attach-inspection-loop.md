# ADR-067：周期自主车道挂既有巡检循环，调度元数据走 sidecar 不进 STATE.md

date: 2026-09-10
status: accepted

## Context

每日自动复盘类周期任务若引入独立定时器/守护进程，会放大运维面并自带补跑/防重复问题；调度元数据若写进 STATE.md 则破坏其 spec 状态表语义。周期车道需要一个可复用的调度与落账形态。

## Decision

- **调度判定挂既有巡检循环**：每轮巡检查「enabled && 到时 && 上次运行日期早于今天」，不新增定时器/线程——补跑（启动后首轮巡检即补）与防重复（状态文件比对）天然获得。触发语义锁定为「到时后首个巡检周期」，精度 = 巡检间隔。
- **调度状态走 `.fenix/` 轻量 JSON sidecar**，不进 STATE.md（STATE 只承载 spec 状态）。
- **独立 run 类型**：周期任务走独立 run_id 前缀，不占 spec 维度预算与实现预算；prompt 数据由框架聚合固定数据源，模板走提示词文件化体系。
- **失败静默降级为告警**（含失败原因），当日不重试（防风暴），次日自然重试。
- **产物写入即 commit + push**：保证后续从 main 分出的 worktree agent 可见（未提交文件对它们不存在）；只产出条目、不自动创建 SPEC，判定权保留在用户。

## Consequences

- 新增周期类能力一律复用该形态，不再各自引入调度机制。
- 每日一条小 diff 提交的噪音接受；回顾质量依赖框架聚合数据源的完整性。
