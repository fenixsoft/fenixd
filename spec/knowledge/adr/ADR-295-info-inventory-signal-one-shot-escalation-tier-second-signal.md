# ADR-295：info 盘点信号维持一次性留痕不收录，自动化经第二档升级信号接入

date: 2026-10-30
status: accepted

## Context

周期盘点类 info 告警（如主树 untracked 散件滞留盘点）既有裁定是「只告警不处置」——被显式排除在自动唤起通道外。当某类 info 信号长期留痕零处置、危害持续恶化（untracked 散件 30 条留痕 0 处置 0 升级、规模 44→119 entry）时出现两难：直接收录 info 信号会推翻降噪设计并放大误报面，不接入则自动处置永无出口、只能靠人工翻告警台账。

## Decision

info 级盘点信号维持一次性留痕语义，不收录进自动唤起注册表（SIGNAL_SEVERITY / SIGNAL_RECOMMENDATION / STORED_SIGNAL_TYPES 与 spec-less 伴生表对其保持关闭），原裁定的适用边界就此固定：info 信号不收录、升级信号除外。某类盘点信号需要自动处置出口时，新增独立的第二档升级信号类型接入唤起链路：更高 severity、可配触发阈值、多路或语义触发、同指纹只升级一次，四处登记同步（漏登即唤起静默落空，须测试钉住）。升级信号的执行器以 signal_type 绑定白名单收口，白名单仅认本升级类型，非白名单信号在任何 git 读/写之前 fail-closed 拒绝——原 info 信号不因证据格式兼容而放行为执行目标。

## Consequences

降噪基线与自动处置出口并存：低危形态维持留痕，超限形态获得自动出口；误报面由「info 一次性 + 升级同指纹一次性 + 注册表双档标记」三重兜底限制。代价是每类需要自动化的盘点信号都要新付一个信号类型的登记成本（登记点分散、信号类型数随自动化面增长），且执行器白名单使处置能力严格按信号类型切分、不可跨桶复用。直接收录 info 信号、或放宽其一次性语义/执行器白名单的方向须显式 supersede。
