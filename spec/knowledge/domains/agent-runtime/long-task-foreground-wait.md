# 长任务前台等待策略

可能超过工具单次调用时限的长任务的等待编排契约：一次后台启动、有界等待，两类后台能力严格区分。

## 现行规则

- 适用范围：可能超过工具单次调用时限（600s）的长任务——全量回归、大范围构建、超时探针等——其所在车道 prompt 注入「长任务前台有界等待」契约。
- 一次后台启动：用一次后台调用（`run_in_background: true`）启动该任务；不用 `sleep` / 周期性 `ps` 轮询模拟等待。
- 等待或并行独立工作：启动后等待完成通知，或在等待期间做与该任务无数据依赖的独立工作；不允许启动后直接收工（「启动即忘」）。
- 有界入口优先：任务存在能在 600s 内返回的有界入口（如 `bin/run_full_suite.py --timeout <t>`）时，优先直接前台跑该入口，不进入后台等待。
- 两类后台能力区分（不得混为一谈）：
  - 后台 Bash 任务的完成通知真实可用（转录中存在成对的 `Background command "…"` 完成通知为实证）；
  - `ScheduleWakeup` 定时唤醒在非交互派发（`claude -p`）下不产生唤醒。
- 能力描述保真：提示词不得声明与实测证据矛盾的能力描述（如把「后台等待」整体判为违规），除非有实测证据支持。
