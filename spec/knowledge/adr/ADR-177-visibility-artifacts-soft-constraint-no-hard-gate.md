# ADR-177：为可视化新增的落盘是软约束——守卫禁为展示数据设硬门，权威判定已有的项读侧合成

date: 2026-09-28
status: accepted

## Context

门禁可视化需要把收尾检查的渐进进展落到产物文件供读侧渲染。若为这份展示数据设硬门，实现者漏写/写坏一个键即被打回重烧——正是「键名契约缺口」类摩擦模式（键名同义改写一次、整轮重派）。而另一部分门禁项的权威判定本已存在于既有数据源（run 终态、STATE 状态、异步车道产物），再落一份盘只会引入第二个真相与写者竞态。

## Decision

- 展示性产物落盘是软约束：守卫对它只做「存在则查格式」的宽松校验，违规仅 WARNING 留观测痕迹，缺失零拦截；渐进更新（每完成一项重写小文件）优于收工一次性写（无法承载「进行中」诉求）。键名在 SPEC 中逐字固化，前端对未知条目容错渲染（不崩、显示原始 id）。
- 权威判定已存在的项由读侧从既有数据源推导合成，禁框架新增写者、禁第二份落盘——避免写者竞态；run 内落盘项与读侧合成项两组数据源不交叉覆盖。
- 读侧对历史 spec / 缺数据一律 fail-open（显示 unknown、不进入新展示形态），零新增打回循环；数据完全不可见时不触发新状态呈现，避免存量列表闪烁新颜色。
- 汇总判定（阶段呈现枚举）纯机械、单点函数化，边界条件场景全覆盖；数据解析与合成落独立数据层模块，聚合层只消费。

## Consequences

- 接受「偶尔缺数据」换「零新增打回」；异步车道类门禁（如代码审查）的进行中呈现直接读车道产物与在飞状态，不经实现者代写。
