# ADR-114：保全链回落 git 事实，worktree 删除前置快照

date: 2026-09-18
status: accepted

## Context

排水强杀首轮在飞 run 时保全链全盲：STATE 的 branch 只在完成态写入（首轮在飞恒空）→ 保全条目三字段全空、保护集为空 → orphan 清理无差别执行，上百分钟工作全丢；且 dirty 快照的唯一调用点挂在删除失败的兜底分支里，而该处删除带 --force 通常成功——快照在最需要它的路径上根本不触发。

## Decision

- spec → branch / worktree 取值以 git 事实回落（worktree list --porcelain 全集 + 目录命名约定全名边界匹配 + 三态可用性校验），不信任内存表：内存表进程重启即失、按路径为键，boot 恢复路径读不到任何东西；匹配歧义（spec 名互为前缀）按不可用处理并告警，不静默取第一个。
- STATE 的 branch 保持「已完成产出分支」语义只在终态写，不在在飞时补写——写中间态会污染 merge-back 等消费方的完成态假设；回落只改读取方容错，不改写入语义。
- dirty 快照从「失败兜底」改为「删除前置动作」：覆盖全部删除路径（orphan 清理与常规清理、含强制删除），任何 worktree 物理删除前必留可取证引用；快照失败降级 WARNING 不阻塞删除。
- 保护集回落取保守方向：宁可多保不删——多保的下轮清理仍可回收，删错不可逆。
- 非计划快速停机路径不进入保全改动：改动仅在保全 / 清理路径生效，快速停机语义逐字节不变。

## Consequences

- 首轮在飞 run 遭排水强杀时分支与工作区可被正确保全、删除前必有留档；零提交分支仍走清空（无提交即无工作可丢，脏区由快照兜底取证而非自动恢复）。
- 删除路径增加一次快照调用（毫秒级，相对停机窗口可忽略）；保护集可能短暂多保已产出 worktree，由既有周期清扫兜底。
