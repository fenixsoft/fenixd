## Why

项目视图（`#project/<name>`）的 SPEC 列表同时混排需求（普通 SPEC）与问题（`fix-*`）。项目推进过程中 `fix-*` 数量不断增长，用户无法快速区分「这个项目还有哪些待办需求」与「还有哪些待修复的问题」，需要按类型筛选。

## What Changes

- 在项目视图 SPEC 列表过滤栏新增一个类型下拉框，三个选项：**全部 / 仅需求 / 仅问题**
  - **全部**（默认）：与当前显示方式一致，不改变现有结果
  - **仅需求**：隐藏名称以 `fix-` 开头的 SPEC（含无父级的问题行与其子树）
  - **仅问题**：只显示名称以 `fix-` 开头的 SPEC
- 类型过滤与既有名称关键字、状态下拉过滤叠加生效（AND 组合），不引入新的服务端请求，纯前端实现
- 类型过滤状态与既有过滤一致，在 2 秒自动刷新重渲染间保持
- 「仅问题」视图下，`fix-*` 之间的树形层级关系保持不变（如 `fix-fix-*` 仍挂在 `fix-*` 下）；因基名 SPEC 被过滤而不在列表中的 `fix-*` 归入「无父级」分组展示

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `dashboard-spec-table`: 在既有「前端名称与状态过滤」之上扩展类型过滤（全部/仅需求/仅问题），新增类型过滤的需求、组合过滤与刷新保持场景。

## Impact

- 前端：`core/dashboard/static/app.js`（`specFilter` 状态、`renderProject` 过滤逻辑、过滤栏 HTML、事件绑定）
- 无后端 API 变更、无数据模型变更
- 复用既有「无匹配的 SPEC」空态与过滤栏样式
