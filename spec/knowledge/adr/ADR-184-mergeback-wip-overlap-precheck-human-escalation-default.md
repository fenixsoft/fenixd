# ADR-184：merge-back WIP 重叠预检缺省升级人工拦截——禁静默收纳

date: 2026-09-28
status: accepted

## Context

done→pushed 中位 14 秒但均值 41 分钟：138 次冲突告警来自「尝试 merge→冲突→autostash→回滚→重试」循环。既有 WIP 重叠闸门能算出「主树脏文件集 ∩ 分支触碰文件集」，但缺省处置是 auto（stash 静默收纳后继续 merge）或 block（粗粒度中止），无人工升级出口——重叠被静默吞掉或整链卡死，二选一都不理想。

## Decision

- 交集非空 → 不发起 merge，经人工升级通道（choices）发告警，附交集文件清单与两侧来源；spec 保持可重试状态（人工清理 WIP 后重试或显式豁免）。把缺省处置从 auto 静默收纳改为人工拦截是有意的策略变更：重叠 ≠ 冲突，可自动合并的重叠也会被拦（已知代价），但静默收纳把「主树有未入库工作」藏进合并结果，冲突告警循环的无效轮次成本更高。
- 复用既有重叠判定原语，禁重复实现；旧配置键读侧兼容（block 语义并入升级出口，auto 不再作为缺省处置），实现必须显式覆盖既有缺省并记录推翻依据。
- 逃生门：显式配置跳过预检（紧急推送用），缺省恒拦截。
- 闸门优先序不变：语义冲突预演仍在最前，WIP 重叠预检居次，spec 目录在飞顺延其后（ADR-160）。

## Consequences

- 误拦由交集判据保守性 + 告警附清单人工秒判 + 逃生门三重兜底；主树 WIP 的可见性从「被 stash 吞掉」变为「升级待人工」，与「主树是人工工作区」的定位一致。
