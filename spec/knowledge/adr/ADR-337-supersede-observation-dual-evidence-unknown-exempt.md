# ADR-337：supersede 触发须实测观测点，unknown 根因不参与自动失效

date: 2026-11-08
status: accepted

## Context

修复生效后同根因旧告警永久滞留，「已修复」与「待处理」在面板上不可分辨（单项目 28 条滞留）。反之，若以「配置加载成功」单条件触发批量失效，配置看似修好而实际仍坏时会把在账告警批量误清，故障失去可见性——批量失效的触发判据必须比「修复动作已完成」更硬。

## Decision

告警携带封闭枚举根因标签（cause），同根因修复生效触发该根因未处理告警单事务原子批量 superseded（新增终态旁路，不动 resolved / auto-resolve / self-heal 语义）。每个根因定义一个可判定修复观测点，触发须实测证据双条件齐备——以 model-chain 为例：provider 引用校验干净加载 **且** 其后派发成功（run 成功终态实测），单条件不触发。cause=unknown（缺席/无法回填）硬拒参与自动失效；supersede 撤销仅限面板人工入口、仅对 superseded 态生效。

## Consequences

后续扩展根因枚举必须同时给出可判定观测点，否则该根因只能留人工处置（harness-cli 观测点未落地前即此形态）；批量失效可逆性由人工撤销面兜底，失效时间与触发观测点写进 resolve_note 保审计；误归因由双条件终判据互斥保护（CLI 不可达期派发全失败，model-chain 观测点同样无法通过，反之亦然）。
