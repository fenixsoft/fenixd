# ADR-223：请求型信号自动闭环走白名单制，入表门槛=只读谓词+事实等价

date: 2026-10-04
status: accepted

## Context

admin 信号摄取链路要免唤起 Administrator 地闭环「诉求已被事实满足」的请求型信号，但哪些信号允许不经 LLM/人工判断直接闭环是安全边界问题：判错即静默吞掉真实诉求。可选口径有三：全量语义判断（每信号多一次 LLM 调用，白耗）、全部信号一律机械探测（不可判定类型必然误闭环）、按类型白名单逐个开闭。

## Decision

- 请求型信号「探测通过即免唤起闭环」走白名单制：只有「探测谓词与诉求满足是同一事实」的存在性可判定类型可入表（段/文件/配置键已存在即诉求满足），谓词与诉求语义等价是入表的根本判据，不是可选的加分项。
- 入表门槛双条件：新增类型必须同时给出只读探测谓词（只读存在性检查——不写项目文件、不触发构建、不联网）与「探测通过即无剩余动作」的论证；需语义判断的类型（manual-intervention、inconclusive_loop 等）永不收录。
- 探测通道 fail-open：探测器自身缺陷不得吞信号，谓词抛错、存储不可读时落回既有唤起路径并留警告日志——探测只是免唤起的优化，永远不得成为信号的前置门。
- 处置终态对原信号的 handled 回写属记账动作，失败降级为警告日志、不得阻塞处置结果落盘；升级人工（escalate=true）的处置永不自动回写，人工处置是唯一出路。

## Consequences

- 换取：白名单内信号零 LLM 成本即时闭环，Administrator 免于被诉求已满足的陈旧信号白唤起；语义等价论证由每个入表 SPEC 举证，误收录风险被「只读+事实等价」双条件压制。
- 代价：白名单外的可满足信号在诉求已满足时仍会白唤起一次处置 run——这是拒绝语义判断自动化 deliberate 付出的成本，扩白名单而非放宽判据是唯一正路。
- 探测异常路径与既有唤起路径完全一致，白名单机制对存量摄取行为的回归面为零。
