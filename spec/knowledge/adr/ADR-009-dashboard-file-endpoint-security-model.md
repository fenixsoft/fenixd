# ADR-009：Dashboard 文件读取端点统一安全模型

date: 2026-09-02
status: accepted

## Context

Dashboard 服务进程以项目根路径为参数读取项目内文件（SPEC 文档 proposal/design/tasks、验证失败截图等）。URL 参数直接拼接文件路径存在任意文件读取与路径穿越风险；同时文档缺失是常态分支而非异常，错误语义也须统一。

## Decision

- 所有读取项目文件的端点一律执行同一套校验：
  1. `project` 必须存在于注册表（仅允许已注册项目路径）；
  2. 文件类别参数用白名单枚举（如 `doc ∈ {proposal, design, tasks}`），非法值 400；
  3. 文件名参数按 kebab-case 正则校验；
  4. 拼接后的路径 `resolve()` 后必须仍位于目标根目录之内（前缀 / `is_relative_to` 校验），防御 `..` 拼接。
- 目标文件缺失返回 `found: false`（HTTP 200）而非 404：按钮/入口常显策略下缺失是正常态，由前端呈现空态；仅当 spec 名称不在该项目 STATE.md 中时才返回 404。
- 新增可读文件类别时扩展同一白名单与同一路径校验，不得为单类别绕过校验另开直读路径。

## Consequences

- 读取面的扩大（新增文档类别、截图等）不放大攻击面；各端点安全语义一致、可独立测试。
- 「缺失 ≠ 错误」的语义分工让前端空态与真实故障（项目/spec 不存在）可区分，不会以 4xx 噪声污染日志。
