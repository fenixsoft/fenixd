# ADR-384：项目测试基建版本控制走忽略规则收敛，框架清理器零豁免

date: 2026-11-27
status: accepted

## Context

merge-back 清理器 stash_guard 对「本次合回新增（--diff-filter=A）且被 gitignore 命中」的 tracked 文件一律剥出索引（设计假设：tracked 且被忽略 = 误提交的运行时草稿，`check-ignore --no-index` 批量判定，无内容性质豁免）。项目侧存在与之长期冲突的规约组合：测试规约强制所有测试文件进 `.test/`、`.gitignore` 整目录忽略 `.test/`、git 官方语义父目录排除后子文件不可反包含。同指纹自动剥离 5 次（2026-09-07..11-25），对象全部是 SPEC 验收 commissioned 的合法测试基建（11 个文件约 3300 行）、「剥真草稿」对照组 0 次；隐性代价是 fresh worktree 回归面自 9 月静默塌缩（磁盘 21 个回归脚本仅 4 个 tracked、回归按磁盘 glob 收集缺席即静默跳过），并迫使至少 3 份在途 SPEC 写绕行条款、一次 fresh worktree 回归打包失败追加定向修复 run。

## Decision

- **在项目侧收敛忽略规则**：整目录忽略 → 只忽略运行时产物与一次性调试/冒烟脚本两类窄规则，使测试基建合法 tracked，从源头解除「规约要求 tracked × gitignore 判忽略 × 清理器必剥离」三方冲突；框架侧 stash_guard 零改动。
- **框架不为单个项目的忽略规则错配提供豁免**：扩展名白名单会为单个项目错配波及所有项目；「剥离前核查引用」形态在框架层不可行（框架无法知道引用关系）。stash_guard 对真运行时产物（verify 截图等）的剥离是设计预期，保持不动。
- **存量散件逐个表态**：目录下每个存量文件归入「入库 / 留档区 attic / 忽略 / 删除」之一并有记录，不留成片未表态散件（不扩大主树散件清扫面）；过期脚本入 attic 留档（仍入库保留历史、退出回归面 glob），不删除。

## Consequences

- 后续 SPEC 可直接把测试路径写入交付物声明，「gitignore 拒 new / worktree 缺件打回 reference」的交付物守卫双难解除；新增测试基建必须 tracked，回归面不再静默塌缩。
- 项目忽略规则纪律：与测试目录相关的规则逐条可归因（运行时产物或一次性脚本两类），测试脚本/共享模块/测试配置不得被任何忽略规则命中。
- 同型冲突若在其他项目复发，处置路径是收敛该项目的忽略规则，不是改 stash_guard；`.fenix/` 下 tracked-但被忽略 的框架基建文件同类冲突不在本裁定范围，另议。
