# 提示词编写设计规则

<!-- knowledge: capability=agent-prompt-authoring rev=1
     sources=spec/knowledge/_inbox/done/memory-distill-agent-prompt-rules.md -->

面向 agent 提示词作者的设计级纪律：约束用语义还是数字表达、哪些行为必须下沉框架机械化、多轮派发失败时的止损判据，以及门禁型 agent 的配套设计义务。提示词文件分层与注入机制见 agent-prompt-files 页。

## 规则

- 「简洁」用语义约束表达，不用数字上限：提示词里任何「≤N 字」「不超过 N 条」都会被模型当硬截断指令字面执行（标题字段被截成描述前 40 字的实证）——数字上限不是长度控制的可靠手段。
- 硬行为约束不依赖模型自律：「分批落盘」类过程约束对快模型无效（deepseek-v4-flash 档仍一次性写全量的实证）——确需强制的过程行为必须机械化（PreToolUse hook 等框架侧拦截），提示词只承载语义意图。
- 提示词路线同一问题 3 次以上失败即判架构问题，停止在提示词层继续迭代：护栏（防死循环、防失控重试）必须框架侧落地（心跳、时长判据、机械拦截）。提示词的「降级继续」条款约束不住模型的归因倾向——辅助工具死亡时模型会归因为瞬态失败而无限重试，提示词降不住这种不死心。
- 门禁型 agent（run 产出结果文件 → 独立消费函数）设计时必须同时定义消费触发者：谁在何时调用消费函数。缺失消费触发者的门禁产物是死知识——评审全部 repaired 也照样来回重派。配套的防重派锚点必须落在启动 run 之前落盘，不依赖 run 内部写入。
