# ADR-160：merge-back 闸门按固定优先级排序，无退出码形态必须结构化判据

date: 2026-09-25
status: accepted

## Context

merge-back 前有多道主树零污染早退闸门（预演语义冲突、WIP 重叠、spec 目录在飞编辑）。`merge-tree --write-tree` 预演只从提交计算合并树、完全无视工作区脏状态（干净仓实测复现），主树脏形态一路放行到真合并才失败；失败分类若按错误文本匹配，会把不产生 git 退出码文本的预演冲突/闸门阻塞误判，也会把错误文本含关键词的真失败误判为可重试而无限重试。

## Decision

- merge-back 闸门固定优先级：语义冲突(rehearsed) → WIP 重叠阻塞 → spec 目录在飞编辑顺延 → 放行合并；顺序固化，禁把顺延置于预演闸之前（会把需 repair 的语义冲突误报为等待提交）。
- 可重试分类 MUST 置于既有早退分支之后、指纹熔断记账之前；可重试=主树脏/spec 目录在飞/锁冲突，逐类显式声明匹配面。
- 无 git 退出码的形态（merge 前早退、锁获取失败）MUST 用结构化字段判据，禁文本匹配；可携带退出码文本的匹配 MUST 锚定 git 原文片段、禁宽泛正则，判不准 fail-open 到既有通道。
- 顺延信号走既有返回载体新增布尔字段（禁另造返回类型破坏 `success, err` 解包契约），MUST NOT 计入合并失败指纹；非派发调用方（恢复 re-merge、repair、fast-track）对顺延保留现场标记原样再试（视为尚未尝试合并），禁消费「仅剩合并」标记退回全新派发。
- spec 名解析失败（非本 spec 分支形态）显式豁免放行，禁把 None 塞进路径查询（会命中整个目录、误判他 spec 受阻）；检测只读，禁为解除顺延就地 add/commit/checkout 主树。
- 可重试不计实现预算仅当未启动新 run；记账口径复用既有幂等回退原语，禁第三套旁路、禁以不写 STATE 代替（与预算对账告警冲突）。

## Consequences

语义冲突不被顺延掩盖、闸门顺序可逐行对照；失败分类假阴性方向收敛；预算记账单一来源、对账不冲销。
