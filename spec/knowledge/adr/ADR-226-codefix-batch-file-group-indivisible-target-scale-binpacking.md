# ADR-226：code-fix 选批文件组不可拆、目标规模浮动装箱

date: 2026-10-04
status: accepted

## Context

code-fix 车道选批原按台账 `first_seen_at` 时间序截取前 `batch_size` 条，同文件的多个问题被拆散到不同批次，每批 agent 对同一文件重复取证、重复理解上下文；批级固定开销（建 worktree、一次 agent run、一次批收尾回归、一次合回核销）随批数线性放大，回归是其中大头。批内子代理并发上限若不随批规模自适应，批变大后会成为新瓶颈。

## Decision

选批以**文件组**（同文件全部 open 条目归并）为最小不可拆单元做确定性贪心装箱：`batch_size` 语义定为「目标规模 T」而非精确条数，硬上限 H = 2T 防单批失控；同目录组浮动吸收（允许超 T 至 H）、异目录组仅批 < T 时吸收且吸收后 ≥T 即封批、单文件组 >H 独立成批不拆分。「同目录」取直接父目录全等，刻意不引入模块/语义相似度判据（那需要 import 图分析，复杂度失控且误聚类代价由批间串行回归放大）。编排调用点只消费装箱首批，链逐批推进、每轮重选，链推进协议不变。配套波次上限按批内文件组数分档（4/6/8，8 硬上限）经 prompt 占位符注入。

## Consequences

- 同文件问题永同批、同目录尽量同批，批数下降直接摊薄批级固定开销；核销与进度粒度维持组级/条级不变。
- 装箱必须保持确定性（同输入同输出），后续任何触碰选批的 SPEC 不得破坏该口径，也不得拆散文件组。
- 目录亲和判据保守：跨目录相关文件的聚类收益放弃，换取零 import 图依赖与可复现选批。
- 超大单文件组整批不拆，批条数可超 T（至组自身规模），依赖批内并行（波次上限分档）消化，不退回拆批重复取证。
