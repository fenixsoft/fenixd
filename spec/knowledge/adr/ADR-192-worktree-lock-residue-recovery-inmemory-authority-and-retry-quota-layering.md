# ADR-192：worktree 锁残留恢复——内存锁权威源不变、诊断记录禁反超、重试配额语义归属派发层

date: 2026-09-14
status: accepted

## Context

worktree 规格锁是进程内存集合，daemon 重启即清空，但同一 daemon 生命周期内孤儿持锁无恢复路径：日志实锤锁冲突链（`Worktree already active` → create 失败 → 派发守卫放弃 → 验证降级）中，锁冲突还被误归为死亡 run（退预算 + 计 retry），而同类基础设施故障已有「不计 retry、不翻状态」先例。恢复设计引入落盘 sidecar 记录锁归属以供诊断，但 sidecar 若被加载为拒绝依据，daemon 重启后的残留条目会把今日「锁空 → create 成功」翻成「create 被拒」——辅助记录反超权威源即制造新故障。

## Decision

- 权威源不变：冲突判定仍以内存锁集合为准；落盘 sidecar 只作诊断读取，禁在构造期加载为拒绝依据。sidecar 的写入/清除必须收敛到锁登记辅助方法（禁散点直改集合——任一路径漏清即留幽灵条目），且禁写入 run 流命名空间目录（混入非流文件污染流扫描 glob）。
- 残留判定复用既有信号，优先序固定：进程表为主判据；run 流转录新鲜度存在前缀盲区（多类 run 前缀不匹配流 glob 而其 worktree 仍用实现前缀），禁单凭转录缺失判残留；锁龄窗口内视为构建中保留；记录缺失 fail-closed 判活动（宁紧勿松，缺证据不得清理）。daemon pid 禁用作存活判据——create 运行在 daemon 进程内，pid 语义与被检进程拓扑错位，该分支在 daemon 存活期内永不成立。
- 职责分层：create 层只做「识别 + 一次性清理重试」，重试配额语义归属派发层——create 层禁排重试定时器、禁写 STATE 状态或退避字段，防与派发退避形成双重重试链；锁冲突必须提供可区分的结构化原因字段，归因对齐基础设施故障先例（不落死亡 run 豁免、不计 retry）。
- 残留清理沿既有删除安全约定：先快照留档、跳过保全集，由 `git worktree remove --force` + prune 完成，失败仅告警禁 rmtree 绕过 git 记账；降级原因走既有结构化诊断通道（同一事实禁双通道），异常驱动的降级路径同步补齐落盘。

## Consequences

- 孤儿持锁的窄窗口恢复提前到 create 冲突点，不替换既有启动期陈锁回收路径；sidecar 的诊断价值不以引入假拒绝为代价。
- 基础设施故障与 run 死亡的预算口径分离：锁冲突不再烧 retry、不再触发死亡豁免，派发退避仍是唯一重试记账方。
- 代价：残留判定依赖进程表信号为主，转录新鲜度只能作辅助证据——新增 run 类型前缀若不进流 glob，其「转录缺失」不可作为任何残留判据。
