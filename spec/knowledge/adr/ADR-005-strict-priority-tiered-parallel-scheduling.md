# ADR-005：调度为严格优先级分档并行

date: 2026-09-02
status: accepted

## Context

FIFO 队列 + 并发上限的调度下，低优先级任务可占满全部槽位，高优先级任务饥饿等待；SPEC 的 priority 形同虚设（只用于报告排序）。并行调度必须裁定：不同优先级之间是否允许混跑、正在运行的任务是否可被抢占。

## Decision

- 队列条目携带 priority（入队时从 STATE.md 读取，缺省 5）；派发按严格优先级分档：
  - 不变量：任何时刻所有正在运行的 agent 属于同一 priority 档；新档位只在前一档全部排空后启动。
  - 同档并行：同一档内多个任务按入队顺序（档内 FCFS）填充空闲槽位，上限 `agents.max_concurrent`。
  - 跨档不并行、不抢占：只要队列或运行中存在更高优先级档，低优先级任务绝不会被派发；正在运行的低优先级档不被中断，高优先级档在其排空后立即启动。
- implementer 成功后 verifier 的紧跟关系不靠物理队首表达，靠同档内 FCFS 保留相对顺序。
- 并行度复用既有 `agents.max_concurrent` 键，不新增配置项。

## Consequences

- 高优先级任务的等待上界为「当前档排空时间」，不会被后续低优先级任务挤压；priority 成为真实调度语义。
- 代价是并行度可能空置（高优先级仅 1 个任务时低优先级不补位）——这是严格语义的既定取舍，不做混跑折中。
- 全部 SPEC 同优先级时退化为档内 FCFS 并行至上限，与 FIFO+上限等价，旧行为是本语义的特例。
