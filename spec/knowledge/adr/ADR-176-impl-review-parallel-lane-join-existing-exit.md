# ADR-176：长耗时质量审查摘出实现 run 为框架并行车道——join 于既有出口，打回复用既有通道零新状态

date: 2026-09-28
status: accepted

## Context

收尾代码审查曾内联在实现者 run 内前台执行：单轮 20-40 分钟 vs 工具调用约 600s 硬上限 vs 全量回归实测 275s。实测失败链：前台 570s 截杀 → 后台重跑 → sleep 轮询烧轮次 → 网关 stall 挂死 42 分钟 → daemon 判死重派 → 中间产物作废。实现者墙钟被一个与编码无关的质量步骤绑架。

## Decision

- 收尾代码审查摘为框架侧并行车道：维护 run 形态（不占 spec 预算、不经 spec 执行路径），run_id 前缀登记保证时间线归属；启动时点 = merge-back 成功后的 tester 派发点（并行窗口最大化，且不为最终未合并的内容白跑审查），审查对象 = 实现分支 head（merge-back 不改分支 ref，testing 窗口内稳定）。
- join 于既有状态机出口：testing→verified 的门禁自动路径增加车道完成判据；发现须修复 findings 复用既有 testing→bug_found 打回通道，零新状态；修复轮计数持久化且上限 1，超限 findings 全部转台账放行（防死循环）。
- 采信/降级分界固定：产物 completed 但 (branch, merge_base, head) 指纹不新鲜 → fail-closed 不得采信不得放行（按当前指纹重跑）；车道超时/非零退出/环境不可用 → fail-open 放行 + 非空 reason + WARNING 留痕（质量审查缺位不阻塞交付，但必须可见）；产物缺失或车道未运行 → join 判据幂等触发车道（在飞单飞去重），禁无限停等。
- 双档 gate | advisory，缺省 gate；车道级硬超时与 LLM 单请求超时按键分离（一种粒度一个键，禁一键两义）；增量游标优先、缺失/非祖先回退全量。
- 实现者内联审查段与产物硬门同步摘除（校验函数保留供 join 复用）；修复轮产物仍写 worktree 内、随拷回单向落主树（写读同层，ADR-171/172 同族）。
- 审查门数据源必须是车道产物，非实现者落盘——摘除后实现者不再产该产物，读侧引用错源即引用一个永不存在的东西。

## Consequences

- 实现者墙钟与审查时长解耦；停等窗口占坑由单飞语义与完成事件驱动推进，无惰性到期风险；上游审查器行为漂移由指纹机制兜底、解析保持宽松。
