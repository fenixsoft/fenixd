# 设计：车道探针稳态降噪与告警生命周期对齐

## 关键决策

- D1 稳态记忆放探针体内：lane_preflight 维护上次判定结论与进入稳态时刻；结论不变时跳过逐拍 WARNING，改由 3600s 节流心跳携带持续时长发射；结论变化（含首次判定）立即 WARNING。判定返回值（ok/reason）与派发冻结闸消费路径零改动。
- D2 自检消费点复用：fenixd.py _lane_preflight_consume 不再无条件重打，改为仅在探针侧标记本拍为「边沿/心跳拍」时发射，天然消除双组件同拍双行。
- D3 告警重武装判据区分稳态与形态变化：人工 handled 后，若下一拍判定仍为同一稳态（不可判定且环境形态未变），不重开新告警（一次性终态登记）；若环境形态变化（路由变量出现/消失导致判定改变），按新边沿重新登记。这是对 lane_preflight.py 告警登记段「人工已处理条目不再抑制新告警落地」设计的稳态例外，保留其瞬态场景语义。
- D4 提醒豁免实现于 core/self_review.py _unhandled_escalation_aging 过滤层：按告警负载中明示的自动关闭语义声明字段判定豁免/降级，而非逐 signal_type 硬编码，避免豁免面扩散。

## 风险与对策

- 风险：稳态心跳间隔过长掩盖恢复——对策：恢复（healthy 边沿）始终即时播报，保留并升格既有 _lane_preflight_ever_unhealthy 恢复播报语义。
- 风险：豁免面过宽吞掉真需人工的告警——对策：豁免判据绑定负载的自动关闭声明字段，非自动关闭型不受影响；单测覆盖豁免仅命中目标类型。
- 兼容：不改在途 evo-provider-fallback-dispatch-gate 的「不可判定→拦截+告警」意图，本 SPEC 只接管该形态的观测面。
