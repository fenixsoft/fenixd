# ADR-016：调度自愈纪律（状态机纯记录 / 幂等重发 / 孤儿白名单）

date: 2026-09-02
status: accepted

## Context

调度管线存在互相放大的失效路径：事件层只看状态差，同状态的行动性重置对调度不可见；周期重发对已推进的子 SPEC 无条件打回；孤儿恢复用「曾经失败过」当跳过理由，把真孤儿排除在外；单条数据异常可让整轮扫描静默中止。自愈逻辑的方向性须固化为纪律。

## Decision

- 状态机保持纯记录：不在状态机内为 diff 语义引入事件副作用；同状态的行动性更新（如重置为 ready、清空跟踪字段）由调用方（pm_engine）在写回后直调派发路径补发，保证「动作性变更必达调度」。
- 周期性信号重发必须幂等且带字段保护：子 SPEC 处于推进态/完成终态时只记日志不动状态；仅确认无活跃工作且从未成功派发时才允许重置，且重置不得清空 `implementer_run` 等历史跟踪字段（其唯一用途是去重与诊断，清空制造的问题大于收益）。
- 孤儿恢复的存活判定为白名单：仅当「存在存活的 agent 子进程」或「存在未超时的活跃 worktree 锁」才跳过重派发；带 error 或有历史 run 记录不构成跳过理由。重派发前清 error 但保留 run 历史字段。
- 容错在源头与单条两层：STATE.md 解析层过滤/规范化非法条目（防御并发半写被读成坏数据）并记 warning；恢复循环逐条独立捕获异常，单条失败不中止整轮扫描，扫描末尾输出 handled/failed 统计。

## Consequences

- 「失明」「误打回」「漏恢复」「整轮中止」四类失效路径分别被机制封闭；恢复分支不再依赖「没有错误痕迹」这类不可靠的负面证据。
- 白名单判定依赖存活探测的准确性（进程/锁检测），探测不可用时须以保守兜底（如 run 文件新鲜度）近似，宁可重派发去重也不误判存活。
- 状态机纯记录要求所有「需要触发动作」的写侧自行补发，新增写路径时遗漏补发会重现失明问题。
