# ADR-363：code-fix 合并门放行判据=机械形态核查，不做语义可修性判断

date: 2026-11-16
status: accepted

## Context

code-fix 合并门零有效修复守卫以 fixed=0 一票拒合回，把「纯 fenix-ignore 误报标记」提交一并丢弃。源内标记是防同一误报下轮复发重烧修复轮（每轮约 $1.5-2）的唯一跨轮抑制手段：条目指向的源文件被架构转向删除后指纹去重对新报失效，审查侧「就近有标记 MUST NOT 再上报」的注入约定全靠标记进 main 兑现，而纯标记批在守卫任何分支上都无合回通道，弃件且零持久留痕（commit id 未落任何持久面即永久不可考，已有弃件实证）。若为放行引入内容级「是否值得修 / 是否真误报」判断，需要语义理解且结论不可机械复现，门禁将退化为不可守卫的自由裁量。

## Decision

合并门放行判据只做机械形态核查：批内全部提交的新增行均为含 `[fenix-ignore:<item_id>]` 标记本体的注释行、删除行仅为标记注释行或空行、批内至少出现过标记本体；注释语法按已知注释形态并集识别、不按文件扩展名绑定；混合批（含任一非标记内容行）与 git 判据不可得一律 fail-closed 拒放并强制留痕（完整 SHA、条目 id、非标记文件清单，留痕先于 worktree 清理）。可修性 / 真误报的语义判断超出门禁职责，MUST NOT 进入合并门判定；fixed=0 批里可能藏真修复的事实由 chain_skipped 下链重试路径承接，不由门禁裁决。放行合回复用既有批合回通道，不新写合并逻辑；产物去向对账挂链级 rollup 与台账注记，runner 层 run 终态发出时点与语义不动。

## Consequences

门禁结论机械可测、可用反例测试钉死（混合批不误放）；纯标记注释不触运行时行为，放行批跳过回归与 fixed>0 批既有口径一致。混合批中的真实修复仍被拒合回，但弃件留证保证可按 SHA 人工 cherry-pick 捞回——可捞回凭证替代门禁做「值不值得留」的判断。后续向合并门扩展任何新放行分支时，判据必须维持纯机械可测形态；引入语义 / 模型判定须显式推翻本裁定。
