# ADR-006：配置分级深度合并（用户级 + 项目级）

date: 2026-09-02
status: accepted

## Context

配置只有项目级一份时，多项目共享的 provider 凭据、模型分配等须逐项目复制维护。配置分级要求：用户级与项目级文件同名（`.fenix/config.yaml`）、作用域由所在目录决定；项目级只覆盖个别键，未覆盖的键继承用户级——这要求合并语义与校验策略一并裁定。

## Decision

- 层级与路径：用户级 `~/.fenix/config.yaml`，项目级 `<project>/.fenix/config.yaml`；daemon 读取有效配置一律走 `resolve_config(project_root)`，单文件直读路径废弃。
- 深度合并语义：dict 键递归合并，标量与 list 一律整体覆盖（`llm.providers` 等列表不做元素级合并）；项目级优先于用户级；合并返回新 dict，不改入参。
- 兜底与校验：用户级或项目级任一缺失都合法（按空配置参与合并）；有效配置缺 `project.name` 时以项目根目录名补齐；顶层必填键存在性检查放宽为「已有键全部值级校验，缺省键由消费方默认兜底」，解析层不因缺键拒绝启动。
- 解析失败不静默：用户级文件 YAML 损坏按空配置处理并记录 error 返回，不阻断 daemon 启动。
- 向后兼容：无用户级文件时合并结果即项目配置，现有项目行为不变；用户级文件不应定义项目身份，合并时项目级 `project` 键优先。

## Consequences

- 多项目共享配置一次维护；配置完全继承用户级的项目也能被正常监控与启动。
- list 整体替换语义与部分用户的元素级合并直觉相悖，覆盖关系必须以「来源层级标注」呈现给用户。
- 宽松校验可能掩盖项目级 YAML 语法错误——解析失败的 error 通道是唯一暴露点，不允许静默丢弃。
