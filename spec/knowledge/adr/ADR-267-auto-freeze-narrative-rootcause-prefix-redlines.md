# ADR-267：自动冻结文案按根因取专用前缀，人工冻结豁免契约不可动

date: 2026-10-11
status: accepted

## Context

评审车道自动冻结复用「用户指令冻结」文案前缀，恰好命中有意等待豁免
（`_INTENTIONAL_PAUSE_MARKERS` 与 `frozen:` 前缀两类文本形态），压制了本应
由熔断冷却承载的自动恢复，把供给瞬态失败升级成人工处置事件。同时解冻还原
（`parse_orig_status`）依赖冻结文案内嵌的「原状态 reviewing」子串，冻结与
告警依赖 `freeze_for_human` 成对入口——文案不是展示层，而是被豁免判定与
解冻还原两处机器消费的契约载体。

## Decision

自动冻结文案必须按根因取与人工冻结可区分的专用前缀（自动冻结不得自称用户
指令），并守三条红线：①内嵌 `parse_orig_status` 依赖的「原状态 reviewing」
子串并保留既有标记子串；②不得命中 `_INTENTIONAL_PAUSE_MARKERS` 三短语、
不得以 `frozen:` 开头——不得挪用有意等待豁免；③仍经 `freeze_for_human`
成对入口落冻结与告警。`FREEZE_ERROR_PREFIX` 常量与 `freeze_spec` 人工冻结
路径的豁免语义不得修改。冻结置 `frozen=True` 后被有意等待豁免命中属「冻结
转人工」预期语义——文案区分的目标是归因准确，不是逃过豁免；供给瞬态的
自动恢复由分类层（infra 不冻结）承载，不在文案层做文章。

## Consequences

- 自动冻结与人工冻结在告警面、豁免面、解冻还原面三处可机器区分，自动链路
  不会因文案形态误占人工豁免通道。
- 新增自动冻结路径受三条红线约束：文案空间与解冻还原、豁免判定两个机器
  消费点耦合，改前缀必须核对两处判定词表。
- 「冻结转人工」豁免命中保留为预期语义，自动恢复能力完全取决于失败分类的
  infra/content 归因正确性——归因错分会连带冻结语义错配。
