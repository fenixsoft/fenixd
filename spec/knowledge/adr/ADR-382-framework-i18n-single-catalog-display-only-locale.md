# ADR-382：框架 i18n 消息目录单源与展示级 locale 解析

date: 2026-11-25
status: accepted

## Context

框架三层用户可见面（Dashboard 前端静态文案、后端 API 展示型字符串、CLI 人读输出）原为纯中文硬编码，无国际化机制，非中文使用者不可用。SPEC 命名体系已有「英文 id + 中文标题」双语数据基因，界面偏好已有主题三档范式（localStorage 偏好 + 配置面板 + 首帧防闪烁 + 守卫测试）可镜像。国际化改造存在三类结构性风险：多消费面各自维护字典必然漂移；locale 若渗入业务逻辑会造成同键并发请求行为分叉；agent 提示词与 skills 文档是 LLM 功能面，翻译即行为变更。

## Decision

1. **消息目录单源**：用户可见消息唯一载体是 core 层单源目录（`core/i18n.py`：zh/en 双语字典、`t()` 查询、en 缺键回退 zh、未知键原样返回键名）。后端 Dashboard API 展示型字符串（error 字段、后端组装下发的展示标签/描述）与 CLI 人读输出共用该目录，禁止任何消费面自建第二份字典；前端界面静态文案走 umi locale 目录（`src/locales/`），前端自有 kind→标签映射不进后端目录——三层消息面边界以此划断。
2. **locale 解析严格展示级**：后端按请求 `Accept-Language` 前缀白名单（zh/en）解析，结果仅作用于该请求的展示型字符串，禁止影响业务逻辑判定；CLI 解析链 `--lang` > `FENIX_LANG` > 配置 `general.locale` > 缺省 `zh`；前端三档偏好（system/zh-CN/en-US）镜像主题范式，缺省跟随浏览器 locale 并归一映射落受支持档。
3. **翻译面排除边界**：`agents/*.md`、`skills/*/SKILL.md`（LLM 功能面）、`docs/help/` 正文、SPEC 生成产物模板、后端内部运行日志一律不翻译。
4. **en 目录以 zh 目录为 spread 底座**：en 缺键运行时回退中文、永不裸键名，翻译进度与交付解耦。

## Consequences

后续新增用户可见消息须先落 zh 键（可分批补 en），API/CLI 消费面零成本获得双语，翻译分批推进不再阻塞交付；展示级解析使语言切换与业务行为完全解耦（并发请求各按请求头渲染）。代价：agent 提示词与帮助文档对英文用户仍为中文（有意接受）；embed 态语言不随宿主 dsh web（与主题不同，不扩 embed 契约）；浏览器系统语言运行期热变化不实时跟随（跟随档解析时刻取值）；无第三语言语言包加载机制（目录结构天然可扩展、本期不做）。
