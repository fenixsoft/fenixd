# ADR-129：run 归属判定单一真源全等匹配，失败计数保留显式子集

date: 2026-09-21
status: accepted

## Context

spec 名互为前缀时，按前缀 glob 命中 run 文件会误归属（fix-x 命中 fix-x-y 的 run）；瞬态重试后缀 `-r<n>` 未被归属解析覆盖时，40 个在跑 run 文件解析出伪 spec 键——活性判定取假、预算豁免失效、stuck 误报误杀。同时监控侧一张前缀表被两类语义共用：表自述「失败计数子集」，却是 spec 名归一化的唯一消费源——把归一化改用全量前缀表，失败计数口径会被静默扩大（planner/test 失败也计入告警阈值）。

## Decision

- run_id → spec 归属判定统一走单一解析函数 + **全等比较**，禁用前缀 glob 作为归属判据；agent 前缀表为唯一前缀真源，后缀剥离必须同时覆盖 `-a<n>`（attempt）与 `-r<n>`（瞬态重试），新增后缀形态先补解析再补消费点。
- 语义分层：归属/活性/归一化消费点用全量前缀集；失败计数保留显式子集常量（实现类前缀计入，planner/test 不计入）。一张表不得承载两种语义；任一侧口径变化必须显式声明并配测试锁定，不得以「只影响匹配广度、行为不变」为由静默扩散。
- 归属判定函数的修复（如补后缀解析）必须先于全仓消费点切换，否则会把「前缀误命中」换成「真实 run 漏命中」——后者会误报 stuck 并触发误杀。

## Consequences

- 历史 `-a<n>-r<m>` 文件的归属由伪 spec 键改归真实 spec，dashboard 分组与时间轴随之修正（属修正非破坏，验收须回归分组用例）。
- 全等判据消除互为前缀误命中整族问题；新增 run 文件命名形态时，解析函数与两张前缀表（全量集/失败子集）需同步评估。
