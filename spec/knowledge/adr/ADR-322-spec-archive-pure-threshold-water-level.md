# ADR-322：SPEC 归档纯阈值水位驱动——终态不设时效性归档通道

date: 2026-11-04
status: accepted

## Context

自动归档曾以「阈值排水 + 时效归档（终态 + verification-report.md + 目录 mtime 滞留 ≥72h）」双通道运转。时效归档的原始设计依据是「归档事件定期发生，归档蒸馏管线随之持续运转」；蒸馏触发已迁至 approve_push 推送成功转移（蒸馏输入双态解析：changes/ 优先、archive/ 兜底），归档不再是蒸馏的前置，时效通道失去存在依据。其副作用是把活跃区水位持续压至远低于 `archive.auto_threshold`（实证 20 目录 / 18 终态，阈值 50 形同虚设），使阈值失去「活跃区水位管理」的本意。

## Decision

- 终态 SPEC 的自动归档仅由阈值水位驱动：终态未归档计数 >= `archive.auto_threshold` 即按 `updated` 升序排水至低于阈值；低于阈值时终态积压滞留活跃区属预期形态。禁止为终态 SPEC 建立任何时效性（滞留时长/mtime 年龄）自动归档通道。
- STATE 无条目的孤儿目录不计入水位、永不被阈值排水覆盖，其唯一自动清理路径为时效判据接管（verification-report.md + mtime ≥72h，`archived_by=auto-orphan`）；废除该通道会让孤儿永久滞留并被每日盘点反复列示。
- 水位可见性由每日盘点纯信号承接：终态未归档计数 + 最老终态目录滞留天数聚合一条 INFO（24h 去重），把「时效归档告警」改造为「水位可观测」，常态信号静默化。
- 存量终态未归档 SPEC 不做一次性迁移，等待水位自然达到阈值（维持阈值左右正是本裁定的水位形态）。

## Consequences

- 「终态 SPEC 3 天内确定性归档」的保证消失，活跃列表长期持有 pushed 条目是设计内形态；活跃目录数增长有阈值封顶（增量上限约一个 threshold 量级）。
- 归档时点延后不影响蒸馏原料可及性：蒸馏触发在 push 时刻（彼时 SPEC 尚在 changes/），双态解析兜底 archive/；仅重启续跑/补蒸场景的原料路径落在兜底态。
- 后续任何「定期自动清理活跃区终态」的新通道构想均受本裁定约束，须显式 supersede；孤儿清理通道保留时效判据不在此限。
