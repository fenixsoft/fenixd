# ADR-190：新周期角色挂共享调度入口——状态键分离禁共享宿主键，注册表全链路同步，run 前缀独立并登记统计排除

date: 2026-09-17
status: accepted

## Context

角色族扩张（如新增以代码为数据源的架构师角色）时，新角色与宿主角色（自省）同周期触发。按字面「共享同一状态判定」直接复用宿主状态会产生双向事故：宿主先写「今日已执行」键则新角色当日永不触发（功能静默失效）；新角色先写则宿主当日被抑制（既有功能回归）。更隐蔽的是宿主状态里还躺着增量窗口锚点键——被新角色覆写会把次日宿主窗口起点推到新角色完成时刻，静默丢失两 run 之间的数据。同时新角色的维护型 run 若不隔离，会计入宿主数据源统计，更点亮零活动防护的反面（使「当日无 SPEC 活动」判定失真、顺序依赖下误唤起宿主）。而新增一种 agent 类型涉及多处必须同步的注册表，漏一处角色即被当未知类型静默失效。

## Decision

- 调度入口唯一：新周期角色挂既有巡检检查点，禁新增定时器/线程；执行顺序固定，宿主路径（含其零活动跳过）先走完，新角色在后。
- 状态键分离（硬约束）：共享调度入口的每个角色持独立状态键；新角色禁写宿主的「今日已执行」键与增量窗口锚点键；巡检早退门扩为「宿主键与新角色键均已完成」才闭合——单角色失败同日可补跑一次，无需人工清状态文件。
- run 前缀独立并登记统计排除集：新角色用独立 run_id 前缀，必须一并登记进宿主数据源统计的既有排除集（run 统计、失败样本、告警口径），防非 SPEC run 污染宿主 prompt 与零活动防护；成本归账用独立类目文件。
- 注册表全链路同步：新增 agent 类型必须同步全部注册点——后端类型白名单、runner 角色映射、prompt 文件映射（缺失 fail-fast）、run_id 前缀映射、前端角色清单（与后端严格一致）；验收逐表断言，禁只测其一。
- 失败处置同宿主：记告警、当日不重试（防风暴），靠独立状态键次日自然重试；失败统计口径同步纳入，防连续失败无人察觉。

## Consequences

- 新角色接入成本前移为一张明确的接线清单，漏改形态被逐表断言钉住；静默失效在验收期暴露而非运行期。
- 共享入口零第二套调度器；两角色的状态、窗口、统计、预算互不污染，任一角色失败不拖累另一角色当日执行。
- 代价：巡检早退门随角色数线性扩展，新增角色必须记得扩门（漏扩则新角色永不触发）——该义务随注册表清单一并验收。
