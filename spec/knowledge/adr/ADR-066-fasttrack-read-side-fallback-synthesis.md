# ADR-066：fast-track/full 双模式产物差异由读侧回退合成吸收

date: 2026-09-11
status: accepted

## Context

fast-track 与 full 的验证产物形态不同：full 有验证引擎进度文件与独立报告，fast-track 只有裁决结果文件中的嵌套场景明细。读侧消费点若只认 full 形态，fast-track SPEC 在场景、报告、进度各通道全线空态。解决方案空间需要钉死：改写入端 schema、还是读侧回退。

## Decision

- **写入端契约不动**：fast-track 结果文件 schema 与 full 引擎写入逻辑均不改；形态差异一律由读侧吸收。
- **统一回退链**：各消费点在专属产物缺失时回退 fast-track 结果文件——专属副本优先、主树回退，spec 匹配守卫防串 spec（主树共享文件会被最新 run 覆盖）。
- **口径同源**：回退合成的计数口径与 full 终态同构，枚举按裁决链既有口径（豁免类不计入失败桶）；回退成功标记数据来源，可追溯可断言。
- **合成内聚在读侧数据层单一入口**，渲染层收纯参数；两路皆缺维持空态不阻断（阻断语义归验证报告闸门，不重复设闸）。
- 新增读侧消费点必须同样接入回退链，不得以「要求写入端新增产物」为解。

## Consequences

- fast-track SPEC 在全部读侧通道呈现与 full 同构的真实验证结果。
- 主树回退可能读到同 spec 旧一轮结果——专属副本优先使实际命中概率低，属既有同险不新增缓解。
