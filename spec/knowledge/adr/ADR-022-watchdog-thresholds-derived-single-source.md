# ADR-022：看门狗阈值单源派生，不设独立配置键

date: 2026-09-02
status: accepted

## Context

stuck 恢复阈值与 run 超时各自独立配置。auto-recovery 的安全前提是「恢复阈值 > 运行寿命」，用户把超时调大而阈值未动时，恢复动作成为对健康运行的定时误杀；反向漂移（阈值 > 超时过多）则推迟真死锁的发现。supervision 绝对上限与「超时 + 续期」脱钩是同一类病的第二个实例。唯一安全的关系「恢复阈值恒大于超时」只能靠派生保证，不能靠人工维持两个键一致。

## Decision

- 恢复判定阈值 = `run_timeout_seconds` + 固定宽限（模块常量 600s，非配置）：宽限让超时终止与恢复判定之间留出确定性时序余量，消除两看门狗同秒触发的竞态。「两值一致」的用户意图由唯一旋钮 + 恒定关系实现，而非字面相等。
- 派生计算集中于单一助手函数，全部消费方（调度巡检、自愈监视、supervision）同源调用；旧独立配置键删除读取逻辑、忽略 + 每 daemon 生命周期一次 WARNING。
- run_timeout 缺失或 ≤0 时回退安全默认值并 WARNING，防止超时被关掉导致恢复永不触发。
- 绝对上限与「超时 + 续期时长 × 续期次数」联动校验，脱钩时 ERROR 并按兜底公式取值；supervision 未启用时不校验。
- 后续新增成对时间阈值（锚点旋钮 + 派生量）一律派生自锚点，不引入第二个独立键。

## Consequences

- 配置面单旋钮，两类看门狗永不脱钩；真死锁的发现时点随超时水涨船高是有意取舍——活进程盲态的根治在进程存活探测（ADR-025），不在更激进的阈值。
