# ADR-169：在飞判定经属主层公开方法封装且异常按在飞处理（宁紧勿松）

date: 2026-09-28
status: accepted

## Context

跨模块消费者（陈旧自愈空闲判定、fast-track 恢复判据、admin 孤儿探针）需要知道某车道/run 是否在飞，而在飞登记散落在属主模块的私有结构（如 dispatcher 的 `_ocr_lane_inflight` 字典，仅为单飞去重而设）。2026-09-23 事故：自愈空闲判定四维在飞信号均不含 impl-ocr 车道，车道启动当秒空闲计时开始累计，120 秒后自愈写入 restart_request，supervisor SIGTERM 杀掉在飞车道 run。修复时存在三条路径：把车道登记塞进 `agent_runner._running_agents`（值为 Popen，车道是线程体跑维护型 run，语义不合）；消费者跨层直读属主私有字典（把内部结构钉死为跨模块契约，属主从此不能重构）；或由属主层提供公开判定方法。

## Decision

在飞状态判定由属主层提供公开方法（`ocr_lane_busy(spec_name: str | None = None)`：带参按该 spec 精确判定，供恢复判据「重入不与在飞收尾竞态」用；无参时任一在飞即 busy，供空闲判定维度用）。消费者禁止跨层直读私有登记结构，也禁止把线程型车道硬塞 Popen 语义的注册表。判定异常一律按「在飞/非空闲/阻断」处理（宁紧勿松：判定不可得时不得放行会 SIGTERM 杀在飞 run 的动作）；消费者侧薄容错单点维护（getattr 链：瘦门面/替身缺属性时该维度静默退出不阻断、不抛异常；仅采纳真 bool，非 bool 返回不误判为阻断）。

## Consequences

新车道/新 run 形态接入自愈、恢复、探针等跨模块判据的成本固定为「属主层补一个公开 busy 方法 + 消费点加一维」，属主私有登记结构保持可自由重构。代价有二：判定不可得时自愈被抑制而非放行——由车道硬超时保证抑制有界，陈旧告警持续可见兜底可观测性；缺属性容错意味着消费点接线遗漏时该维度静默失效，须以源码接线契约探针类验证场景守住（本裁定的落地 SPEC 即含逐点接线探针）。
