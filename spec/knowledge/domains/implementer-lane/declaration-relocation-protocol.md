# 交付物声明重定位协议

陈日声明（规划期路径被上游演进甩下）的确定性识别与凭据驱动的机械重定位：改声明必须以交付物真实落地为前提，全程审计可回滚。

## 现行规则

- 陈日声明确定性信号：对生效声明中的 **`modify` 条目**，该路径在**基线树（主树 HEAD）不存在**即判陈日声明——`modify` 语义即「上游已存在、本轮改动」，基线无该路径只能来自上游删除/改名。判定零语义推断，只认基线树存在性事实，与本轮实现产出无关。`new`（基线期望本就是不存在，恒不参与陈日判定，未落地缺件走既有缺件处置与收缩防护）、`delete`（反判存在性）与 `reference`（软校验）不参与陈日判定。
- 重定位凭据契约：重定位由凭据驱动，凭据含三项——①旧路径在基线树不存在（陈日信号）；②替代路径在实现分支 HEAD 真实存在；③来源标注（如 `relocated`）。三者齐备方可改写生效声明；任一缺失不重定位（降级走既有缺件处置）。替代路径来源为 LLM 终审给出的 `actual_path`（复用 `typo` 归途）或机械定位（basename 在树内唯一命中）；多命中或零命中不自动重定位（转 LLM 终审或人工）。
- 机械执行与写回层：重定位机械执行（不经 Agent 手改文档）——将生效声明中旧路径确定性替换为替代路径（同名去重，与既有 `replace_declared_path` 语义一致），改写目标与提交根为**生效声明命中的那一层**（与守卫读取基准同源）：worktree 命中 → 该 worktree（分支提交）；主树命中（`source == "main"`）→ 主树 `spec_dir` 就地写入（此时主树即读取基准，不构成错层）；无 worktree 且读取命中分支版本（`source == "branch"`，`spec_dir` 为 `None`）→ 不得通过回落写主树「就地生效」，走既有缺件打回/凭据登记通道，由实现方在分支上续做。worktree 来源时不另行单独写主树声明（主树对齐由 merge-back 携带分支提交完成）。
- 审计与复检：每次重定位落 dispute 审计流（旧路径、替代路径、来源标注、触发 run id、声明改写前后 diff、时间戳），人工可据审计复核与回滚（恢复声明段原文 + 触发重派）。修正执行后以生效声明解析入口复检旧路径不再作为硬校验项；复检不一致（写读错层）告警并记 error 明细，不静默放行。
- 已对齐声明的凭据登记：实现方可能先行改写生效声明（如按派发处方对齐陈旧路径），机械文本替换会因「声明段无该条目」上抛；凭据三要素仍齐备时，裁决流水线以**凭据登记**方式落册（审计含旧/新路径、来源、run id、时间戳），不因文本替换不可用而卡死，不静默放行，亦不无界重派。凭据未齐备（如替代路径在实现分支 HEAD 不存在）不登记，按既有缺件处置。凭据落在跨 run 持久的 dispute 审计流（`.fenix/dispute_audits.jsonl`）——上一轮重定位后本轮未 merge-back 时，下一轮守卫对同一陈旧基线的豁免判定仍可命中；凭据在册后收缩防护视为「有据重定位」，不再判 `removed`。
- 重定位后防洗白复检：改写落盘后以改写后的生效声明重跑收工守卫对账——替代路径在实现分支 HEAD 真实存在方可通过；仍缺失不放行（改写声明 ≠ 放行缺件），按既有缺件处置路径处理。
- 失败安全：重定位任一环节异常（声明段解析失败、改写失败、并发编辑致内容漂移）fail-safe——该条不改写、不判定，回退既有缺件处置（LLM 终审/blocked 人工），不因重定位异常阻塞整条收工链，也不静默放行（WARNING 留痕说明异常）。
