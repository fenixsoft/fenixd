# ADR-153：清锚点前必须先判定恢复续做，保持态按出路分型

date: 2026-09-25
status: accepted

## Context

「新轮次派发前清除旧锚点」与「恢复续做复用保留分支」共存于各车道派发出口；无条件清锚点会把保留分支从 STATE 脱钩，分支上已提交成果整轮丢弃（实证：fast-track 车道漏接恢复续做标记，5 提交成果脱钩）。复用登记表被打回重派、瞬断重试、恢复续做多条路径共写，「登记非空」不能推出「本轮是恢复续做」。

## Decision

- 派发出口处置锚点前 MUST 先做续做判定：读恢复续做标记 → 载体三态解析 → 一次性消费标记 → 仅解析未命中才清锚点（消费先于清除）。
- 全部车道全部派发出口的锚点处置矩阵必须完备：降级/旁路出口（规模预检降级、派发异常回滚、已确认 run 死亡的有意重置）MUST NOT 清锚点、MUST NOT 消费标记——标记与锚点应完好交给会正确消费的车道。
- 恢复归因 MUST 用显式来源标记（复用登记时携带 recovery 来源），禁以「复用登记非空」为恢复判据；未命中恢复来源时回退普通继承注记，禁把普通重派/重试轮注记为「曾被中断」。
- 恢复续做收口字段集 MUST 与既有先例同集同形状：残留验证锚点会被误读为在飞验证、残留合并失败连击计数会触发误告警。
- 续做判定复用 `_resolve_preserved_branch`/`resolve_resume_site` 单点，禁漂移副本；载体工具不可用=判定未运行，MUST fail-closed 拒绝（STATE 零变更、可重试）；degraded 仅当判定真正运行且给出「无锚点/零提交/载体不可用」结论。
- 保持态按出路分型不合并：取消保持（人工取消，唯一出路显式复位，恢复链豁免）与冻结保持（冻结终止，现场已保全，出路解冻自动续做）。冻结终止写冻结保持的同时清取消保持（防解冻后恢复链被残留取消保持跳过）；保持态字面写点数受静态守卫锁定。

## Consequences

保留分支成果不再被锚点清除丢工作；恢复与重派归因正确、提示词注记不误导 Agent；恢复续做 STATE 单一形状，不因入口不同产生漂移。
