# ADR-148：verify-serving 目录回收按多证据保留集判定，fail-safe 一律保留

date: 2026-09-23
status: accepted

## Context

verify-serving worktree 是完整仓库副本 + 依赖实装，单份 GB 级；其回收只挂在 spec→done 事件且目录路径取自仅存内存的缓存，daemon 重启清缓存、spec 未经 done 消失（archive、手动清理、状态回退）等路径下目录永久残留。清扫是破坏性删除，误删在飞验证的工作区是最高代价失败形态。

## Decision

- 保留集判据为多重独立证据，满足其一即保留：spec 存活（changes 或 archive 中在册，归档等同存活）、登记在册（登记路径 resolve 后全等匹配，空串登记项不参与匹配）、活进程（argv/cwd 指向该目录）、宽限期内（与清扫节拍同量级的模块常量，不新增配置键、不复用语义无关的既有键）。四个判据 helper 均只读且异常时返回「保留」。
- mtime 陈旧度不作为删除依据（在飞验证可能长时间无文件变动，mtime 不可靠），只作宽限期豁免维度。
- 删除执行复用既有幂等 remove（worktree remove + prune），清扫器只负责「枚举 → 判据 → 调用」，不重新实现 git 调用；触发点为启动 reconcile + 周期节拍两处，事件路径（done）保留但不可作唯一机制——它覆盖不了重启与绕过 done 的消失路径。
- 目录名解析显式校验时间戳段位宽，防把含数字后缀的 spec 名误解析；归档匹配用全等后缀而非前缀 glob（spec 名互为前缀会误归属）。
- 依赖实装默认采用硬链接模式（共享 inode，单份占用从 GB 级降到数十 MB）；镜像默认值的多处落点 MUST 同步。

## Consequences

- 增量泄漏被启动 + 周期机制封住；存量主体因「归档等同存活」会被保留，须由人工/运维一次性清理——自动机制只承诺不再累积，不承诺回收存量。
