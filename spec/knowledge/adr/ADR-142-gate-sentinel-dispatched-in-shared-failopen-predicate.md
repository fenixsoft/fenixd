# ADR-142：门控字段哨兵值必须在共享谓词内显式分派，禁止消费点各自判等

date: 2026-09-23
status: accepted

## Context

调度门控字段 `start_after` 的共享谓词是 fail-open 语义（字段缺失/非法值不阻塞）。要在此字段上表达「手工激活、永不到期」的哨兵值，若散落到各消费点判等，必有一处把哨兵当非法值按 fail-open 吞掉、反而立即放行——哨兵语义与 fail-open 缺省恰好相反，「静默放行未激活 SPEC」是最高危失败形态。

## Decision

- 哨兵值在字段的共享谓词内、解析之前显式优先判等（大小写不敏感 + 容错空白，兼容人工手改 STATE），全部派发入口经同一谓词零改动覆盖；任何新派发入口 MUST 过该谓词，禁止绕过或第二处判等。
- fail-open 的既有旁路行为（如到期检测对不可解析值跳过）保持原样，并在注释显式标注「哨兵经该路径天然豁免，勿改」；MUST NOT 顺手改写判空条件使哨兵被判到期。
- 哨兵复用既有单字段而非新增 STATE 字段（哨兵与定时值互斥）；共享读函数原样返回哨兵字符串，MUST NOT 折叠回 None（前端标记丢失）或被伪渲染成时间戳，各读侧消费点按哨兵分支安全降级。
- 激活动作 = 哨兵置空 + 复用既有即时唤醒信号；对非哨兵态的操作幂等拒绝，MUST NOT 误清既有定时值。

## Consequences

- 字段取值域扩展（时间戳之外多一类哨兵）零 schema 变更、存量零迁移；后续任何「在一律放行的门控字段上表达一律阻塞」的需求都走同一谓词内分派范式。
- 哨兵的读侧扩散面（列表摘要、CLI 渲染、弹窗预填）是固定核对清单，防伪时间戳/丢标记回归。
