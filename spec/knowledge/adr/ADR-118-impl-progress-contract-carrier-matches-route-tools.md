# ADR-118：实现进度契约载体与路由工具能力一致

date: 2026-09-19
status: accepted

## Context

任务完成度门禁原本只在 `verified→done` 转换点检测，「没做完却报 success」要等实现、验证、合并全走完才暴露，且 verified 无回炉出口成死角。提示词要求的进度载体（TaskCreate/TaskUpdate 工具）在实测全部 runner 派发的 run 中出现 0 次——Task 家族在派发路由上不存在，契约从未可执行。无条件强制会让硬门在无该工具的路由上永远无法通过：把「防造假」做成「防收工」。

## Decision

- 任务完成度硬门前移到实现者收工时刻（产物硬门层），与 verified→done 的既有转换点门禁并存；实现者获得诚实申报出口：结果文件 `status: partial` + `completed_tasks`/`unfinished` 结构化字段。
- 进度契约载体固定为结果文件结构化字段（与既有结果契约同址、可机械对账、partial 有天然缺口字段），不依赖过程性工具调用；工具契约改为条件生效——按本轮 init 事件的 tools 数组探测，含 TaskCreate 才注入 Task 粒度契约。
- 能力探测缺失时 fail-open 并记审计事件：「无法核对」不是「核对不通过」；无条件强制会把每轮实现烧在同一个不可满足的判据上直至 blocked。
- `partial` 与 error 同侧处理：不进 implemented、走失败重派、**消耗**实现尝试预算、归因必须由 unfinished 清单构成（空壳归因禁止）——免费续做通道会让 partial 申报成为绕开预算的逃逸口。
- 硬门失败的退化语义是原地续做（保 worktree、同 session resume、注入缺口清单），不判失败重派；判失败会丢弃已完成部分的全部上下文。
- tasks.md 勾选解析收敛单一纯函数实现点，禁第二套正则（两套口径漂移会产出「硬门放行、门禁拦截」的矛盾结论）。

## Consequences

- 显式空跑（自报成功但零交付）从可发生变为不可能；「先勾后做」仍不可检——申报自洽不是工作已做的证据，由验证场景覆盖任务面兜底，如实记入文档不假装解决。
- 完成度判定读 worktree 内的结果文件原件（绑定本轮 run），不读主树共享拷贝（跨 spec 无条件覆盖，混轮次即污染）。
