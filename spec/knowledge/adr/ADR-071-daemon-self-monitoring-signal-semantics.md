# ADR-071：daemon 自检信号口径——错误升级按时间窗+指纹，代码陈旧按 mtime 指纹

date: 2026-09-11
status: accepted

## Context

「从日志尾部往回数连续 ERROR 行数」的升级口径在日志活跃期被其他级别打断、物理堆积期才撞上——触发机理取决于日志安静度运气，同一故障首复现后无人介入窗口被拉长。另外「磁盘代码已更新、进程仍跑旧码」的不一致没有任何检测。升级机制必须消除对日志安静度的依赖，且不放大告警噪音。

## Decision

- **错误升级按「时间窗 + 错误指纹」**：窗口内同指纹复现达阈值且相邻间隔受约束即升级；无状态每轮巡检重算（不持久化计数器，重启安全，窗口滑动自然过期）。
- **指纹 = component + 保守归一化的 message**：只归一时间戳/UUID/hex 串/纯数字四类，不动路径与文字骨架——过度归一化会把异类错误误聚合，复现阈值已提供缓冲。逐行 JSON 解析；非 JSON 行回退 raw 行归一；timestamp 缺失 fail-closed（宁可多告警不漏告警）。
- **代码陈旧检测用 mtime 指纹**：进程启动时缓存代码文件集的 max mtime 为基线，热重载轮询比对，超基线每进程 WARNING 一次。不用 git hash（覆盖不了未提交修改、怕非 git 环境）不用 schema 版本号（依赖人工 bump 纪律必腐化）。
- **阈值保持模块常量，不进配置**：规避「新增配置项必须带 Dashboard 界面」约束，也避免为内部检测口径扩配置面。

## Consequences

- 升级不再依赖日志安静度，无人介入窗口收敛到巡检周期量级；单次瞬时错误、不同错误各一次、相隔超限的孤立抖动均不触发。
- touch 无内容变化会产生一次可控误报（每进程一次）；告警频率上升由既有 cooldown 节流兜底。
