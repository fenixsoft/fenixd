# 项目架构图（floorplan 按需生成）

<!-- knowledge: capability=project-architecture-diagram rev=7
     sources=spec/archive/2026-10-04-add-project-architecture-tab,spec/archive/2026-10-04-fix-archify-vendored-injection,spec/archive/2026-10-04-add-architecture-two-stage-generation -->

项目详情页的「项目架构」页签：用户手动触发生成项目高层运行时架构图（headless claude 按 vendored floorplan skill 工作流生成），产物经后端下发、前端沙箱渲染，让读者快速看懂项目顶层子系统、调用与数据流、外部依赖。

## 规则

- 页签与手动触发：项目详情页页签序列固定为 …→测试回归→项目架构（key `architecture`、label「项目架构」）→项目知识，对全部注册项目一视同仁（无项目级特殊处理），未注册项目查询一律 404。页签内容由独立组件 ArchitectureTab 承载，按 `active` 门控——仅选中本页签才发起请求，未选中零请求。系统不得在页面加载、页签切换、daemon 启动等任何时机自动触发生成。「刷新架构图」按钮统一置于项目标题栏右上角（2026-11-25 用户指令；仅选中本页签时渲染——ArchitectureTab 经 forwardRef 句柄暴露 refresh、经 onControlChange 签名去重上行 generating/triggering 快照驱动按钮 loading/disabled，generating 态分面内不渲染按钮），从未生成时展示空态提示引导到该按钮。none/failed 态快操按钮（2026-11-25 用户指令「按钮显示在内容区域中央，以便用户快速操作」）：分面内容区（沿用 ready 全幅几何的容器）中央居中渲染大号主按钮（标题+按钮+说明文案的居中列；failed 态在按钮上方展示失败原因），与标题栏按钮同走 handleRefresh、loading/disabled 同步，两入口行为一致；中央按钮相对内容区居中（含侧栏偏移的内容区几何中心），不相对视口。
- 生成范式（单段式管线）：点击「刷新架构图」后 POST 只受理并立即返回，实际生成由 daemon 后台线程执行**单段**生成管线——一个小 prompt 的一次性 headless claude（`claude -p <提示词> --permission-mode bypassPermissions`，cwd=项目根，`start_new_session=True`，env 剔除 agent-run 专用三键 FENIX_RUN_PROJECT_ROOT / FENIX_RUN_WORKTREE / CLAUDE_CODE_ENABLE_TODO_TOOLS）按 vendored floorplan skill 的工作流出图。HTTP 线程不得同步等待生成（范式见 ADR-216）。生成完全在开发主链路之外：无 run 台账、无车道、无预算、无新增配置项，超时等均为模块常数。prompt 落在「小上下文 × 短输出」安全区、不内嵌 vendored SKILL.md 与 references 全文（见 ADR-224）。spawn 前先 unlink 旧 diagram.html（missing_ok，尽力而为）：产物存在即代表本轮写入，claude 自述完成但写盘被静默拒绝时旧图不再混入本轮 ready。
- 生成 run 工作流（floorplan 子集）：prompt 以包根绝对路径引用 SKILL.md 与 `references/schema.md`（architecture.json 契约）、`references/choosing-boundaries.md`（边界划分方法），指引中的 `${CLAUDE_SKILL_DIR}` 占位符即包根。步骤：① `FLOORPLAN_UNATTENDED=1 node <vendor>/scripts/scan.mjs . --out .fenix/architecture/floorplan/.cache/scan.json --json` 机械扫描（repos/LOC/entrypoints/跨仓 HTTP 边/外部包，只读）；② 在 map 目录写 architecture.json；③ `FLOORPLAN_UNATTENDED=1 node <vendor>/scripts/build.mjs . --out .fenix/architecture/floorplan --json` 构建校验并按报错迭代至 ok（unassigned < 10%）；④ `node .fenix/architecture/floorplan/serve.mjs --export .fenix/architecture/diagram.html` 导出**自包含单文件** HTML（内联全部脚本样式与数据、script hash CSP、无外部请求、无 Ask 交互条）。禁跑 describe.mjs / recent.mjs / open.mjs / status.mjs / refresh.mjs / plan.mjs（逐文件描述与 Ask 服务器等交互特性不需要）。unattended 模式保证：只写 map 目录、不写 CLAUDE.local.md、不动 `.git/info/exclude`、不起服务器不开浏览器。architecture.json 分段小步写（先最小骨架再逐段 Edit 补全），禁止单次巨量 Write。
- floorplan 依赖保障（vendored 随库分发）：floorplan 以 vendored 整包随本仓库分发于 `vendor/floorplan/`——SKILL.md 与 scripts/（scan/build/export 链）、references/、assets/（内联 ELK 与字体原料）等必须整包在位；上游 LICENSE 随包保留，溯源（上游仓库/快照 commit/许可/node>=18）与升级方法见 `vendor/floorplan/VENDORED.md`，升级=整体替换 skills/floorplan 内容并同步更新该文件，禁止只换 SKILL.md。spawn 前校验包完整性：`SKILL.md` 与 `scripts/scan.mjs`、`scripts/build.mjs`、`scripts/lib/common.mjs` 存在且非空；缺失或为空判 failed，错误信息注明 vendored 包缺件属部署损坏、提示对照 VENDORED.md 恢复，且 MUST NOT 触发任何安装动作。生成链路零联网安装、零用户环境依赖（不读不写 `~/.claude` 与 `$CLAUDE_CONFIG_DIR`），期间派生的唯一外部进程是 claude 本身。
- 图形态契约（约束落在提示词文本 + 判定链机械校验）：3–9 个顶层子系统节点（floorplan skill 自身契约即 3–9；每个大节点可带 3–12 个子节点）；1–3 条 flows、3–8 站 tour；第三方服务/外部存储用 external 节点表达（packages/hosts 字段）；**external 节点必须是汇点**——所有 edges 只允许从内部节点指向 external，禁止任何以 external 为 from 的边（external 之间/指向内部的关联一律改用 hosts/packages 字段表达不画边）：viewer 把 external 钉在 ELK LAST 层，external 出边会让导出图整张渲染崩溃（UnsupportedConfigurationException，2026-11-25 fenixd 图实测），而 build.mjs 只校验 schema 不校验边方向（上游盲区），故判定链在产物判定时 best-effort 读 map 的 architecture.json 补机械校验——存在 external 出边判 failed（错误含违规边描述），文件缺失/损坏放行（与 marker 缺失同哲学）；节点 label/summary、flows、tour 与全部图面文字用中文（白话、面向所有人）。顶层节点数机械校验只对「能提取到」的情况生效——提取到则越出 3–9 判 failed（错误信息含实际数量与允许范围）；marker 缺失提取不到时记 `component_count: null` 放行，产物可用性优先于校验完备性。
- 产物判定权威链：进程退出码 → diagram.html 存在且非空 → 自包含 HTML 特征（起始 `<!DOCTYPE html` / `<!doctype html` / `<html`，大小写不敏感——floorplan 导出产物起始为小写 doctype）→ 顶层节点数提取（stdout 末行 marker `FLOORPLAN_DONE <顶层节点数>`，倒序扫描、缺失记 null 放行）。判定权威是产物实况，不采信 claude 自述（口径见 ADR-217）；任一必需环节不满足判 failed。
- 无取证复用：单段管线不设探索段产物与 HEAD 指纹跳段复用——floorplan 的 scan.mjs 本身即是便宜的机械取证（秒级），每次 refresh 全量重新生成；无 TTL、无指纹头、无 evidence.md 交接面。
- 存储与单写者：产物按项目存于项目根 `.fenix/architecture/`（`diagram.html` + `status.json` + floorplan 脚本产物目录 `floorplan/`——scan 缓存、architecture.json、graph.json、index.html 与 build 生成的 serve.mjs/query.mjs，gitignored 运行时产物，目录按需创建；scratch 目录保留不清理，供排查），每次状态迁移 tmp+rename 原子写；dashboard 进程内 ArchitectureManager 持单飞锁与在飞进程句柄，是唯一写者。刷新即覆盖旧图，只保留最近一次，无历史版本。status.json 字段：`state` / `generated_at` / `started_at` / `error` / `duration_ms` / `component_count`（语义为 architecture.json 顶层子系统节点数），另加可选键 `stage`（生成 run 运行态 mapping；终态与受理初态 null，向后兼容，读侧容忍缺键）。
- API 端点（mixin 形态，query 传 project）：`GET /api/architecture/status` 返回 state（`none|generating|ready|failed`）、generated_at、失败原因与 stage 等；`POST /api/architecture/refresh` 受理返回 200，在飞期间重复 POST 返回 409 语义（不产生第二个 claude 进程）；`GET /api/architecture/diagram` 以下发 `text/html` 返回产物字节。state=none 时 diagram 返回 404 结构化 JSON 错误，前端不渲染 iframe。
- 生命周期治理（无死态）：同一项目同时至多一个在飞生成（per-project 单飞）；单段硬超时 1800 秒（模块常数），到时以进程组方式击杀 claude 及其派生子进程并判 failed（错误信息含超时秒数）；daemon 重启后 status.json 残留 generating 而内存无在飞进程时，读侧合成为 failed（生成被中断），不得永久停留 generating；failed 态展示错误信息且按钮恢复可点，重试受理即开始新一轮生成，旧失败原因被覆盖。
- 前端渲染：generating 期间以 3s 固定间隔轮询 status（活动门控内），标题栏按钮 disabled；ready 后以 `<iframe sandbox="allow-scripts">` 渲染产物（sandbox 恰为 allow-scripts，不给 allow-same-origin，产物脚本与主站 cookie/DOM 隔离，见 ADR-218；floorplan 导出产物 localStorage/pushState/fetch 均已 try/catch 或门控，沙箱内零 console 错误）。ready 态全幅渲染（2026-11-25 用户指令「不留左右上下边距，最大面积显示」）：不渲染生成时间/顶层子系统数等元信息行；容器负 margin 抵消 Tabs 导航缺省下边距 16 与内容区左右 padding（桌面 15/移动 12），高度 `calc(100vh|100dvh - 实测偏移)`——standalone 102 / embed 106（实测：标题行并入顶栏行，导航行底=顶栏 56+导航 46；embed=行壳位 60+46），minHeight 兜底，iframe 贴 Tabs 行底直至视口底缘（2026-11-25 两档视口实测零滚动零 console 错误）。下发 URL 不附带演示模式参数（floorplan 导出产物无此参数）。
