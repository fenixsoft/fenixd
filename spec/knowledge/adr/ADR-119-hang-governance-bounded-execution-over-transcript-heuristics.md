# ADR-119：挂起治理——转录启发式有天花板，主防线是有界执行

date: 2026-09-19
status: accepted

## Context

一次与变更无关的存量死循环烧掉 14.5h：死循环发生在 pytest 子进程内部，agent 本人的转录全程多样且合理。实测「重复工具调用占比」「结果文本重复度」等纯转录判据在挂起 run 与合法长跑 run 之间不判别甚至反向；心跳事件持续刷新事件窗口，使「窗口内零事件直判停滞」守卫恒久失效——活性判定被喂了假进展。预算刹车同时被绕开（见 ADR-120）。

## Decision

- 活性快照分离**实质事件**（assistant / 带 tool_result 的 user / result）与**心跳**（tool_progress）：进度语义只取实质事件，心跳不得刷新活性窗口。
- 挂起短路只在「可观测零产出」三条件同时成立时触发（阻塞等待超阈 + 输出文件零增长 + 工具完成数低于阈值）；输出文件不可观测即回退既有 LLM 判定。禁止使用纯转录重复度判据——实测不判别，下调阈值必误杀合法 run。
- 主防线是**有界执行**而非更聪明的检测：全量回归必须走有界入口（硬超时 + faulthandler 挂起时打印栈 + 超时输出挂起测试标识），禁止裸调 `pytest tests/` 无限等待；附基线对照模式在变更前基线的临时 worktree 跑同一套件，直接输出「存量 / 本次引入」归类。
- 并发隔离：套件入口主机级互斥（fcntl 文件锁）；端口分配去除「探测即释放」TOCTOU，提供保留已绑定 socket 的分配路径。

## Consequences

- 挂起在数分钟内以「挂在哪个测试」的形态显式失败，而非烧穿超时×重试；「合法慢」与挂起的残余混淆由三条件收窄，误杀后果有重试兜底，远优于整轮空转。
- 有界入口靠契约引导而非强制（框架无法拦截任意命令）；套件串行化以排队成本换伪失败归因成本的下降。
