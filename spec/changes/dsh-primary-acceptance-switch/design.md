## Context

SPEC-3 已使 `agent.harness: dsh` 端到端可用（假端点单车道冒烟级）。主 harness 地位的切换需要：可重复的验收证据、出问题时的回退路径、以及把「真实环境验收」与「缺省值翻转」两个人工决策从自动链路中隔离出来。

## Goals / Non-Goals

**Goals**
- 验收脚本假端点模式无凭据可重复（CI/回归可用）；真实模式由用户持凭据触发。
- 多车道（≥3）假端点全链回归。
- 运行手册覆盖切换/回切/故障处置全路径。
- 验收报告模板固定五段证据 + 决策申请段。

**Non-Goals**
- 真实全链验收的自动执行（人工触发，信号式交付物）。
- 默认值翻转的实现（用户裁决后的后续微变更）。
- 车道级路由、跨 harness 回退（仍属第二阶段候选）。

## Decisions

1. **验收证据以「既有机制产物」为唯一真相源**：run jsonl、投影可观测性计数（SPEC-3 交付）、`.fenix-run-result.json` 硬门、run_metrics——脚本只收集与比对，不另造证据格式；claude 基线对比用同夹具在 claude 通道的最近 run 指标。
2. **真实验收走信号式交付物**（restart_request 既有范式，参照 fix-dashboard-read-path-performance 4.2 先例）：agent 落位执行请求 + 预演自检（凭据存在性/健康检查/dry-run 计划），实际执行由用户发起——agent 无凭据与运维权限，写成任务必被打回（粒度规则五类之「需外部资源/人工运维门控」）。
3. **默认值决策进报告不改代码**：报告含决策申请段（证据摘要+建议+影响面），用户裁决后由后续一次性微变更执行（config 缺省值翻转 + ADR-271 补记）；本 SPEC 不含任何缺省值改动。
4. **验收发现缺陷回归本 SPEC 修复**：验收夹具/脚本缺陷直接修；dsh 通道功能性缺陷若根源在 SPEC-2/3 交付物，修复在本 SPEC 实现分支内完成并注明来源 SPEC（避免跨 SPEC 打回循环）。
5. **玩具项目夹具即测即弃**：临时目录注册、验收后清理（含 runs 产物），不污染真实项目注册表（孤儿实例事故教训：测试产物必须显式清理）。

## Risks / Trade-offs

- [假端点验收通过但真实模型行为差异导致验收失真] → 报告模板区分「假端点证据」与「真实证据」两栏，翻转决策只认真实证据；真实验收由用户执行时观察。
- [验收脚本自身缺陷造成误判] → 脚本测试（tests/test_dsh_acceptance.py）覆盖证据收集与判定逻辑；脚本失败 fail-loud 不出「假绿」报告。
- [玩具项目清理不净] → 夹具带唯一前缀 + 清理步骤纳入脚本 finally；runbook 记录手工清理命令兜底。

## Migration Plan

纯新增交付物，无迁移；回滚 = revert。真实验收的执行与裁决时点由用户掌握（todo.md 队列）。
