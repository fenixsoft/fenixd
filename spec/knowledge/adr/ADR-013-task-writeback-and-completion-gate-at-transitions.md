# ADR-013：任务进度回写与完成度门禁挂在状态转换点

date: 2026-09-02
status: accepted

## Context

agent 对「完成任务后勾选 tasks.md」的服从率不可靠，读侧实时叠加只在 run 文件存活期有效，run 清理后历史进度永久失真；同时「验证未跑完即放行推送」的缺口说明完成度必须有人在状态推进处把关。回写与门禁的挂载层级与位置需要统一裁定。

## Decision

- 职责分层：agent_runner 只负责子进程生命周期；项目级状态维护（任务进度回写、完成度门禁、merge-back 等状态机与 git 操作）归属 pm_engine，挂载在 run 终态处理与状态转换处。
- 任务进度回写为只增不减的并集语义：仅把未勾选任务按 run 记录确认为完成（`- [ ]` → `- [x]`，id 精确匹配），绝不撤销任何勾选；agent 自行勾选的记录即使 run 证据缺失也保留。回写在乱序/重放下安全。
- 完成度门禁置于状态转换点（`verified→done`、`testing→verified`），而非在每个推送入口重复校验；拦截时保留原状态并把缺口清单写入 error 字段供人工裁决。
- 门禁语义边界见 ADR-017：可重试的关口 fail-closed，重试成本高的关口 fail-open；「无证据可查」不卡死流程（无法证伪即放行，回写侧静默跳过）。
- daemon 产生的同步提交使用固定可识别的 commit message 前缀，与 agent 提交区分；工作树不干净时跳过本次回写，下个调度周期重试。

## Consequences

- 任务进度以 run 证据为准被确定性固化，run 文件清理后进度不再失真；验证「跑完才放行」由转换点闸门保证。
- 单点拦截意味着所有推进路径自动获得门禁，但也要求新增推进路径时核对是否经过同一转换点，绕过转换点的旁路会让门禁失效。
- 门禁误拦（任务清单本就不打算全做）是有意暴露而非故障，由人工在 error 信息与审批入口裁决。
