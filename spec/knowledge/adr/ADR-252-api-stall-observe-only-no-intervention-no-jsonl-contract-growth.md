# ADR-252：API 往返停滞只读侧观测，不干预、不扩 run-jsonl 契约面

date: 2026-10-07
status: accepted

## Context

run 是 claude CLI 子进程，单次 API 往返发生在子进程内部，框架对子进程内的请求不可重连、不可原地重试。合法长轮与真停滞在 stream-json 转录上不可区分：2026-10-02 potplayer-base 窗口实证，对照 run 亦有 119s 无事件空隙，目标 run 的 4 个 >60s 样本中 3 个落在 85–123s 区间。对停滞做期内自动干预（kill/重派/重试）既无从下手（黑盒），又会把合法长轮误伤成重试，且过早重试放大 token 消耗。同时 run jsonl 的行序/行数存在多处契约消费者（末行=终态、恰一条 run_metrics、深扫 error/stderr 计数、dashboard 增量索引），为观测目的扩事件类型会把契约面扩散到全部既有读者。

## Decision

子进程内 API 停滞（及同类的子进程黑盒现象）一律只做读侧旁路观测：期内样本完成时点打 WARNING 日志留现场、run 末统计结果随 run_metrics 结构化入账；不做任何期内干预——不终止/重启进程、不重派、不自动重试、不接独立人工告警与 admin 唤醒。观测产物不得向 run jsonl 注入新事件类型，结构化出口只有 run_metrics 字段与日志检索两条。未来任何「停滞自动干预/重试」类 SPEC 必须携带新的可区分证据（能可靠区分合法长轮与真停滞）以 supersede 本裁定，不得默认绕开；新增任何 per-run 观测指标沿用「字段入账 + 日志侧检索」出口，不动 jsonl 事件契约。

## Consequences

真停滞不会被框架自动止损，长尾时长成本被显式接受（限流/网关恢复依赖 provider 侧既有机制）；run jsonl 行序/行数契约面稳定，既有消费者零破坏。期内现场完全依赖日志检索与 run_metrics 字段聚合，转录中不新增可检索标记；告警线与统计口径、判停线三常量必须保持语义分离，告警阈值调整不得泄漏成判停行为变更。
