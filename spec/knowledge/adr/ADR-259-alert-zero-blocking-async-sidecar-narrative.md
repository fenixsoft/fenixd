# ADR-259：告警落盘零阻塞，LLM 增强走异步侧车补写

date: 2026-10-09
status: accepted

## Context

ADR-242 确立转人工裁决叙事挂告警写入口作纯增强、失败 fail-open，但初期实现把 LLM 生成放在落盘路径上同步执行（硬超时 60s 兜延迟）。「同步 60s 可容忍」的假设被实测推翻：potplayer-base 项目 45 条告警 0 条带叙事（两条超时 WARNING）；一条 judge_rerun_cap 冻结告警因叙事调用整窗超时延迟 60.58s 才落盘，恰逢网关长尾窗口（同期 judge run stall 188s）。告警本就在系统异常期高发——同步设计让叙事的失败成本直接加在裁决及时性上，与「裁决贵在及时」的立项初衷相反。

## Decision

- 告警落盘主链路结构上零阻塞：任何 LLM 增强内容不得在告警落盘的同步路径上生成。告警以机械文案立即落盘（落盘耗时不含 LLM 时延），增强内容后台生成、完成后异步补写。
- 告警记录本体（admin_alerts.json）append 后不可变，异步增强内容一律写独立侧车文件（`.fenix/admin_alerts_narrative/<alert_id>.json`，mkstemp + os.replace 原子写），读侧按 alert_id 合并渲染；禁对本体做「读改写整文件」的原地补写。
- 增强失败必须有终态：重试封顶（至多 2 次）全败、或熔断生效期跳过生成时，写终态侧车（text=机械说明、model=null）；禁以「生成中」pending 假态悬挂，读侧 pending 判定=侧车文件缺失。
- 后台生成配连续失败熔断（连续 3 次失败冷却 1 小时、冷却期零调用）与有界重试，防网关事故期逐告警白烧超时窗。

## Consequences

- 裁决及时性与叙事可用性解耦：网关长尾最坏退化为「晚到的调查」或「带终态失败说明的机械文案」，告警本体时效与 choices 处置闭环不受影响；人工已处置后补叙照常落盘（历史完整性优先）。
- 修订 ADR-242 的「叙事生成在落盘路径上同步执行、硬超时 60s 兜延迟」后果；其纯增强字段、机械闸门零 LLM、fail-open 边界裁定继续有效并延伸到异步形态（后台失败同样不阻断、不回滚告警本体）。
- 侧车文件成为新的生命周期责任：告警清理路径必须级联删除侧车；孤儿侧车无害（渲染按 alert_id 匹配不到即忽略），归档视图不含叙事属预期。
- 后续任何给告警（或同类 append-only 台账记录）增加 LLM 生成内容的需求，必须沿用「机械文案即时落盘 + 侧车异步补写 + 终态侧车防假态」形态，不得回退到同步生成路径。
