# ADR-327：v2 商业化界面例外域并存架构

date: 2026-11-05
status: retired
Retired: 2026-11-08 v2 商业化例外域并存架构主体已退役（2026-11-07），无取代裁定

## Context

商业化观感重构采用全新设计语言（Bento 磁贴：浅灰页底、白磁贴大圆角、黑主色按钮、蓝链接、语义胶囊徽标），与既有全站界面宪法全面冲突：统一标题栏形态基准、antd 默认圆角（6/4/8）、theme.ts dsh 配色单源、白底页底、PageContainer 布局承载均被新语言偏离。若原地改版，现产界面回归风险不可控且服务不可中断；若另起独立应用则重复基建（API 客户端、构建与托管链路）。同时宪法附则「未声明偏离判真违规」会使新界面在无登记通道的情况下被判定全面违规，需给出偏离的合法登记形态。

## Decision

采用例外域并存架构：v2 商业化界面作为独立界面域与现产界面双轨并存，四条支柱——

1. **路由前缀隔离**：v2 全部页面挂 `/v2/*` 前缀（hash 形态），既有路由表条目逐字零改动，未匹配 `/v2/*` 落既有兜底重定向；v2 路由条目不写 name/icon，`app.tsx` menuDataRender 白名单（现产侧栏菜单单源、手写数组不消费路由表）不新增 v2 条目——现产导航零污染。
2. **主题单源分立**：v2 域独立主题单源文件（Bento token 常量 + 局部 ConfigProvider，只作用 v2 子树），与现产 theme.ts 互不引用；v2 域外任何页面禁用 v2 主题。配色单源原则保持，例外域由各自单源分别承载。
3. **宪法例外域机制**：DESIGN.md 增设「例外域」小节形态（用途声明 + 域专属 token 表 + 与一般域偏离清单），例外域条款只约束域内页面、既有条款不回溯；域内偏离须在 SPEC design 偏离声明表显式登记，以免按「未声明偏离判真违规」误判。
4. **原型为 UI 真相源**：例外域界面以定稿原型为界面契约（与「数值以 Scenario 为准」同纪律等级），实现与原型冲突不得擅自偏离、须升级用户裁决。

是否将 v2 切换为默认界面由用户另行裁决、另行立项，本裁定不含默认路由切换。

## Consequences

- 现产页面零改动并存，商业化界面可独立实现、验收与迭代，交付风险被隔离在 `/v2/*` 子树内。
- 双主题并存存在漂移风险，以「域外禁引用 + code review 对照 + routes 快照守卫」压制；新增 v2 页面必须留在 `/v2/*` 子树并取用 v2 主题单源，给现产页面套用 v2 风格属违规。
- 例外域机制成为界面宪法的可复用扩展点：后续再引入整域定稿的新界面（另一设计语言）按同程序登记例外域，不再逐条对抗一般域条款。
- v2 域内功能扩张（占位分面实体化、默认路由切换）须各自立项，且仍受本裁定隔离条款约束；另立并存机制或回改现产主题单源须显式 supersede。
