# ADR-199：code-review 产物分片直写、发现单一入口与聚合消费口径

date: 2026-09-29
status: accepted

## Context

code-review 车道原产物契约为「单一 `out-<run_id>.jsonl`、agent 自觉逐文件追加」，在两起零产物事故（合计 $39.44）中同时于两环节失效：agent 选择 async 子代理并行审查后，claude -p 非交互模式 turn 结束即主进程退出，`Async agent launched` 元数据对应的批次结果永不回收；主 agent 把落盘视为「最后汇总」，等待期通读全部待审文件却零落盘。三轮提示词修复（落盘纪律、语义消歧、等待期纪律）均无法改变执行流，定性为架构问题而非纪律问题。既有产物硬门收尾拦截有效但纯事后；进度读侧只数主产物单文件，用户在前端盯 0% 无从分辨零进度。

## Decision

- 落盘义务前移：谁审谁写、审完即写——并行子代理各直写分片 `out-<run_id>-b<N>.jsonl`（N 为正整数），主 agent 汇总只作兜底、不再作为唯一落盘路径；并机制性禁绝「等待异步批次通知收工」的收工模式（非交互模式下该等待不存在）。
- 分片发现单一入口：`shard_paths` 是分片集合的唯一来源，进度读侧、收尾 ingest、产物硬门三消费侧一律经它取分片，禁止任何一侧自写 glob——多消费侧口径漂移是本仓高频事故模式。
- 聚合口径三侧统一：迭代顺序分片（N 升序）→ 主产物；同 `file` 多行保留先见者（分片是原始产出、主产物是汇总兜底）；`done` 按去重后文件数计，保证 `done==total` 语义严格成立；ingest 侧以指纹幂等兜底重复行。
- 读侧 fail-显式不 fail-静默：非 `-b<正整数>` 形态的同素材错名分片只 WARNING 点名、不消费，不放宽发现口径兜错名。

## Consequences

- 提示词无法机械强制子代理落盘（软约束），防线转为纵深：事中零进度停滞告警（超阈值 admin 告警，15 分钟量级可见）+ 产物硬门收尾兜底（聚合零有效行判整轮失败）——比用户肉眼盯 0% 严格改善，但不保证零丢失。
- 进度允许行数虚高（agent 重写已落盘批次为不同行），按 file 去重计数使虚高可控；台账不因重复行产生重复条目。
- 与 ADR-198（车道批内并行、orchestrator 单写者、子代理禁写产物）的边界：ADR-198 管辖「产物须喂回归/合回门」的车道（code-fix 等），单写者是单产物可验证性的前提，该裁定在其辖域继续有效；审查车道产物是 append-only 结果行、无回归合回语义，且并行与否由 agent 自主决定（框架不做子代理编排，为 Non-Goal），故写义务下放子代理分片直写。新增车道选择单写者还是分片直写，以「产物是否喂回归/合回门」为判据。
- 后续新增任何消费 code-review 产物的能力必须接入聚合入口，不得旁路自建读取口径。
