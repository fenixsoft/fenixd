# 交互契约与逐断言分诊
<!-- knowledge: capability=interaction-contract rev=1 sources=spec/archive/2026-09-07-add-interaction-contract-and-per-assert-triage -->

验证场景以交互契约声明操作与断言；裁决按逐断言分诊定位失败归属，豁免粒度到断言级，防止单条被掩盖的缺失行为被场景级豁免连带放行。

## 现行规则

- 可交互元素行为契约：页面类 SPEC 的场景生成必须保证每个渲染为可交互形态的元素（按钮、链接样式卡片、可点击行、表单控件）至少对应一个交互场景（断言点击/操作后的可观察结果），或在该元素定义处含「纯展示」声明；两者皆无的场景集判覆盖不完整，要求 planner 补齐。
- 契约可审计：可交互元素与场景的映射关系（或纯展示声明）记录在 scenarios.json 元数据中。
- 裁决逐断言归因：failed 场景的全部失败断言逐条归类（沿用四分类：product-bug / test-defect / flaky / env）并附证据；场景级豁免（不记产品 Bug）仅当该场景全部失败断言均被单独归类为非 product-bug 时成立——单条 product-bug 断言即阻止整体豁免。
- 断言级豁免清单：验证报告含「断言级豁免清单」小节，逐条列出被豁免的失败断言（场景、断言内容、归类、证据、豁免理由），供人工复核豁免是否掩盖真实缺陷。
- 实现任务书契约呼应：凡实现为可交互形态的元素，其行为必须在对应 SPEC 中有定义或在任务书中声明纯展示；两者皆无法满足时，实现 agent 在产出说明中列为「待裁决交互」（元素、现状、建议行为），不静默保留可交互外观。
