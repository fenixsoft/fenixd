# ADR-225：帮助文档机制描述按使用场景落位，不按提交历史集中

date: 2026-10-04
status: accepted

## Context

帮助文档需要持续跟上框架的机制演进（验证链、治理守护、生命周期、Dashboard 交互面等）。若每次补文档都新建一份「新机制汇总」，文档会随提交历史长出一条平行结构：读者按使用场景检索找不到入口，既有章节的叙事轴被稀释，汇总章与正文章还要双向同步、必然漂移。

## Decision

机制描述一律进「用户遇到问题时会翻的那一章」：env 豁免握手进验证体系章、瞬断解封进瞬断治理节、取消保持态进生命周期章并与 Dashboard「恢复运行」操作互为入口、质量门禁在 Dashboard 章与验证章交叉承载。帮助中心的组织轴是使用场景，不是提交历史；禁止集中新建「新机制汇总」章。篇幅上每项机制一段到一小节、先「用户看到什么/该做什么」再机制细节（用户视角两段式），禁止整段搬运 SPEC 设计文档；新增小节后置于相关既有小节、不改既有标题文本。

## Consequences

- 读者按现象检索总能命中唯一章节，无平行汇总结构需要同步维护。
- 单章篇幅随机制增长，靠两段式篇幅上限与小节后置插入控制；既有标题文本不动，锚点 id 不漂移，既有相对链接保持有效。
- 文档化 SPEC 的章节归属成为实现时的必答题，归属争议按「用户在哪个场景翻文档」裁决，而非按机制在哪个提交落地。
