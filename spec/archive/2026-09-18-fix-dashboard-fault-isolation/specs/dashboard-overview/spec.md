## ADDED Requirements

### Requirement: 概览项目卡片展示项目级错误态

概览视图的项目卡片 MUST 展示该项目摘要中的 `error` 字段（存在非空值时）：卡片 MUST 呈现错误态（警示色）并展示错误原因文案，MUST NOT 以正常的 daemon 徽标 / 进度数字形态呈现而误导用户认为该项目一切正常。

处于错误态的项目卡片 MUST 仍然出现在概览中（MUST NOT 被静默过滤）——错误态卡片本身就是「该项目当前不可用」的可见信号，供用户定位与处置。单项目错误态 MUST NOT 影响其它项目卡片的渲染、`totals` 的展示或页面整体可用性。

#### Scenario: 单项目错误态展示
- **WHEN** `/api/overview` 返回的项目中有一个携带非空 `error` 字段，其余项目正常
- **THEN** 该项目卡片显示错误态与错误原因文案，其余项目卡片正常显示，`totals` 正常展示

#### Scenario: 错误项目不被静默过滤
- **WHEN** 某项目携带非空 `error` 字段
- **THEN** 该项目卡片 MUST 出现在概览视图中并带错误标记，而非从列表中消失

### Requirement: 概览数据加载失败的降级视图

概览页在 `/api/overview` 请求失败时 MUST 提供可操作的降级视图：MUST 显示错误提示，且 MUST 提供「重试」入口以便在服务或磁盘恢复后就地重新加载。MUST NOT 只渲染空白页、空白骨架或永久加载态。

#### Scenario: 请求失败时显示错误与重试入口
- **WHEN** `/api/overview` 返回非 2xx 或请求本身失败，且页面此前没有成功数据
- **THEN** 页面显示错误提示与「重试」入口；触发「重试」MUST 重新发起一次 `/api/overview` 请求

#### Scenario: 重试成功后恢复完整视图
- **WHEN** 首次请求失败后用户触发「重试」，此时服务已恢复
- **THEN** 页面显示完整的项目卡片与 `totals`，错误提示消失

### Requirement: 概览刷新失败保留上次成功数据

概览页在已经成功加载过数据之后，若后续刷新（30s 心跳或 SSE 触发的重载）失败，MUST 继续展示上一次成功获取的数据，并在其之上显示错误提示。MUST NOT 因刷新失败清空已展示的项目卡片与 `totals`。

#### Scenario: 刷新失败不清空已展示数据
- **WHEN** 概览已成功展示过一次数据，随后一次刷新请求失败
- **THEN** 页面 MUST 仍展示上次成功的项目卡片与 `totals`，并额外显示错误提示

#### Scenario: 恢复后错误提示消失
- **WHEN** 一次刷新失败后，下一次刷新成功
- **THEN** 页面展示最新数据，错误提示消失
