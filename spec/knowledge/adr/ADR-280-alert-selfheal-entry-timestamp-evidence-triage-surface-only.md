# ADR-280：告警自动收口的证据源与收口面边界

date: 2026-10-25
status: accepted

## Context

告警自动闭环（ADR-043 的条件白名单契约）原本只覆盖 spec 附着族；基础设施瞬态族（daemon_errors 日志指纹风暴、run_infra_failure 熔断、evo 分析 run 失败、处置收敛升级「处置终态未收口」）的共同形态是底层故障自愈型——风暴过去即恢复，但告警本体无人收口、长期滞留人工待处理队列。为该族引入「签名安静」闭环判定时有两个横切问题必须裁定：闭环证据从哪里取（fenixd.log 会轮转，读日志做证据不稳定）；自动收口的边界划在哪里（AdminMonitor 孤儿处置生效核查的 fail-closed「不补记 resolved」契约，依赖处置台账不被旁路机制改写）。

## Decision

- **证据只取条目自身时间戳**：signal 族复现时刷新的 `last_seen`（缺失回落 `created`）是唯一安静证据；判定输入（告警列表、当前时刻）全部由调用方注入，判定模块保持纯函数、不读写文件、不读日志——条目时间戳由写入链维护、口径单一，日志轮转不影响闭环稳定性。收敛升级条目（spec-less escalation 带 `admin_run_id`）的安静锚点取「`admin_run_id` 名下 disposition 条目」与「同 signal_type 未收口 signal 条目」双源的最新时间戳，禁只锚 disposition created（否则底层风暴仍在复现时升级条目被提前收口）。
- **自动收口只作用人工甄别面**：写回只改告警条目自身（handled=True、handled_by=auto-self-heal、note 前缀「已自愈：」附安静证据），MUST NOT 改写 disposition 记录本体（result/status 逐位不变）；写回走独立函数与独立标识，不复用不改 auto_resolve 签名语义。
- **复发走新条目不重开**：自愈收口后底层故障复发由既有冷却/去重自然产生新条目；安静窗口默认 1440 分钟（覆盖跨日同刻复发节律的一整个周期，满窗才收口避免收后即重开），可配、脏值回退缺省。

## Consequences

判定证据口径单一且不随日志轮转漂移，纯函数架构延续；任何后续自动收口类机制（条件扩族、新自愈通道）受同一边界约束——触碰 disposition 台账须显式推翻本裁定。误收口风险由「复发即新条目＋冷却节流」兜底，代价仅是重新出现一条告警；以大于窗口的周期复发的故障可能被提前收口，窗口可调大。
