# ADR-057：任务进度协议——subject 编号契约 + 读侧无编号兜底链

date: 2026-09-09
status: accepted

## Context

进度可见性断链根因：侧写叠加与写侧回写两套既有机制都假设 run 产物中 TaskCreate 的 subject 内嵌 tasks.md 编号，而该假设从未被提示词保障——agent 把多条任务归并为分组级 TaskCreate 后完成集恒空，spec 正常实现但进度永远 0/N。run 产物中同时存在不依赖编号的创建序完成下标，是零成本兜底资源。

## Decision

- 契约入提示词强制段：一个 tasks.md 任务 = 一个 TaskCreate = 一次完成汇报 = 一次勾选；subject MUST 以 `Task <分组号.任务号>:` 开头；禁止把多条任务归并为一条、禁止把分组标题当任务创建；任务完成的瞬间立即更新状态，不攒批到收尾；收尾逐项勾选 tasks.md 与汇报记录一一对应。
- 读侧兜底链不依赖编号：完成编号集非空 → 精确对齐（主路径）；编号集空但创建序完成下标非空 → 按 tasks.md 文件序回退勾选前 N 项，带弱一致性门槛（创建数须达未完成项一半才启用，宁多勾不勾错）；两者皆空 → 保持跳过不误写。
- 展示侧 tasks.md 快照与 run 实时完成度并行显示，互不掩盖；run 层进度字段独立于 tasks.md 快照计算。

## Consequences

- 提示词是软约束，契约仍可能被违反——兜底保证不回「全盲态」，精确对齐依赖契约纪律与实测验收。
- 工作树不干净跳过回写的既有守卫保持；新增进度类消费方应优先依赖 run 产物字段（不依赖编号）而非 tasks.md 快照。
