# ADR-328：v2 移动双形态走断点主题单源与页内布局容器级分支

date: 2026-11-05
status: retired
Retired: 2026-11-08 v2 移动双形态架构主体已退役（2026-11-07），无取代裁定

## Context

v2 商业化界面六页需覆盖 <768px 窄屏场景，且桌面形态零回归。可选路径有二：为移动形态另建一套路由/页面族；或在既有六页组件内做双形态分支。前者复制路由表与数据接线，违背 v2 域「零新路由、零新 API」的轻量增量口径，也把例外域的并存面翻倍；断点判定若散落各页，则会与全站移动断点约定（CSS 与 JS 两轨同界 <768px，见知识 mobile-breakpoint-unification）漂移，产生两形态交叉污染。

## Decision

移动双形态收进 v2 主题单源与页组件：断点判定与移动形态工具类收进 `src/pages/v2/theme.tsx`（断点 token 与现产 useIsMobile 同界，形态判定 hook 六页统一消费，禁止散落断点魔法数）；桌面/移动两形态在页组件内按断点做布局容器级分支渲染，数据层共享，禁止拆成两套路由。移动惯例（改布局不改宽度、越界布局优先、渐进披露、触控目标）对齐仓库既有移动端约定，不另立标准。

## Consequences

后续 v2 扩页或分面实体化时，双形态是页组件内分支而不是新路由族：路由表、菜单与 API 面保持零增量，例外域并存面不随形态数翻倍。theme.tsx 成为域内断点唯一判定点，页组件出现裸断点数值即违规；分支代码收敛在布局容器级、卡片/行级组件抽子件两形态复用，防止页组件膨胀成两套实现。桌面形态以原定稿原型为基准零回归，移动形态以移动版定稿原型为 UI 真相源，冲突升级用户裁决。
