# ADR-210：code-fix 回归门通过语义分轮，定向轮只重跑失败用例集

date: 2026-10-03
status: accepted

## Context

code-fix 批回归失败后的重试轮沿用「整批 agent 重做 + 全量回归重跑」（实测约 16min/批 + 10.2min 回归），2026-09-24~09-25 窗口发生 8 次浪费约 3.4 小时；失败用例明细不落盘，重试 prompt 只拿到纯文本摘要，事后也无法区分「真缺陷」与「测试自身缺陷」。若维持全量回归门不变，定向修复的收益被回归重跑吃掉大半；但把门收窄为失败子集，意味着「合回 = 全量绿」不再成立，修复碰坏其他未重跑用例存在漏检窗口。

## Decision

- code-fix 回归门通过语义分轮：首轮为全量回归；定向重试轮的回归范围为上一轮失败用例集，定向轮子集回归通过即视为该批回归门通过，MUST NOT 再强制补跑一次全量。合回闸门（merge-tree 预演 / WIP 重叠 / spec 目录在飞）语义不变。
- 门收窄的漏检风险由两道既有机制锚定：合回后的周期回归兜底 + 失败用例明细结构化落盘供复发追溯（衔接回归问题台账复发重开通道）。后续 SPEC 消费「code-fix 回归门通过」信号时 MUST NOT 假设其蕴含全量绿。
- 修测试授权随定向轮一并放开：失败用例可以是产品缺陷也可以是测试自身缺陷，由 agent 依据用例信息判定；修测试产物行强制 `fix_scope=test` 标注，与明细落盘、台账复发重开构成防白洗三重防线。

## Consequences

- 每轮重试从约 25min 降到分钟级；代价是定向轮之间对未重跑用例的破坏不可见，靠周期回归滞后发现——这是用户已确认的权衡（整批重做同样不保证无隐性破坏）。
- 「回归门通过」由单义变为分轮义，任何把该信号当全量质量证明的下游（推送门、分面展示、台账消费）都须显式区分轮次来源。
- 子集重跑的执行载体与命令改写约束见 ADR-211。
