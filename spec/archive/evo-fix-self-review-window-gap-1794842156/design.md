## Context

夜间全仓 code-review 与每日自省挂同一 run_once 巡检节拍，检查点顺序由代码强制审查先于自省（core/admin_monitor.py:1989-1996）；审查 run 恒早于自省冻结锚点亚秒级起跑（实测三夜 51-777 毫秒）。core/self_review.py:1678-1680 以 run_id 内嵌整秒 epoch（缺省回退 mtime）调 :245 的 window_start <= dt <= window_end 归窗：起点早零点几秒即被排除，而上一窗聚合执行时该 run 尚在飞（空壳不列），两窗均不可见。已实锤三晚：2847.1 秒与 207.7 秒漏计，第三晚判据上已定。

## Goals / Non-Goals

- 目标：已终态 run 的窗口归属确定性唯一、消除亚秒起点缝隙；第 2 节 runs 统计与第 6 节停滞聚合同源生效；跨窗天然去重不重计。
- Non-Goals：不改调度节拍/检查点顺序/错峰抖动（条目建议③治标且动调度面）；不改停滞采样口径与分级阈值；不改摘要渲染契约与降级行为（rev2 已约定）。

## Decisions

- D1 归属判据改终态归窗，终态时刻取 run jsonl 文件 mtime：result 行自身无 timestamp 键；mtime 在终态行写完即定格、归档搬移（同盘 mv）不变；_run_start_ts 已有 mtime 回退先例。窗口为小时级区间，mtime 精度足够。
- D2 弃条目建议①（起点前移容差+补列条件）：其所需「上窗聚合完成时刻」历史值并不在档——self_review_state.json 逐夜覆写仅存最新一份（last_run_at/updated_at/last_run_date 三键），按①立项需新增持久化字段，复杂度高于②且收益相同。
- D3 弃条目建议③（错峰/抖动）：治标，且动调度面（admin_monitor 检查点顺序有既有语义约束），不解决判据层面的缝隙类。
- D4 在飞语义：无终态产物不列终态统计（与现状一致）；起点晚于 window_start 的在飞 run 维持「在跑」展示；起点早于锚点且仍在飞者允许一窗可见性延迟，待终态落后续窗补列——以一窗可见性延迟换永不漏计，语义即「终态统计按终态归窗」。
- D5 实现单点：改造收在 _bounded_per_run_scan 的归窗谓词处（起点取值行替换为终态 mtime），第 2 节与第 6 节共用该扫描面，不新增并行扫描路径。

## Risks / Trade-offs

- mtime 依赖文件系统时间精度：窗口为小时级、run 终态与窗口边界相隔小时量级，亚秒精度无关紧要；跨盘归档若改副本方式将破坏 mtime（现状为同盘 mv，保持即可）。
- 「在跑」一窗可见性延迟：起点早于锚点的长在飞 run 在聚合窗内不可见、次窗补列——可接受，趋势判读以终态口径为准。
- 既有窗口类测试（如 tests/test_self_review_window_snapshot.py）若锁定起点判据断言，需随 D5 同步对齐。
