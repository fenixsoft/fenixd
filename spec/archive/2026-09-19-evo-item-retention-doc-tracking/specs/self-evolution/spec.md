# self-evolution 增量规格

## ADDED Requirements

### Requirement: 条目保留与自动清理

框架 MUST 对 `.fenix/evolution/items.jsonl` 实施保留策略：仅保留「创建时间在最近 **7 天**内」的条目与「按创建时间倒序最近 **100 条**」的条目之**并集**（即两者中数量较多者），其余条目 MUST 硬删除。两个阈值 MUST 为固定常量，MUST NOT 新增配置键。

清理的删除 MUST 复用既有「删除路径」语义：记录从 `items.jsonl` 移除（不写墓碑、不留占位），草稿目录存在时一并删除（含解析后路径必须位于草稿基目录内的校验，符号链接越界拒绝删除并保持记录不动），并沿用既有的 todo.md 标记幂等回写。

保留判定的排序 MUST 以「创建时间倒序 + 条目 id 兜底」为确定性次序。条目创建时间缺失或非法（无法解析为时间）时 MUST 判为保留——MUST NOT 因年龄不可知而删除。

清理 MUST 由 daemon 周期执行（自进化检查点节拍），且 MUST NOT 因自进化分析 run 在途而跳过。逐条删除失败（如 `OSError`）MUST NOT 中断其余条目的清理，也 MUST NOT 中断 daemon 主循环；失败 MUST 计数并记录可观测日志。

清理 MUST NOT 依赖分析 run 成功落地（分析 run 失败或长期无就绪项目时，清理仍按检查点节拍执行）。

#### Scenario: 超过 7 天且落在最近 100 名之外的条目被硬删

- **WHEN** `items.jsonl` 含 120 条条目，其中 20 条创建于 30 天前、按创建时间倒序排在第 101 名之后
- **THEN** 这 20 条记录被移出 `items.jsonl`，其草稿目录（若存在）被删除，其余 100 条保留

#### Scenario: 最近 7 天条目多于 100 条时按 7 天保留

- **WHEN** 最近 7 天内有 130 条条目，另有 10 条创建于 8 天前
- **THEN** 130 条最近条目全部保留（较多数），8 天前的 10 条既不在最近 7 天内也不在最近 100 条内，被硬删

#### Scenario: 阈值内不做任何删除

- **WHEN** `items.jsonl` 含 35 条条目且全部创建于最近 7 天内
- **THEN** 不删除任何条目，`items.jsonl` 内容不变

#### Scenario: 创建时间缺失按保留处理

- **WHEN** 某条目缺 `created_at` 字段或其值无法解析为时间
- **THEN** 该条目被保留，MUST NOT 被本次清理删除

#### Scenario: 未决条目同样受保留策略约束

- **WHEN** 一条 `pending` 或 `analyzed` 条目既不在最近 7 天内也不在最近 100 条内
- **THEN** 该条目按策略被硬删（清理不设状态门，MUST NOT 因状态未决而豁免）

#### Scenario: 清理不因分析 run 在途而跳过

- **WHEN** 自进化分析 run 正在执行、检查点的派发判定会因此提前返回
- **THEN** 该检查点仍执行一次保留清理

#### Scenario: 单条删除失败不中断其余清理

- **WHEN** 某受害条目的草稿目录删除抛出 `OSError`
- **THEN** 其余受害条目仍被正常清理，该失败被计数并记录日志，daemon 主循环与自进化派发不受影响
