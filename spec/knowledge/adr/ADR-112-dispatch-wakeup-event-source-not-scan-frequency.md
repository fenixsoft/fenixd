# ADR-112：调度空隙用事件源补齐，不提频扫描

date: 2026-09-18
status: accepted

## Context

两类 SPEC 落在事件驱动与兜底扫描的空隙：依赖满足型（依赖判定只在自身被派发时求值，依赖转好是为别的 SPEC 产事件，等待者收不到）、观察项通过型（通过只记 INFO 不派发，且通过判据比声明宽松）。缩短扫描间隔是伪解——扫描本身毫秒级不是瓶颈，真正的约束是 recovery 副作用随频率成比例放大（每小时重验 9 轮的实证）。

## Decision

- 唤醒点绑在「依赖确实变好」的事实上，不绑在时间上：接受态转换检出处定向反查 dependents（遍历已读入的 spec 字典；百量级不建索引——索引失效维护成本高于收益），触发重评；零新增定时器、不改扫描间隔。
- 重评复用既有依赖满足判定（单一判据源，防「闸门说满足、唤醒说不够」双口径漂移）；唤醒后的派发必须走既有派发入口——预算 / 内容完整性 / 冻结 / 冷却 / 去重闸门与幂等自动继承，不在唤醒路径重实现一遍。
- 观察项通过判据按声明意图收紧（已进入 ready 后续态、或已有活跃派发才算恢复）；仍未恢复 → 就地重新派发，派发不成立才升级 dispatch_stalled——能自愈的不升级人工，自愈动作排在告警之前。
- 分层不动：EventBus 只识别事实，派发决策与闸门求值全留 PMEngine；异常一律捕获降级 WARNING，单条不中止整轮。

## Consequences

- 依赖唤醒最坏延迟从「一个扫描周期」降为「事件到达即醒」；新增派发次数上界 = 接受态转换数 × dependents 数，规模可控。
- 定向唤醒不经过孤儿恢复 / 状态回退分支，副作用面小于全量扫描——这是宁补事件源不提频的根本理由。
