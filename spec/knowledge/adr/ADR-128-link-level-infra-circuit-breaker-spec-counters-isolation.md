# ADR-128：链路级 infra 熔断持久化，spec 级计数器对 infra 失盲

date: 2026-09-21
status: accepted

## Context

provider 熔断器只覆盖 4xx（进程内存态、不落盘、不告警），402/429/quota/budget 类链路故障无熔断；同时 run 失败按 spec 级尝试计数器机械递增——评审链路连续 403 时，第 3 次会同时撞上尝试上限触发冻结：链路故障被误判成 spec 内容问题，且冷却期到来前 spec 已被冻结，「冷却后自动恢复」永不成立。若不清派发锚点，冷却到期后还会因锚点非空拒派，spec 永久卡在评审态。

## Decision

- 链路级熔断器按 `{链路: (连续 infra 失败数, 熔断截止)}` 建模：连续 infra 失败达阈值（默认 3）→ 冷却窗口内短路该链路的派发入口。与既有 provider 4xx 熔断互补——后者保持进程内存态，链路级熔断负责 402/429/quota/budget 类 + 持久化 + 告警；同型失败双计无害（链路计数只聚合告警，不抑制派发）。
- 熔断状态持久化落盘，daemon 重启后恢复（防重启重置熔断）；文件损坏按熔断复位 fail-open，不阻塞派发。
- infra 失败分支对 spec 级计数器失盲：不递增尝试计数、不触发冻结、清派发锚点（链路级问题不计入 spec 内容问题的预算；锚点不清则冷却后拒派）。
- 熔断触发/恢复各落一条告警：触发记录走 ESCALATION 档但不唤起 Administrator（infra 对人工无操作杠杆，唤起即烧 token 空转），恢复记录落 SIGNAL 档；新增信号类型必须登记进摄取白名单，否则记录落 store 无人摄取。
- 分类函数保持链路无关可复用；冷却到期自动恢复，恢复后首次成功清零计数，阈值与冷却时长走配置。

## Consequences

- 链路故障的爆炸半径收敛在「该链路冷却 N 分钟」，spec 状态零污染；verify/impl 链路接驳同一套分类与熔断语义。
- 冷却窗口内该链路零推进，属有意代价；由恢复后自动续跑承接。
