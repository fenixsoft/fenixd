# Why

周期全仓审查近 3 轮 2 轮死于同一收尾形态：code-review-1791997425（82.98 美元，本地 2026-10-15 04:32）与 code-review-1792170059（136.20 美元，本地 2026-10-17 04:33）均在夜间断连窗死于 ENOTFOUND/CLI Exit 1，合计实损约 219 美元。两轮死亡都发生在 evo-add-review-night-defer-snapshot-writeoff 落地的跨窗顺延守卫生效之下（10-17 01:00:59 派发按近 3 轮均值 9577.2s 判「预计结束 03:40 < 04:15 不相交」放行，实跑 12778s 低估 33%）：估计器是纯均值（core/admin_monitor.py:1988-2060），对审查时长方差与单调上行趋势（5338→9225→10893→12500→12778s）系统性滞后；同时抢救落账写下的 writeoff-pending 锚没有任何续审消费者——429 限流车道已有的 manifest 剃余重派机制只挂 429 意图，夜间断连死亡不产生该意图，下一轮周期审查将整轮全量重烧。

# What Changes

1. 跨窗估计保守化：审查派发守卫的时长估计由近 3 轮均值改为近 3 轮 max（可用样本不足取已有样本 max）。按 max(12500s) 估计，10-17 01:00 派发预计结束 04:29 落入 04:15-04:45 窗即顺延——10-17 派发实测可拦（归档在案复核）；10-15 派发的归档样本已被保留策略清理、不可复验，按样本上行趋势其当轮 max 估计预计未越窗起点，不再断言两轮均可拦，该轮残局由改动 2 的锚驱动续审兜底（不整轮重烧）。
2. 锚驱动剃余续审：周期审查派发前检测 writeoff-pending 锚，存在则复用 429 车道 remaining_manifest 剃余机制、只审未落分片对应文件；收尾由既有累计覆盖守卫判定，覆盖完整解锁核销并清锚，部分覆盖维持抢救红线。
3. 在飞穿窗防护以 1+2 组合实现：保守估计把「将穿窗」的 run 拦在派发前；极端超时仍穿窗死亡的 run 由锚驱动续审只补未落分片，不整轮重烧。不做进程级停等（分片推进在 agent 侧，框架无法可靠暂停 CLI 会话）。
