# ADR-249：定向子集证据对全量口径门禁不可见

date: 2026-10-07
status: accepted

## Context

定向子集回归（只重跑失败/错误与长耗时用例的并集）的结果覆盖单快照 `last-run.json` 后，会以 `status: "passed"` 呈现；而 full-suite 门的数据源①按「框架侧回归产物」存在性采信（读侧优先级：框架车道产物 > run 内自查 > pending），不区分产物口径。若不加区分，「子集通过」会把全量门洗成 passed——与空场景白洗、陈旧 dist verified 洗白同族的证据口径白洗通道：门以完整口径命名，证据却是缩小口径的。

## Decision

按缩小口径产生的证据，对以完整口径命名的门禁一律判本源不可见：门读侧在数据源内部先做口径判定（框架侧回归快照带 `run_scope == "issues"` → 判 `(None, "")`），fail-open 回落 run 内自查值与既有逐级回落，不抛异常、不产生 error、不新增失败终态。口径标记只在子集改写实际生效时落（回退全量的运行是真全量，不落标记，可被正常采信）；终态豁免等更高优先级语义不受不可见规则影响。

## Consequences

- 门禁呈现与单快照内容可能暂时不一致（子集 passed、门 pending）——这是设计内语义而非缺陷：口径差距必须可见，而不是被门吸收。
- 后续任何新增「子集/部分范围」产物源必须携带口径标记，并同步进各全量口径门读侧的不可见判定；读写两侧漏标任一端即重新打开白洗通道，须配对测试锁定。
- 代价是真全量证据在子集运行后的一段时间内不可见（快照被子集结果覆盖），须再跑一次全量恢复——接受，不做历史留存。
