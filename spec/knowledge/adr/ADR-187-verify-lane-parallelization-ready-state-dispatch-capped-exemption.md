# ADR-187：验证链并行化纪律——出题挂 ready 态、就绪短路复用既有校验禁双标准、槽位豁免带独立上限

date: 2026-09-28
status: accepted

## Context

验证链三阶段曾全部串行排在 implemented 之后：出题中位 36 分钟且几乎纯 LLM 生成，而实现排队占全历史 893h（37.1%）期间验证侧闲置；过队列受实现槽钳制的验证环节与实现争抢槽位。并行化要防两件事：并行产物与串行产物双标准，以及豁免车道无上限挤占网关。

## Decision

- 并行出题派发挂 ready 态进入（实现排队窗口期完成出题，implemented 时场景集必然就绪），产物仍写既有场景文件随拷回机制落主树；读 pre-impl 源码是可接受偏差（UI 结构被实现改动导致部分场景失准），兜底链 = 既有 REPLAN 回环 + 场景静态校验。
- 就绪短路必须命中既有「场景存在且指纹有效即跳过出题」分支：同一文件、同一校验，禁为并行产物新增独立校验路径（双标准即漂移源）；并行产物损坏走既有回落出题通道。
- 槽位豁免必须带独立在飞上限（独立计数器，不走 max_concurrent），防豁免车道挤占网关；豁免落点复用既有车道放行点扩展，不另造机制。维持管线内同步派发的环节不为它建独立队列条目（同模式计数仅作接口预留）。
- judge 重裁决双计数并存：轮内阈值（同 spec 同验证轮达到阈值即停派 + 人工升级 + 保持可重试）先于既有 spec 级硬上限触发，计数器随验证轮重置；低置信判定优先证据扩充（局部补证）而非整轮重裁决；快道命中即复用、不计入真实派发，命中率落读侧字段可观测。

## Consequences

- verifier 条目本身仍占实现槽（场景执行依赖 implemented 产物，跨 spec 争抢是本纪律不处理的剩余大头）；分片出题允许实现期申报 unattainable 收敛，不构成打回理由。
