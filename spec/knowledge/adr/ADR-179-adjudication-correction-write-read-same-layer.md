# ADR-179：裁决修正写读同层——修正被执行 ⇔ 下一次守卫读取能看到修正

date: 2026-09-28
status: accepted

## Context

裁决侧机械修正（typo 改写/引用软化/删除）曾固定写主树 spec 目录并以主树为提交根；守卫却按 worktree > 分支 > 主树的优先序读取。当生效声明只存在于分支对象库时，修正落主树、读取取分支——每轮守卫读回旧声明再判违约再打回，死循环 31 小时 / $44.98；恢复续做每轮都在携带旧声明的分支上重演。

## Decision

- 修正写入落点必须等于守卫实际读取的那一层，按解析 source 三态分流：worktree → 就地写 worktree 内 spec 目录并经该 worktree 的分支提交；main → 就地写主树并提交（该来源意味着本轮守卫也读主树，禁一刀切禁写——既有主树就地软化是 merge-back 死锁修复的前提）；branch（生效声明只在分支对象库、无落盘位置）→ MUST NOT 写主树就地生效，走既有缺件打回/凭据通道，并把该条裁决落审计流供跨轮核销。
- 核心不变量：修正被执行 ⇔ 下一次守卫读取能看到修正；看不到即视为修正未完成，禁记成功。
- 修正确认后以读取基准复检，不一致记 error 明细（含 source 与落点）并告警。
- 跨轮残留凭据核销：仅对 missing 类违约、命中凭据且替代路径在分支 HEAD 真实存在的条目核销（防空洞放行）；此路径不依赖本轮 judge 是否再跑，正是「重派但无从改」死循环的解药。
- 复发熔断计数必须用独立持久字段，MUST NOT 复用会被恢复续做/分支重建显式清零的重试计数（实证 31 小时在飞期间既有计数恒为 0，既有封顶形同不存在）；独立计数不随 blocked→ready 复位清零，仅修正复检通过或退出该形态时清零。
- 同族降级必须可见：续做保留判定不得以调用方显式传参为前置条件（未传时自解析项目根再尝试），worktree 已清理只剩分支时必须记录续做分支锚点，判定确实不过才降级且必落 WARNING——绝无静默降级。

## Consequences

- 写入点须全量清点（同错层的预分类/孤儿预检路径一并接线，漏接线则目标仅部分达成）；裁决写 worktree 须与实现 run 的 WIP 提交协调（写后立即提交，防被续做覆盖），占用冲突时降级打回通道。
- 存量在飞 spec 凭凭据核销脱困，无需重跑实现；复发熔断为迁移期安全网长期保留。
