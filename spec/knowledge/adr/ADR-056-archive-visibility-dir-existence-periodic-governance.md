# ADR-056：归档可见性唯一事实源 = 活跃目录存在性，低频治理挂周期计时

date: 2026-09-09
status: accepted

## Context

归档存在三条路径（界面 API / CLI skill / 手动 mv），其中 CLI skill 不写 STATE.md——任何基于 STATE 标志的归档判定必然漏标，标志与目录检测两套逻辑并存必然漂移。归档后 STATE.md 条目保留而 changes 目录消失，按条目枚举目录的代码路径会踩空。

## Decision

- 归档判定唯一事实源 = 活跃目录存在性：STATE.md 有条目且 `spec/changes/<name>/` 不存在即 archived。不写 STATE 标志，不匹配归档区具体路径形态（删除路径命名不同、手动移动命名不可控），三条归档路径天然一致。
- 归档动作在核心数据层函数级复用（与 CLI 同一移动规则与命名），dashboard 不子进程调 CLI 脚本；终态校验在 API 层做。
- 凡按 STATE.md 条目枚举 changes 目录的代码路径（调度扫描、进度读取等）必须容忍目录缺失——跳过或返回空进度，不异常；此为涉及归档语义的 SPEC 实现期强制检查项。
- 低频治理检查（终态积压超阈值自动归档）挂主循环独立周期计时任务（分钟级），不用状态转换事件埋点——转换点多、埋点易漏，与告警自动闭环同模式（见 ADR-043）；阈值配置非法值记日志回落默认，0 = 禁用。

## Consequences

- 归档可逆（目录移回即恢复），无需恢复功能；代价是列表请求每条目多一次目录 stat，百级条目无感知。
- 「读 STATE 条目前先确认目录在」成为通用容错要求；治理类低频任务默认选周期计时而非事件埋点。
