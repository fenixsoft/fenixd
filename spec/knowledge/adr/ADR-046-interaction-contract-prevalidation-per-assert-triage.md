# ADR-046：交互契约前置校验，豁免逐断言归因

date: 2026-09-07
status: accepted

## Context

页面元素渲染为可交互形态但 SPEC 未定义点击行为 → 实现未做跳转 → 场景集（由 SPEC 生成）无导航场景 → 失败场景被整体豁免为 harness 缺陷 → 带缺陷 pushed。事故暴露两端机制缺口：场景生成层对交互覆盖无把关，裁决层豁免粒度粗到整场景，单条断言的误分类足以豁免真缺陷。

## Decision

- 交互契约落在场景生成校验器（与场景冻结同型的机制性把关）：对 SPEC 页面定义中渲染为可交互形态的元素逐一要求对应交互场景或纯展示声明。可交互候选采用声明式模式识别（button/按钮组/cards 渲染循环/href·link 字段等），清单维护为常量可扩展；不做渲染树自动探测（成本高误报多）。
- 场景-元素映射记入 scenarios.json 元数据（`covers` / `declared-display`），校验器 diff 元数据与候选集；旧场景集不追溯，仅新验证轮生效。
- 裁决输出结构化到断言粒度：failed 场景必附 `assertion_triage` 数组（断言/分类/证据），由确定性校验器强制；豁免判据从「场景级分类」收紧为「全断言非 product-bug 才豁免」。
- 断言级豁免清单由报告合成器渲染，历史报告缺字段时小节缺省（向后兼容）；实现任务书模板加契约条款——发现待裁决交互写入 run-result findings 申报即合规，收工守卫不因此拦截。

## Consequences

- 每条被豁免的断言都有分类与证据，豁免可复核；代价是裁决输出 token 增量约 10-15%。
- 声明式候选清单会漏非典型交互形态，靠清单迭代收敛；契约与豁免两侧都由确定性校验器把关，与裁决信任模型（只信可校验输出，见 ADR-042）一致。
