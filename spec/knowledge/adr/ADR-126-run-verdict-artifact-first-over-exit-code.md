# ADR-126：run 判定产物优先——进程退出码不等于裁决

date: 2026-09-21
status: accepted

## Context

run 的进程退出码与业务成败是两回事。实证事故：结果文件已于 14:56:22 落盘 `approved`，进程 14:56:39 才以 exit code 1 退出；消费侧只读进程 success 旗标、从不读取已落盘产物，按失败重试至上限后冻结，整轮成本作废。只要「产物已落、进程后死」这一窗口存在，任何按退出码判失败的路径都会白烧重试。

## Decision

- 进程退出码不是 run 裁决；run 结果产物（`.fenix-run-result.json`）优先。失败分支处理前，先做产物有效性判定：JSON 可解析、`status` 在该车道白名单内、产物 mtime ≥ 派发锚点时刻、与派发前快照的 spec 一致性通过。
- 判定满足 → 记 warning（携带 exit code 失败原因供复盘）并直接消费产物，不重试、不重派。
- 判定不满足 → 走既有失败处理：`status=failed`（agent 自判内容失败）不算合法产物；快照/spec 戳校验失败视为产物不可信——保守方向宁可重试不可错消费。
- 消费侧幂等由既有状态推进保证；产物优先分支不得在消费后再次触发重派。

## Consequences

- 「产物已落盘但进程异常退出」从整轮白烧降为一次 warning；消费不绕过下游硬门对账（捞回只解决文件没落盘，不解决内容不实）。
- 保守分支存在少量冗余重试，属可接受代价；进程级失败的 infra/content 分类与链路级熔断由后续裁决承接（见 ADR-128）。
