# ADR-110：确定性验证环境错误在场景执行前 fail-fast 短路

date: 2026-09-18
status: accepted

## Context

契约缺失、入口不存在、依赖缺件等确定性环境错误原样要到场景执行甚至整轮结束才暴露——实证首轮 14 场景空转（6 过 7 环境伪失败）→ judge 误拒 → 原地重新实现，单 spec $39。可达性判定与自愈本已在场景前完成，结果却被调用点丢弃后照跑整轮。

## Decision

- 验证管线次序固定：依赖供给 → prepare 构建 → 入口存在性预检 → spawn → 就绪探活。预检解析器取最小确定性：只拦「100% 是错误」的形态（node 族运行时 + 单脚本文件不存在），复合命令 / 未知运行时一律放行走既有探活兜底——零误杀优先，漏检交给探活与自证。
- 应用不可达（reachable=False 且非 user_blocked）在本轮 fail-fast：短路点在场景重读之前，场景执行数为 0；统一走既有 env-blocked 升级通道（blocked + 自动呼叫 admin），不按子源分流、不新增信号类型——不可达备注自含原因与启动日志尾部证据。
- fail-fast 态不产验证报告：确定性环境错误在场景执行前终结，与消费期轻量自证短路同一语义；blocked 不经 verified 判定链无洗白面，时间轴由读侧按 STATE 重建。
- 消费期契约自证走 mtime 快照门：契约未变零开销，admin 修正后（mtime 变化）下轮自动重证，无失效指令；兜底 spawn 的启动日志落盘、探活最终失败时附尾部证据随升级送达 admin。
- user_blocked 守卫显式保留：「需用户参与」的不可达不得被短路自动判 blocked（当前恒 False 纯防御，为未来语义留位）。

## Consequences

- 确定性环境错误的代价从「整轮空转 + 判定误拒 + 原地重实现」收敛为「一次升级 blocked」；环境反复不可达按既有阈值快速冻结转人工，是期望行为。
- 预检零误杀的代价是漏检面存在（复合命令等），由探活、轻量自证与 admin 证据链兜底。
