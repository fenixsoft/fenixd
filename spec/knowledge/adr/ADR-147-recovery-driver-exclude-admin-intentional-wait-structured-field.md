# ADR-147：恢复判定只认真驱动，有意等待须结构化表达给探测器

date: 2026-09-23
status: accepted

## Context

testing 态恢复判定以「近期有 run 写活动」为驱动证据之一，admin 处置 run 的产物使被处置 spec 恒判「有驱动」，恢复链路在整个处置期间被跳过。同时预算耗尽后的重验没有显式日程，孤儿探测器按静默阈值成条唤起 admin 长跑接管，形成「无日程 → 探测器接管」的错位。

## Decision

- admin 处置 run 不构成被处置 spec 的驱动证据：驱动判定的 run 前缀集合排除 admin 前缀。选排除而非加「admin 占用超时」——这是语义修正，长跑 admin 本身正常，加超时会引入新阈值配置面且 admin 停止写盘后仍挡判定；同源实现多处 MUST 共用同一排除逻辑防漂移。
- 判定点保持纯判定（无副作用、无引擎依赖），并发守卫放在派发点与唤起点：派发 verifier 前、唤起 Administrator 前各自查「该 spec 是否有在飞 admin run」，有则跳过（信号仍按既有节流沉淀落库）。在飞判定取「存储层 pending 记录」与「进程表存活 run」两真相并集（前者含 pending 残骸、后者仅存活进程，互补），异常 fail-open 放行并记 WARNING。
- 有意等待必须双落：持久结构化字段（退避截止时刻）表达给探测器（孤儿探测窗口内静默），进程内定时器承担准点触发；MUST NOT 以进程内定时器为唯一机制（daemon 重启即丢失），到期兜底由周期扫描承接，最坏延迟为一个扫描周期。
- 排程与周期兜底可能同时到期：幂等由既有队列按 (spec, agent_type) 去重与退避门承担，MUST NOT 新增第二套派发判据或第二套「在飞」定义。
- 耗尽类计数为生命周期累计语义：清零点只在终态落定（verified）与人工解冻，admin 复位/中间转换 MUST NOT 清零——防每轮复位重置计数形成无限循环敞口。

## Consequences

- admin 处置期间恢复判定如实反映「无驱动但有人管」：verifier 不与 admin 并发写验证产物，第二个 Administrator run 被唤起侧守卫抑制；预算耗尽的 spec 获得显式、可观测（error 内嵌下次重验时刻）、有界的重验机会，连续耗尽才升级人工。
