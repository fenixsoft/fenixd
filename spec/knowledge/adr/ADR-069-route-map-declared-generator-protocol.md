# ADR-069：框架不解析被测应用源码，路由地图由项目声明生成器协议接入

date: 2026-09-11
status: accepted

## Context

planner 出题需要源码考古，大轮次 × 网关长尾 = 长耗时零产出。注入路由地图能砍掉大部分考古，但框架若自行解析被测项目源码就破坏了框架通用性——框架不可能内建对所有技术栈的理解。

## Decision

- **框架不解析被测应用源码**；项目侧以**声明式生成器协议**提供路由地图：固定路径 `bin/gen-route-map.py`、框架以 impl worktree 为 cwd 单参（worktree 根）调用、stdout 输出人类可读 Markdown（含 `文件:行号` 出处）、超时/非零退出 = 失败 fail-open。框架不解释生成器内部实现。
- **地图来源 = impl worktree**（非主树：spec 新增路由只在 impl 分支，主树地图会瞎）；**复用键 = worktree HEAD**（未变跳过、变更重生成，与 impl worktree 复用同键）；生成物 worktree 私有，随清理消亡、并行互不污染。
- 无生成器项目回退主树静态地图，再无则维持现状——存量项目零迁移。
- **覆盖缺口防线在措辞不在解析**：注入 prompt 钉死「已知入口索引、非穷尽清单，未覆盖入口仍须自行源码取证」，不依赖地图完整性假设。

## Consequences

- 生成器质量由项目自担；错误条目可能浪费 planner 数轮抽查——远小于全量考古，可接受。
- 框架只提供协议、超时与回退，不为任何技术栈内建解析逻辑。
