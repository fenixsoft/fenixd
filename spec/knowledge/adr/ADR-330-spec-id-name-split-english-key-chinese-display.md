# ADR-330：SPEC 英文名与中文标题语义分离（id 唯一寻址、name 纯展示）

date: 2026-11-06
status: accepted

## Context

SPEC 的唯一人类可读标识长期是 kebab-case 英文名，它在全框架内同时承担唯一寻址键（目录名、STATE.md、信号文件、CLI/API 写入路径、fix-* 树构造、排序）与展示文本两个职责；中英文混排工作语境下列表页辨识成本高。引入中文 display name 存在走向选择：让中文名参与寻址/匹配（需迁移一切既有键，破坏面不可控），或严格展示层化（键域不动，标题缺失只影响展示）。

## Decision

英文名 = id：一切输入、寻址、排序、信号与状态机继续以 kebab-case 英文名为唯一键，永久不迁移。中文标题 = name：纯展示字段，不进入任何寻址路径或匹配逻辑；参与匹配的唯一例外是列表名称关键字过滤（与英文名 OR 命中）。存储单源收在 `.spec.yaml` 的 `title` 字段（与 `mode` 同位：git 交付物、随归档迁移、无 STATE.md 运行时写放大），读侧单点容错缺省 None（字段缺失 / 文件缺失 / 解析失败最坏退化 = 展示缺席，零寻址影响）。生成只落在 LLM 起草的立项通道（fenix-new + evolution 双通道同步约束 5-25 字纪律），纯程序化生成通道（code-fix）不产生标题、缺省合法。

## Consequences

新增展示面可直接消费 `title` 而无须触碰键域；标题质量问题被隔离在展示层，不扩散为寻址事故。代价是两条立项通道的起草契约必须同步维持标题纪律（遗漏即该 SPEC 无标题、列表退回单行形态），且任何未来消费方不得把 title 当匹配键或排序键——放宽 id/name 分离须显式 supersede 本裁定。
