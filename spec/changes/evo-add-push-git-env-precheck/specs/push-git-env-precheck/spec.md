# 能力规格：推送步骤无远程环境预检短路

## 概述

规范 pm_engine 发布推送与 done 态续推通道在 git 环境不满足时的行为：预检、短路留痕、审批门、配置分级。

## 行为规格

1. 预检：执行 git push 前必须确认存在 remote 与目标分支；任一缺失时推送不执行。
2. 短路留痕：预检不通过时推送结果标记为 N/A 并写入 entry 专用持久字段（push=N/A + 原因，不走 error 字段），不进入退避重试、不计入重试计数；续推通道读该字段即终局跳过。
3. 审批门：approve_mode 生效值为 manual（含配置缺省回退 manual 的未显式配置项目）且该 done spec 无推送记账（未经人工批准）时，done 态续推通道不得自动补投推送；有推送记账（人工已批准推送的退避重试）的 manual spec 不受此门约束，续推语义与既有 push-retry-recovery 能力兼容；显式配置 auto 的项目行为不变。
4. 分支解析：推送目标分支优先取配置（新键或既有项目配置），缺省按仓库当前分支探测，不再硬编码 main。
5. 配置分级（回归锁定既有行为，无新实现）：pm.push.retry_backoff_seconds 缺失→静默（DEBUG 级）用默认 [300, 900]；存在但形式非法（非 list/长度不足/负值/零值/布尔）→WARNING 回退默认；元素级非法（int 转换失败）→静默回退。
6. 短路幂等：N/A 结果稳定可重复，daemon 重启后对同一 done spec 不再产生新的失败记录。

## 验收

- 无 remote 仓库推送零执行、零 error 写入、零退避计账、重启后零重投递。
- manual+零记账（未经人工批准）的 done spec 不被续推通道自动补投；manual+有记账（已批准推送的退避重试）照常续推。
- 非 main 分支仓库推送目标正确。
- 缺键项目静默（DEBUG 级）用默认退避，非法键仍 WARNING（既有分级行为回归锁定）。
