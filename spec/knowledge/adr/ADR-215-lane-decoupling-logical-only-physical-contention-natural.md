# ADR-215：车道解耦只解除逻辑调度耦合，物理冲突点保持自然串行

date: 2026-10-03
status: accepted

## Context

code-fix 批派发曾被「周期审查 run 在飞」绑死：审查 run 停滞期间 code-fix 90 分钟无派发，只能人工取消 + 重启恢复。取证定案车道间应有的关系——逻辑调度层互斥没有资源依据，而两条车道真正共用的资源（回归主机级套件锁、worktree 主机资源）存在物理竞争。

## Decision

车道间解耦的边界 = 只删除逻辑调度层的否决/等待条件（「他车道在飞则我不派发/我等他收尾」类门控）。物理资源冲突点不假装解耦：由既有锁（全量回归主机级套件锁等）自然串行，逻辑调度层 MUST NOT 为同一冲突再叠一层互斥或等待。车道自驱动推进语义对所有批收尾路径成立（含延迟批合回路径），恢复不依赖其它车道的事件或周期扫描兜底。

## Consequences

- 单条车道停滞不再连坐其它车道吞吐；停滞自身由看门狗收走（ADR-214）。
- 物理冲突点仍会串行等待（如回归锁排队），这是预期行为不是缺陷；排查吞吐问题时先查锁占用者，再查调度门控。
- 后续车道解耦类 SPEC 的验收口径 = 「删逻辑门控」，禁以新增跨车道互斥来「治理」资源冲突。
