# ADR-007：多项目发现 = 显式注册 + 目录扫描兜底

date: 2026-09-02
status: accepted

## Context

跨项目 Dashboard 需要发现机器上的全部 fenixd 项目。每项目独立 daemon（独立 STATE.md、配置与 tmux session）是刻意的隔离设计，监控层不做聚合调度。发现机制必须兼顾「手工注册的精确性」与「新项目零配置可见性」，且项目识别判据须允许配置完全继承用户级的项目。

## Decision

- 项目注册表 = 显式 `projects` 列表 + `scan_dirs` 目录扫描的合并结果；显式配置优先于扫描。
- `scan_dirs` 未配置时回退为用户主目录（`~`）一级子目录扫描；扫描判定为仅要求目录内存在 `STATE.md` 即识别为 fenixd 项目（不要求项目级配置文件存在，配置可完全继承用户级）。
- 项目识别判据的最终口径是单文件 `STATE.md`；更早的双文件（`STATE.md` + `.fenix/config.yaml`）判定已被此口径取代。
- 已注册项目可显式移除；仅被扫描发现的项目无法移除（不在配置中，扫描天然恢复），属「扫描为主」定位的既定语义。
- 扫描与发现结果可缓存（秒级 TTL），识别判定基于文件存在性，开销可忽略。

## Consequences

- 新 clone / 新初始化的项目无需注册即可出现在监控中。
- 判据放宽为单文件后，理论上存在把恰好含 `STATE.md` 的非 fenixd 目录误识别的可能——接受此权衡，显式注册仍可精确控制监控面。
- 每项目独立 daemon 的隔离架构不因监控聚合而改变：Dashboard 只读汇聚，不做单 daemon 聚合调度。
