# ADR-140：交付物声明权威源在实现分支，读写同位并以派发基线快照防收缩

date: 2026-09-23
status: accepted

## Context

交付物声明在规划期写入主树、实现期只应改 worktree/分支内那份；消费方各自硬编码直读主树，形成「声明权威源」与「声明改写权限」的错层：上游重构删除声明路径后，主树声明陈旧且永不可满足，守卫每轮判缺件打回、实现方已无可新做之事，原地空转至 blocked。而放开读分支又引入被守卫者自证张力——删声明行即可绕门。

## Decision

- 声明读取基准 = 实现期真实在测的那份：统一解析入口按 worktree 内文件 > 分支内容 > 主树文件优先序取「生效声明」，全部消费方（守卫/预分类/lint/终审/提示词组装/快照）改经此入口，禁止各自硬编码直读主树。
- 声明改写基准 = 同一份生效声明（读写同位）：裁决改写写 worktree 内并 MUST 在 worktree 内提交到实现分支（写盘即提交），MUST NOT 用主树 commit（不会落到实现分支）；主树对齐由 merge-back 搬运提交自然完成，不再单独写主树声明。
- 收缩防护以派发时可信基线快照为独立参照系：派发时把主树声明集合快照落到实现 Agent 路径不可触及的位置；生效声明中无声剔除、且实现分支 HEAD 也不满足原有 kind 要求、且无重定位/软化凭据 → 判收缩违规不放行。「声明只可增不可减（除非有凭据的替换/软化）」机械化。
- 陈旧声明走确定性重定位而非缺件打回：信号只认存在性（modify 条目在基线树不存在；new 不参与——其基线期望本就是「不存在」，无信号量）；凭据三要素齐备（旧路径基线不存在 + 替代路径在实现分支 HEAD 存在 + 来源标注）方机械改写，任一缺失或多命中/零命中转 LLM 终审或人工，禁「哪个新文件对应旧路径」的语义推断。

## Consequences

- 声明权威源唯一（分支），主树只是基线快照来源与 merge-back 落点，不做双向合并；上游重构不再诱发守卫死循环。
- 收缩违规条目 MUST NOT 静默放行亦 MUST NOT 无界重派，与缺件同源入裁决流水线；基线缺失时降级保守（不做收缩判定）并审计留痕。
