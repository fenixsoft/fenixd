# ADR-174：STATE 读改写必须整体锁内原子——禁锁外快照整体回写，写入必留痕，空闲判定须复核全部车道在飞

date: 2026-09-28
status: accepted

## Context

STATE.md 的 update_spec 曾在锁外读全量快照、改一处、整体写回（写时才加锁）：daemon 多 worker 线程与 dashboard 独立进程并发时，后写者用陈旧快照覆盖先写者。2026-09-21 实证两形：评审 run 锚点被旧快照回退为 null，评审结果文件已合法落盘却被消费函数静默早退，spec 永停 reviewing；冻结写入的 error（解冻目标解析唯一来源）被清 null，全库 277 条 spec 的 error 全为 null。同日二次事故：自愈空闲判定只读单一活跃计数器，而评审 run 从不计入该计数器——在飞评审 run 被判空闲，陈旧自愈写入重启请求杀掉在跑 run。

## Decision

- STATE.md 的一切 read-modify-write（条目更新/增删/计数器）必须整体收进同一把跨进程文件锁内：锁内读、锁内改、锁内调内部落盘原语（禁锁内再调外层写入口——同进程对同一文件重复 flock 自阻塞）。以既有「锁内读改写+回读校验」范式为准，全库写路径同源收敛。
- 写入必留痕：StateMachine 构造必须注入真实 logger，禁空实现兜底——静默来源正是无 logger 构造点，跨进程丢失更新与无日志两个特征同源；读侧构造点逐一核对，禁只改一处便宣称留痕达成。
- 注释声明的不变式与实现不符必须同步订正（如「并发写者不能复活条目」在锁外快照回写下不成立）。
- 自愈/空闲判定完备性：空闲谓词 MUST NOT 只读单一活跃计数器——凡存在不计入该计数器的车道（评审车道显式不增减），必须对未收口在飞 run 逐个经既有在飞权威判据复核（属主登记 → 进程表 → 流兜底）；进程表判据是「停滞但仍存活」run 的成立依据，禁流文件新鲜度单独作在飞依据（停滞 run 的流本就不增长）。确已死亡/收口的 run 不得永久占位（既有 stale 判定天然不占位），禁引入新的永真条件。
- 每 tick 复核的代价以「候选收窄 + 命中短路 + 可选短 TTL 缓存」约束，缓存 TTL 显著小于空闲确认窗。

## Consequences

- 跨进程锁粒度变粗可接受（单进程内写入本已串行、dashboard 写频低）；自愈不再误杀在飞 run，停滞识别仍由活性监督（ADR-025）承担——空闲判定与停滞判定语义有意分离。
