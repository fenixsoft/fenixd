# ADR-195：冻结回置噪音治理走「入口 frozen 复核 + 升级指纹冷却」双腿防御

date: 2026-09-29
status: accepted

## Context

外部整文件重置 STATE（夹具复位、人工编辑）会把冻结/已交付 spec 打回 ready，且可能连带抹掉 frozen 字段，日志无法区分「frozen 残留」与「frozen 被抹」。此后恢复链（60 秒级精触发）与派发链（重启空快照整批回放 spec_ready）反复重放「就绪→派发→闸门拦截→冻结」，闸门 ERROR 直达 daemon_errors 升级条件点燃 Administrator 召唤——2026-09-22 实证：单日 9 轮重放、18 条闸门 ERROR、3 笔 admin-global 召唤（其一 45 轮后被停机截断）。任何单一断点都封不全：只做入口复核挡不住 frozen 字段被整文件重置抹掉的形态；只做升级降敏则拦截流程仍在空转烧闸门。

## Decision

- 双腿并存、缺一不可：
  - **入口复核腿**：恢复入口（`_recover_ready` 及其白名单入口）与派发准备（`_on_spec_ready` 守卫链、派发失败重试路径）在清 error/重派/重试之前重读 STATE 条目 `frozen`，为 True 即跳过并记 INFO、零 STATE 写入——断「部分回置」腿（frozen 字段仍在，直接不进派发）。
  - **升级冷却腿**：daemon_errors 升级路径对「重启后首扫回放的已知指纹」实施指纹级冷却（30 分钟模块常量窗内不计满阈值、不召唤，窗后复现或全新指纹照常升级），同轮孪生/成对指纹合并为一条召唤信号——兜「整文件重置」腿（frozen 被抹、入口复核放行，闸门照常拦截但噪音不再升级成召唤）。
- 两腿职责正交、互不替代：后续 SPEC 不得以「已有冷却兜底」为由移除入口复核，也不得以「入口已复核」为由移除冷却；任何新出现的回放/恢复入口必须同口径接入 frozen 复核。
- 已知指纹的跨重启对账依赖信号 description 的「指纹 <前 8 位>」稳定文案（store 无结构化指纹字段）；冷却仅约束重启后首扫窗口，不以永久静默为代价。

## Consequences

- 冻结 spec 的人工重派必须先解冻（人工 kick 走同一派发入口被 INFO 跳过，跳过原因操作者可见）。
- 冷却窗可能延迟一个「重启后立即复现的旧指纹真故障」的升级——有界：窗满即照常升级，INFO 留痕可溯，告警记录全程可见。
- 修改 daemon_errors 信号 description 的指纹文案格式会破坏跨重启已知指纹对账（冷却退化为每次重启后多召唤一次）；若未来为 store 增补结构化指纹字段，须同步替换对账路径。
