# ADR-263：主树活交互会话归因——只读探测、相关性信号门、采信回退全局单键

date: 2026-10-09
status: accepted

## Context

`identify_wip_occupant` 的在飞车道归因对主树直改形态结构性零命中：活交互会话在主树内直改、待人工提交的成果被散件盘点判为无主，宽限耗尽即派 major 告警并触发 admin 代查（实证：单日 7 连发、累计约 51 分钟 admin 车道，其中确认为盲区误报）。补「主树活交互会话」探测有两个结构性风险：一是把「无主滞留」误判成「有人在做」——若仅凭存在活跃会话即归因，任何无主散件（含真实滞留）都会被活跃会话吞掉，盘点与升级链路整体失明；二是归因语义变化若只落在盘点侧消费者，defer 侧仍按无主升级，两侧告警口径分裂，且「盘点侧可回退、defer 侧无开关」的不对称使配置回退失去全局语义。

## Decision

- 探测只读 fail-open：会话探测仅用只读信号（git config/log、交互会话 transcript 尾读），MUST NOT 为归因写入主树；零命中、源缺失、任何异常一律回「无主」现状，行为与无探测时逐位一致；保持纯机械、不引入 LLM 推导。
- 相关性信号门：任一会话探测源构成命中 MUST 含散件与会话的相关性信号（散件路径×最近提交触碰集路径交，或 transcript 尾部路径提及）＋身份/时间窗/活跃窗判据；仅「存在活跃交互会话」MUST NOT 单独构成归因命中。
- 采信回退全局单键：会话归因的采信由 `admin.maintree_session_attribution_action`（info|keep，缺省 info）单键统一约束，盘点侧降级与 code-fix defer 侧采信共用同一读取器，禁单侧可回退的不对称；配置非法值守卫回退 keep（保守方向：配置事故 MUST NOT 静默吞 major）；降级留痕走盘点结构化返回值与既有日志通道，MUST NOT 新增 AdminStore signal_type（免三表登记缺口）。

## Consequences

- 主树活交互会话直改散件可归因到会话线索，误报代查税下降；真实滞留被活跃会话降级掩盖的残余风险由 info 留痕完整证据链与 keep 回退开关兜底，默认值待观察窗口后再调。
- 后续任何新增归因探测源一律受相关性门与只读约束；新增归因衍生的消费侧行为必须挂同一回退键，或以显式新裁定 supersede 本条。
- 会话归因 holders 无 run_ids，事件驱动重试在其上自然缺席，相关消费者由既有周期轮询兜底——归因形态扩展不改变各消费者的等待与升级骨架。
