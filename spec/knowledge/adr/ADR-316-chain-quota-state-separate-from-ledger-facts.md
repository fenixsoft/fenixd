# ADR-316：处置链自主处置治理走配额制，计数是状态不是台账事实

date: 2026-11-03
status: accepted

## Context

同签名「只自主处置一次」的永久跳过纪律（D6/`_dispositioned`/`_ledger_sigs`）在长期运行下过紧：一次性环境问题处置后同根因复发直接上升人工，而自动化本可再试；同时计数若混入 arbiter 台账，会让只增的事实流承担可变状态职责，回放与审计语义被破坏。

## Decision

自主处置治理以配额制承载：Admin 尝试配额 2 次/签名（run 崩溃/超时计一次，超范围转单不计失败）、Arbiter 复现配额 2 次/签名（第 3 次复现上升人工）；复位双通道——签名连续 7 天无复现清零，或该 spec 状态发生迁移清零；dead-man/停机类基础设施死亡签名维持永久单次、不适用复位。

配额计数是状态不是台账事实：独立 gitignored 状态文件 `.fenix/escalation_chain_state.json` 按签名记数，不入 arbiter ledger；主树运行时写入仅 daemon 执行。签名键复用 `arbiter_failure_signature` 单源并扩展主体键提取——spec=null 信号从 payload 取主体（如蒸馏欠账归档名、triage 场景集指纹），提取不到退化类型级并在台账标注粒度。

后续链上新增计数类机制沿用同一状态文件与签名键单源；把计数写进台账或另立签名实现的，须显式 supersede 本裁定。

## Consequences

台账保持只增事实流（可审计回放），状态文件可清零可重置；状态文件丢失等于配额重新计数（宁可多处置一次，不误封自动化）。签名粒度依赖主体键提取质量，提取失败退化为类型级会放大配额消耗，须台账标注粒度提示人工解读。
