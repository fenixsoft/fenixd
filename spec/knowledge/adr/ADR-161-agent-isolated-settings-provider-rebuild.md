# ADR-161：隔离运行环境按目标 provider 完整重建，存量隔离目录须版本化失效

date: 2026-09-25
status: accepted

## Context

车道隔离清空宿主模型映射是对的，但只清不建使子代理 tier 解析回落宿主进程 env 的官方模型名，直连 provider 无此模型、子代理全数 404 并被隐性串行化。隔离 settings.json 已存在时构建函数按 marker 直接跳过重建——只改构建逻辑对存量隔离目录不生效。

## Decision

- 隔离配置 MUST 按目标 provider 完整重建：清宿主映射的同时写入按该 provider 重算的新映射，子代理模型与全部 tier 缺省映射到 provider 自身可用模型（配置键优先），禁任何 tier 解析回落宿主 env。
- 存量隔离目录 MUST 版本标记+内容不匹配原子重写（沿用 tempfile+os.replace 手法），或显式登记人工清理处方并落提示；测试必须覆盖「已存在旧 settings 时新映射仍生效」，禁只覆盖首次创建路径。
- 同语义配置键禁双活：死键（全库无读点）收编复用或明示边界，禁留下两个都能被用户读作同一语义的活配置键。
- 子代理启动失败 MUST 在 run 转录落显式 WARNING/告警事件，禁静默吞成任务失败通知。

## Consequences

子代理并行原语在任意直连 provider 上可用；隔离目录内容与代码版本的一致性可机械判定；配置键语义单一。
