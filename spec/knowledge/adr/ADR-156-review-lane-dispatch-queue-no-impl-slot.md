# ADR-156：评审并入派发队列同构执行，不占实现槽位不进活动优先级集合

date: 2026-09-24
status: accepted

## Context

晋升门评审曾是唯一仍在调用栈上同步执行的 agent run：分钟级执行阻塞调用方线程，daemon 启动路径上评审恢复未完成则主循环进不去，全部文件信号消费者停摆。若评审占用实现并发槽位，「先审后跑」退化为「审等实现跑完」，晋升门与实现互等死锁。

## Decision

- 评审派发与实现同构走派发队列（入队 → worker 分支执行），禁新建第三套 worker 池、禁复用 admin 执行池（该池已承载多类分钟级 run，再加评审互相饿死）。
- 评审条目不占 `max_concurrent`、不写活动优先级集合：max_concurrent 语义是实现车道槽位，优先级活动集合会影响他人档位判定。槽位闸门的扫描前早退 MUST 为「队列存在合法评审条目」放行，且只放行评审条目、禁顺带放行实现条目。
- 独立在飞登记集合覆盖「条目出队→锚点落盘」窗口（此间进程表与流文件均判否，会落陈旧分支诱导清锚点）；单飞守卫=在飞集合 ∪ 锚点非空双判据，生命周期至收口（清锚点+worker finally）。在飞登记的释放时点 MUST NOT 晚于锚点落盘，否则同线程续 attempt 会被自己的在飞登记拒死。
- 在飞判据取「在飞结论」：仅「陈旧锚点」结论允许清锚点后续派，禁按「锚点非空」直接自清。
- 收口链（锚点→快照→执行→机械收口）保持同调用栈：attempt 启动时间戳的新鲜度校验基准产生于同栈局部，拆栈即失去基准；worker 层异常与链内异常的收口必须显式分层，「异常被捕获」不等于「状态已收口」。

## Consequences

主循环不再被评审阻塞，启动后数秒可响应；评审与实现无槽位互等；同 spec 评审并发派发窗口闭合且无自锁。
