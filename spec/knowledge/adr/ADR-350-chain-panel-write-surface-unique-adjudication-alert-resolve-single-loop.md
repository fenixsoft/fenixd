# ADR-350：处置链视图写面唯一化，人工裁决收敛 alert-resolve 单闭环

date: 2026-11-11
status: accepted

## Context

处置链视图由纯只读观测面扩展出人工裁决能力（人工队列内嵌裁决）。链视图区块多（统计行/链在办/签名配额/上升件全量），若各区块各自开裁决写入口，会形成多套裁决真相、多处执行面难以审计，且上升件全量列表的浏览场景极易误触执行。「视图只读」的旧纪律与「人工裁决就地可执行」的新诉求必须给出单一边界。

## Decision

处置链视图唯一写面 = 人工队列内嵌裁决面板：复用既有告警裁决交互（choices 下拉 + 处置依据 + 执行/destructive Popconfirm + 标记已处理）与 alert-resolve 闭环端点，不建第二套裁决真相；执行成功后刷新队列。视图其余面恒只读——上升件全量列表与详情抽屉中裁决选项仅只读预览、无执行入口。告警记录页签保留为人工裁决第二入口。后续在链视图新增任何写能力必须落入人工队列裁决面板通道，另开写面须显式新裁定。

## Consequences

- 视图其余区块无法就地执行裁决，处置动作经人工队列或告警记录页签完成；「视图只读」的直觉被分层只读语义替代，评审按「唯一写面」边界核验。
- 裁决写路径审计单点化：留痕沿用 alert-resolve 既有闭环台账，不产生新台账面。
- 人工队列空时整卡隐藏，此时链视图回到纯只读形态——写面的存在与否由待人工件驱动，属设计内行为。
