# ADR-133：外部信号致死闭集归因与冷却通道隔离

date: 2026-09-22
status: accepted

## Context

Exit 143/-9 类信号死法无来源记录、无熔断，一律走 provider 瞬断通道空转重试；产物硬门失败也被记入全局瞬断指纹（信号指纹污染）。归因若不先排除框架自身终止，supervision 超时强杀与 cancel 会因 returncode=-9 被误标为外部 kill，框架自己冷却自己的链路。全局瞬断熔断的爆炸半径是冻结全项目新派发，不能作为单 spec 信号死法的计数通道。

## Decision

- **死亡来源归因是闭集、按序短路**：admin cancel → supervision 超时/轮次上限强杀（错误文本已自带归因，明确排除在信号通道外）→ daemon 关停（shutting_down 旗标或产物 interrupted 标记，沿用既有守卫）→ 剩余才是外部/未知信号致死，打 `[signal-kill: …]` 标签进入信号计数通道。归因只由可实测的信源推导；环境不具判别力时如实标 `unknown` 并携带 returncode，禁止以猜测断言具体发出者。
- **信号死法冷却按 spec 维度计数**（同 spec 连续达阈值即冷却）：冷却只跳过该 spec 的重派（复用秒挂冷却「跳过派发、不耗预算、不起进程」语义），MUST NOT 写全局瞬断指纹/熔断。与秒挂冷却同事件双记时只允许累加、取更晚的冷却截止，不互相覆盖。触发与恢复各落一条告警，节流沿用既有窗口。
- **产物硬门失败与瞬断指纹通道隔离**：任务完成度类失败（任务未勾/计数不一致）不带瞬断标签、不记指纹，走既有降级语义与 attempt 层重试；结构类失败（结果文件缺失/非法）保留原地退避重试与瞬断标签（真实恢复需求），但同样不记全局瞬断指纹。

## Consequences

- 信号死法可追溯（错误文本/日志/告警 evidence 带来源标签）、有界（冷却）、自动恢复（到期解除，成功清零）；全局瞬断熔断保留给 provider 链路级抖动专用。
- daemon 硬死场景 runner 线程随之消失、天然不产生误标，遗留 run 终态由读侧清扫承接；归因闭集新增信源时必须按短路顺序插入，不得旁路。
