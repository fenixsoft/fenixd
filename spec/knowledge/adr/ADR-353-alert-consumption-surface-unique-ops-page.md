# ADR-353：告警消费面唯一收敛运维页，概览页回归纯数据概览

date: 2026-11-12
status: accepted

## Context

告警的主消费面曾是概览页横幅：裁决类与知情类混排展示、内嵌裁决闭环、独占「清理所有事件」入口，并由概览页专属 SSE 告警管线供数。这与「概览页=跨项目纯数据概览」的页面定位冲突，也使告警可见性绑定在概览页挂载上。用户定调：告警归属运维域，概览页回归纯概览。

## Decision

告警展示唯一面=运维页「告警记录」页签 + 侧栏运维菜单红点数字徽标（计数=未处理且携带非空 choices 的可裁决告警，知情类/已处理/已失效不计）；概览页不渲染任何告警横幅、告警列表、裁决控件或清理入口，不为告警维护专属数据管线；「清理所有事件」为全系统唯一全局清理入口，收敛在告警记录页签（桌面操作栏与移动端工具行两形态）；裁决闭环保留于 spec 详情页告警区、运维页告警记录移动端行、指挥中心收件箱三面，运维页桌面列表行保持无裁决控件现状。任何后续界面轨道（含重设计类 SPEC）不得在概览页或其它新界面重立告警横幅/告警列表/清理入口；另立告警展示面或迁移清理入口须显式新裁定。

## Consequences

- 告警第一可见性从「打开概览页」改为「侧栏徽标常驻」，知情类告警不再占用全局注意力（仅进告警记录页签）。
- 桌面可裁决入口收窄为 spec 详情页与指挥中心收件箱两处；运维页桌面行不补裁决控件是有意取舍，补齐属独立增量。
- 徽标口径（choices 非空）与告警页签列表口径（全部未处理）有意不同，帮助文档须写明防「计数对不上」误读。
- 横幅组件、横幅样式与概览页专属告警管线的删除属 BREAKING 变更，回滚=revert 提交；历史告警数据双向兼容。
