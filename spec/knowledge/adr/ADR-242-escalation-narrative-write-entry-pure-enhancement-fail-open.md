# ADR-242：转人工裁决叙事挂告警写入口作纯增强，机械闸门零 LLM

date: 2026-10-06
status: accepted

## Context

转人工裁决告警的文案由发射点机械拼凑，evidence 是原始技术串；真实事故中决策者面对告警无法独立回答「遇到什么问题、为何需要人工决策、各选项意味着什么」，每多一次「先找人问清楚」的中转，冻结窗口就多拉长一段。但冻结与升级的决定必须留在机械闸门——预算/计数类安全判断不能依赖 LLM 存活；同时告警的 description/evidence/choices/trigger 等结构化字段已有多个机器消费方（alert-resolve、闭环判定、Administrator 处置），说明文本不得侵入这些字段的语义。

## Decision

LLM 叙事只作为告警写入口的纯增强字段落盘：接线点收口在全部 ESCALATION 告警的共同写入口（覆盖六个升级族）与少数旁路 choices 附带点，旁路点复用同一叙事辅助模块，禁止第二套生成逻辑；state_machine 与闸门判定保持零 LLM 依赖；narrative 不改写任何结构化字段，机器消费方零感知、不参与动词分派与闭环判定；生成失败（异常/超时/空输出/三段结构校验不过）fail-open——至多一次尝试、硬超时、WARNING 留痕，告警照常落盘，发射链路零阻塞。叙事是增强，不是门禁。

## Consequences

- 网关不可用时最坏退化为「无叙事的机械文案」，与无此能力时行为一致，冻结决定不受影响；LLM 幻觉最坏退化为文案不好读，不污染裁决执行链。
- 叙事生成在落盘路径上同步执行；转人工为低频事件，硬超时（缺省 60s）+ 总开关兜住延迟上界。
- 后续任何给告警增加 LLM 生成内容的需求，必须沿用「写入口挂点 + 纯增强字段 + fail-open」边界，不得把 LLM 变成发射链路的门禁、不得让闸门判定读取 LLM 产物。
