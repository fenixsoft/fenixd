# ADR-168：进度明细由读侧经 agent 产物实时合成，定位上下文显式落盘禁反推

date: 2026-09-28
status: accepted

## Context

code-fix 车道的进度模型是批级的：进度快照只在批生命周期收尾时更新 `done`，一批 20 条约 60 分钟，期间进度卡片恒 0%，用户无法区分「正常工作中」与「卡死」（fenixd 实测单日两次误判质询）。条级进度源在契约上早已存在——修复 agent 被要求每处置完一条立即向 out 文件逐条追加一行结果（append-only、单写者），编排侧也有容错解析器；缺口仅在消费侧不知道当前批的 worktree/run_id，无法定位该文件。

可选机制有三：写侧（编排器）回写条级进度、读侧按目录形态反推最新 worktree、读侧持显式定位上下文现算。此外「明细不可得」与「已处置 0 条」在用户感知上是两件事（后者读作卡死，前者是正常窗口），回退值语义必须区分二者。

## Decision

- **进度明细类字段由读侧实时合成，不新增写侧回写路径**：写侧在批内阻塞等待 agent run 结束，无从感知条级进度；引入看门狗线程回写则新增进度文件读写竞态并发面。agent 产物 append-only 单写者，读侧 stat+解析的竞态窗口由既有损坏行容错兜住，天然安全。合成字段为现算字段不落盘（合并写剥离），防陈旧快照被后续合并写冻结成误导性数字。
- **读侧定位上下文由写侧显式落盘传递，禁按目录 glob/前缀反推**：上下文键（worktree/run_id/分母）写入既有状态文件且必须进缺省键集（白名单合并语义下缺省集外键读侧不可见、会被下一次合并写剥离），在收尾写点显式清除。备选「按 worktree 目录前缀 glob 取最新」被否——前缀归属歧义是本仓已知事故模式，与 ADR-122/ADR-129 的禁前缀 glob 判归属同源。
- **run 标识由编排器预生成并经既有形参传入 run**，run 内部不再自行生成：不预生成则调用方在 run 返回前无从得知标识，读侧合成恰好在目标窗口（run 在飞期间）失效。
- **「不可得」必须为 null，禁回退 0/空对象等可被误读的值**：任何合成激活条件不满足（不在飞、上下文缺失、产物缺失/零有效行、解析异常）一律置 null，由前端以「尚未产生」类文案呈现；读侧不得因此报错中断。
- **条级字段与批级字段的权威分界随产物生命周期让位**：产物随 worktree 收尾清理后读侧自然返回 null，彼时批级字段已承载终值，不做历史批次进度回放。

## Consequences

- 后续车道可见性/进度类需求优先复用「显式上下文落盘 + 读侧合成」通道，不得为同一产物另起写侧回写；后续车道启动阶段可见性字段（startup_stage）已按此复用同一批上下文。
- 产物逐条落盘成为读侧合成的前提契约：agent 输出契约中「逐条追加、不等全批完成」从软约定升格为可观测性硬依赖，失约场景由 null 三态兜底但不产生明细。
- 轮询读放大受控的前提是产物行数有界（单批条目量级）；无界增量的产物不能套用此模式。
- 可用窗口与产物生命周期绑定，历史批次明细不可回溯——需要回溯的场景须另立持久化口径，不得依赖运行时产物。
