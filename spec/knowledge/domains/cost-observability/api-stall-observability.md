# Run 期 API 往返停滞观测与入账

<!-- knowledge: capability=api-stall-observability rev=5
     sources=spec/archive/2026-10-07-evo-add-api-stall-observability,spec/archive/2026-10-30-evo-api-stall-signal-grading,spec/archive/2026-11-27-evo-add-lane-stall-daily-budget-accounting,spec/changes/evo-stall-signal-archive-scan-reconciliation,spec/changes/evo-add-api-stall-request-detail -->

run 期内单次 API 往返停滞的分级记录、结构化入账与车道级日累计记账：超长往返按严重度分级留现场信号，停滞计数、最长间隔、停滞总秒与逐停滞明细（含请求体积与 token 可用性标注）随 run_metrics 持久化并进每日自省摘要，再按车道聚合出「车道×日」累计视图与阈值告警，形成可按 run/车道/provider 聚合的长期基线；run 期观测动作纯读侧，不做任何干预。

## 规则

- **期内停滞分级信号**：在飞延迟采样点（样本口径 = tool_result→下一 assistant 间隔，与 run-latency-observability 同源单点）对单轮延迟超过 `STALL_ROUND_WARN_SECONDS = 120.0` 秒的样本分级（事件名恒为 api_round_stall，context 增 `grade` 字段）：单轮 >120s 且 ≤300s、且非连续第 2 轮及以上停滞 → INFO 级落日志（`grade="info"`，只计数）；连续 2 轮及以上停滞（连续 = 相邻样本逐个 >120s，遇 ≤120s 样本重置计数）→ WARNING（`grade="warning"`）；单轮 >300s（`STALL_ROUND_ESCALATE_SECONDS`）→ WARNING（`grade="warning-escalated"`）。阈值内样本零信号（严格 > 判定，≤120s 含 119.9s 边界样本静默）；timestamp 缺失/负差值等无效测量既不产样本也不触发信号。
- **停滞常量语义分离**：四常量同值（或近值）不同义、各自独立，严禁合并、复用或互相引用——`STALL_ROUND_WARN_SECONDS = 120.0`（期内分级告警线）、`STALL_ROUND_ESCALATE_SECONDS = 300.0`（单轮升级线，独立声明、不并入既有常量同源组）、`LATENCY_STALL_SECONDS = 60.0`（停滞统计口径，深扫行/摘要日志/stall_ratio 分母依赖，改动破坏历史可比性）、`RUN_STALL_ROUND_SECONDS = 120.0`（run-stop-loss 判停样本计入线，行为面）；常量同源契约测试锁定既有三常量；告警线改动不得泄漏成判停行为变更。
- **run 级统计入账**：run 结束汇总行（`format_latency_summary` 渲染）行尾附分级计数（`warning=N info=M`；既有 stalls>60s 口径不变）。run 收尾时，档案 run_metrics 行（`append_run_line` 的 `type: run_metrics`）与 daemon 侧 run metrics 结构化日志（`metric_type: run_metrics`）均含 `latency_rounds`（有效样本数）、`latency_stalls`（>60s 样本数）、`latency_max`（最长样本秒）、`latency_stall_total_seconds`（>60s 样本秒数总和；空样本/无停滞 run 为 0）四字段，取值复用 run 末延迟摘要已计算的同一 `latency_stats` 结果——单一真源，禁止重复采样或二次计算；停滞总秒在 `latency_stats` 一处求和，run_metrics 透传、自省聚合与车道×日告警全部复用该键，禁止下游各自重算（口径单源）。两条透传链（`_metrics_latency` 公共 helper 与成功路径）同覆盖、不漏。**成功终态**的 run metrics 日志行必须带本 run 实际四字段（统计对象经主通道返回值随 `_finalize_success` 传入），MUST NOT 回退 0/0/None；提前终态路径（无样本上下文）维持零样本回退（`latency_rounds=0`、`latency_stalls=0`、`latency_max=None` 或省略 latency_max、总秒 0），不抛异常、不阻断 run 收尾；轮询环崩溃路径下 run_metrics 行仍照既有契约追加，字段缺省不抛。
- **停滞事件 token 与请求体积语义**：api_round_stall 事件携带本轮 `input_tokens` 与 `cache_read_input_tokens`——同轮 assistant 事件 `message.usage` 可得且非全零时填本轮真实值并标注 `usage_source="assistant_usage"`；不可得（网关逐消息不回传 usage、字段缺失或全零）时置 **null** 并标注 `usage_source="unavailable"`，MUST NOT 写 0 冒充真实用量（「无数据」与「真实值为 0」必须可区分）。事件另携带请求字节体积 `request_bytes`——截至该轮请求发出前本 attempt 已写入 run 转录的累计 JSON 行字节估算（prompt 体积的可得代理；不取 stdout 响应字节，响应体积不代表请求体积），取不到置 null，事件不因体积缺失而丢弃。
- **逐停滞明细（stall_details）**：run_metrics 终态行新增 `stall_details` 数组，每项含停滞轮次号、相对本 attempt 起点的时刻偏移 `offset_s`、停滞时长秒、请求字节体积、该轮 token 与 usage_source；采集点独立于 120s 告警分支，覆盖全部 >60s 停滞轮（含 (60,120] 不产事件的轮），与 `latency_stalls` 计数同口径。新增统计键 `latency_stall_bytes_total`（明细 request_bytes 求和）；停滞汇总行追加停滞合计秒数（复用既有 `latency_stall_total_seconds`）与请求体积合计，新键缺失时行形态与历史逐字节一致（无新键的存量消费方零改动）。既有聚合四字段（latency_rounds/latency_stalls/latency_max/latency_stall_total_seconds）字段名与语义不变，读侧缺新键按无明细/0 处理。
- **每日自省停滞聚合**：每日自省数据摘要第 6 节含「API 停滞聚合」——当日 stall 计数>0 的每个 run 列 run_id、stall 次数、累计停滞秒、最大单轮秒；三值同源自 `latency_samples_from_events` 产出的 samples（stalls/max 取 >60s 统计口径，累计停滞秒取 >60s 样本之和）。同一遍扫描内按 agent_type 分组输出车道级日汇总行（`- <lane>: total=<X>s runs=<N> max=<Y>s（<阈值标注>）`：停滞总秒/run 数/最大单次；车道缺标归 unknown，组按车道字典序确定性渲染；阈值标注与告警面同源——`admin.lane_stall_warn_minutes>0` 标「已超/未超 <N> 分钟阈值」，0 标「阈值关闭」但汇总行照出），不新增 IO、不新建扫描器；自省只读铁律保持（摘要不产生 admin 告警、不写任何文件）。聚合随第 6 节既有降级契约（聚合环节异常降级空产出 + warning，不阻断摘要与其余各节）；逐 run 扫描沿用既有有界流式口径（`MIDFLIGHT_SCAN_MAX_LINES` 上限、逐行解析，MUST NOT 整文件读入内存）；不改 MIDFLIGHT_OUTLIER_DIMS 既有三维度与深扫行为。
- **车道×日累计阈值告警**：admin_monitor 在 api-stall 收尾检测循环内维护车道×日内存计数器——终态 run_metrics 行已落即入账（success 豁免与否、升级线内外均计：日累计是过程指标，独立于单 run 升级信号面，success run 的停滞正是「停滞全被编排层吸收」的墙钟税主体；车道取 `agent_type` 缺落 unknown；产物 mtime 当日过滤挡跨日陈旧产物回灌）。某车道当日累计停滞总秒超阈值（`admin.lane_stall_warn_minutes`，缺省各车道统一 30 分钟，0=关闭）发 info 级 `lane_stall_daily_budget` 信号提示 provider 拥塞（文案含累计秒数/run 数/最大单次；info 级不进人工队列）。去重键=lane+date、每车道每日至多一条：信号携带稳定指纹 `_fp=lane-stall-daily:<lane>:<date>`（不含累计秒数——文案数值变化不得被判「状态变化」拆出第二条记录）走 spec=null 的 daemon 级指纹位经 `merge_signal` 持久键合并，同日复触发仅刷 last_seen 不新增记录，跨日 date 变化指纹自然过期，daemon 重启无需重建去重状态；当日计数器为派生态不持久化，重启后从已落账 run_metrics 行重建（缺新键的存量行按 0 计、不回填历史），跨日条目评估时顺带清理防无界增长。
- **扫描面含归档与对账自证**：admin_monitor 两个停滞信号面（车道×日累计入账与 api_round_stall_escalated 单轮升级）的 run 档案扫描源为「顶层 ∪ archive/」双源——终态 run 被 runs 保留清理（约 5 分钟一拍）移入归档后仍可被后续巡检轮入账/补报，消除「终态落盘→归档窗口窄于巡检节拍」的漏报（实证：历史 4 组落账均为擦边赶上、落账仅比归档最早 4 秒；2026-11-25 窗两例窗口内无巡检轮即漏——code-review 车道日累计 2819.1s 超预算线 57% 首次零告警，单轮停滞 370.9s 使升级面保持上线以来零落账）。归档源沿用与顶层同款 48h 新鲜度界（`_API_STALL_SCAN_MAX_AGE_SECONDS`），MUST NOT 按 UTC 日桶对归档源额外收窄（跨午夜归档的日末终态 run 仍可在 48h 窗内被升级面补报；日桶收拢语义由入账 helper 既有当日 mtime 过滤承担）。三来源（顶层/归档/对账）共用同一 run 级去重键空间；入账去重集每轮收敛裁剪以双源候选全集为收敛基，防「顶层入账→归档→条目被裁→归档源重新入账」同 run 双计。对账自证为确定性兜底（不依赖漏报根因裁定）：每巡检轮将终态 run_metrics 停滞行合计（含当日 archive 内终态 run；基准与入账面同口径——success 终态行计入、当日 mtime 过滤、`latency_stall_total_seconds` 缺键按 0）与内存累计器对账，差额超 60 秒（单条记账线 `LATENCY_STALL_SECONDS`）补发 `lane_stall_daily_budget` 信号（同 kind、同 `_fp` 持久键 merge 不新增记录），evidence/description 注明对账来源；累计器与入账去重集不在对账侧改写，漏计 run 由入账重试自愈、差额随之收敛。
- **既有单 run 观测行为不变**：单 run 分级（classify_round_stall）与升级信号（api_round_stall_escalated，success 终态豁免）语义不变；存量 run_metrics 行缺新键按 0 计入日累计、不回填历史行。
- **行序契约不变**：run jsonl 仍恰一条 run_metrics 行且位于终态行之后、末行=终态；停滞记录不向 jsonl 注入任何新事件类型，事件类型集合与无停滞记录时一致。
- **run 期观测面纯读侧不干预**：停滞分级、逐停滞明细采集、请求字节累计、run_metrics 入账与自省聚合均为读侧旁路——不改变流式事件处理时序、不新增事件类型、不终止/重启进程、不重杀 run、不新增配置键、不接入独立人工告警。run 终态（success/failure）与调度不因停滞记录改变；既有 run-stop-loss 判停按其自身判据独立评估，不受停滞观测影响亦不被其豁免。车道×日累计面是本能力唯一 admin 信号出口（info 级提示，唯一配置键 `admin.lane_stall_warn_minutes`），不改变 run 行为、不做 provider 拥塞治理或重试改造；run 墙钟预算的停滞单列与 dashboard 健康面停滞曲线不在本能力范围。

## 关键行为

数据流三段：① 在飞采样点逐样本分级——info 只计数、warning/warning-escalated 打 WARNING 留现场；② run 末 `latency_stats` 单次计算（停滞总秒在此单点求和），分级计数进汇总行、四字段进 run_metrics 两落点（持久化基线）；③ admin_monitor 收尾检测循环读终态行入账车道×日计数器并评估阈值告警。消费面：每日自省第 6 节逐 run 聚合行提供 run 级可见性——停滞但 turns/cost_usd/duration 三维度正常的 run 不再漏出深扫初筛；车道级日汇总行与 `lane_stall_daily_budget` info 信号把 provider 拥塞从「次日自省才被人工读到」提前到当日感知（噪声三重收敛：lane+date 去重每车道每日至多一条、阈值缺省 30 分钟、info 级不进人工队列）；dashboard 增量索引按 `metric_type==run_metrics` 读特定键，加法字段无破坏。

## 代码锚点

- 主实现：`core/agent_runner/runner.py`（在飞延迟采样、api_round_stall 事件构造、stall_details 组装与 request_bytes 累计）、`core/agent_runner/latency.py`（`LATENCY_STALL_SECONDS`、latency_stats、format_latency_summary 汇总行）
- 停滞信号面与对账：`core/admin_monitor.py`（车道×日累计入账、双源扫描与对账自证）
- 守卫测试：`tests/test_api_stall_signal_grading.py`、`tests/test_api_stall_request_detail.py`、`tests/test_lane_stall_accounting.py`
