# ADR-202：限流打死的 run 冷却到期自动重派一次，意图登记与消费拆分

## Context

ADR-201 落地前，429 限流打死的 run 直接终态失败，需要人工手动重跑。ADR-183 确立了「禁同因重派」的失败语义（防止重派风暴与无限循环）；限流是其中唯一「等待即自愈」的暂时性失败形态，需要裁决是否以及如何对其开有界重派例外。

## Decision

- **上限 1 次**：限流打死的 run 冷却到期后自动重派一次，重派计一次 attempt，受既有预算与重试上限守卫，超上限按既有失败路径收场升级人工——这是对 ADR-183 禁同因重派的有界例外（仅限流、仅一次、冷却到期后）。
- **意图登记与消费拆分**：run 已终态死亡，进程内无人续跑，重派执行必须拆分——runner 只负责终态归因（terminal_reason 为 api_error 且错误文本命中 429 分类）与重派意图登记，不执行重派；消费落在唯一生产调用方的收场分支（code-review 车道为 `core/admin_monitor.py` `_worker`），在该 provider 冷却到期后执行重投递。
- **幂等续做**：重派携带原 run 上下文，code-review 车道复用原 manifest，已落盘分片经聚合读侧按 file 去重消费、已审文件不重审（热修 1b83c1c1 的 error 抢救保证死前产物不丢）。
- **留痕**：重派 run 在运行记录 jsonl 标注限流重派缘由，供取证；冷却期内不派发。

## Consequences

- 限流打死的 run 无需人工介入即可自愈一次，人工只处理重派后仍失败的场合。
- 意图登记/消费拆分使重派不依赖死亡进程存活，消费方收场分支是唯一执行点，无双写者。
- 依赖 ADR-201 的分类判定；分类误判（非限流错误被归为限流）会导致一次多余重派，受上限 1 约束无风暴风险。
