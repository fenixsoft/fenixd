# ADR-230：知识真相源写入单门——一切写入共用蒸馏契约与校验门

date: 2026-10-05
status: accepted

## Context

真相源 `spec/knowledge/` 有多条写入路径：归档触发的增量蒸馏、存量回填批处理、audit 体检的语义转写 run。若各车道各自定义产出格式与提交方式，同一真相源会被多套标准撕裂——校验口径漂移、半成品落盘、并发写互相踩踏都会以「真相源腐烂」的形态累积，而真相源的读者（人类检索者、AI 检索者、audit 扫描器）无法分辨哪条路径的产物可信。三条路径在时间上还可并发：回填批量进行期间用户照常归档新 SPEC，可能同时改同一能力页。

## Decision

- 对真相源的一切写入（增量蒸馏、回填批、audit 语义转写，以及后续任何新写入车道）必须走同一蒸馏契约（同一提示词契约、同一 ADDED/MODIFIED/REMOVED 合并语义），落盘前经 `validate_knowledge` 全量校验，同一标准零豁免；通过后以 pathspec 限定 `spec/knowledge/` 提交。
- 并发写契约：页级冲突先提交者胜；蒸馏类 run 启动时重读现网真相源、基于新版叠加。不做页级文件锁——实测出现高频撞车再升级，避免过度设计。
- 提交必须 pathspec 限定 `spec/knowledge/`（或其子目录），保证每批/每次处置可独立回滚，不与其它工作区的提交混装。

## Consequences

- 真相源任意时刻可用同一校验器体检，读者无须区分产出车道；任一批次可单独回滚。
- 后续任何想写真相源的新机制（新的蒸馏车道、新的纠错通道）都被约束在单门之后，不得旁路直写。
- 代价：并发写以「后者重读重写」吸收撞车，极端高频撞车场景会浪费后写 run 的算力；届时再引入页级锁。
