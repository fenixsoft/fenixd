# 保障机制文档专章（docs/help/07-safeguards.md）

帮助文档中系统回答「框架靠什么机制保证不出事」的专章：按纵深防御叙事讲解各类保障机制的目的、原理与控制点。

## 规则

- 章节定位：`docs/help/07-safeguards.md` 为「保障机制」章，紧随 06 章「调度与治理规则」之后。
- 机制覆盖面：覆盖五类保障机制——lint（交付物声明 lint、晋升 lint、任务格式解析）、门禁（plan-ready/verdict 等产物硬门、晋升门、环境门、verdict 读侧 fail-closed 等状态机转移门）、守卫（收工守卫对账、PreToolUse hook 拦截、场景出题分批等运行时守护）、自愈（boot recovery、restart 协议、run sweeper、watchdog、autostash 回收等恢复链路）、告警（分级流向、escalation 冷却）。该清单是起点不设上限：维护时对照代码盘点，未列入的机制应纳入，已退役的机制不得保留。
- 控制点三要素：每个机制条目说清目的（防御哪类真实事故）、原理（怎么工作）、控制点（在哪拦截/检查什么/违规后果）。
- 零幻觉纪律：章内出现的模块名、文件名、配置键、hook 名必须能在仓库中检索实证。
- 与 06 章分工边界：按「原理/参数」分层——本章讲机制的目的、原理与控制点，不展开运维参数数值（预算数量、退避秒数、告警阈值等）；参数口径留在 06 章；两章正文互相交叉引用，不重复不搬家。
- 写作质量：面向人类的流畅散文体，每个机制小节以连贯段落充分展开论证（段内有因果/递进衔接，不以并列短句堆叠收束），章节间有叙事衔接；表格与列表只作辅助汇总，任何小节不得以清单罗列为表达主体。
- 章节结构变更纪律：章节文件新增、删除或重命名使用 git mv 等保留文件历史的方式；变更后对全目录检索旧文件名（含 `#锚点` 形式链接）必须零命中，README 导语与完整目录表同步反映当前章节编号。
