# ADR-134：run 存活判据以流末行终态为准，恢复语义单一实现点

date: 2026-09-22
status: accepted

## Context

「流文件 mtime 新鲜 ⇒ attempt 进程仍活着」的存活回退把框架主动杀死的 run 判为存活：run 流末行已是终态事件、启动终态补写扫描也认定该文件已终结，而恢复链路的存活探针仍因 mtime 落在窗口内判「有生命」——同一份 run 文件被两处读取给出相反答案，孤儿 ready 被假阳性挡住恢复。且孤儿 ready 的恢复时机绑在 30 分钟周期扫描上：status 不变不产生事件，watcher 触发源对该形态结构性失效。

## Decision

- 存活判据的流回退只认「末行是否终态」：末行属于既有终态事件单源集合（result/error/interrupted/cancelled）即判死，口径 MUST 复用该单源集合、禁止另立字面量列表；`superseded` MUST NOT 纳入——其语义是「本文件弃置、run 在新 sub_run_id 文件继续」而非死亡，纳入会在原地重试退避窗（与流新鲜窗口同量级）内把在跑 spec 判孤儿，造成双跑同一 SPEC。
- 终态判定按「末行」而非「出现过」：终态后置不变量 ⇒ 只看末行；用尾部字节窗口 seek 读取，禁止派发热路径上的全文件逐行扫描。解析失败/窗口不足一律 fail-open 视为存活——保守侧是不误杀在跑 run（误杀=双派发烧钱且污染分支，误判活只损失一个恢复周期）。
- 恢复语义只能有一个实现点：短周期精触发与全量扫描兜底共用同一恢复函数，禁止另写轻量探测（两套实现必然分叉成「这条链说该派、那条链说不该派」的双口径）；精触发入口只补「有意等待早退」（复用既有派发退避/取消保持判据，不新增判据、不绕过任何派发闸门）。
- 精触发稳态零 STATE 写入：error 清空写回仅在 error 非空时执行；有界性依赖队列按 (spec, agent_type) 去重与有意等待早退，不得依赖秒级冷却窗口。

## Consequences

- 派发闸门与恢复链路对「该 SPEC 是否有活 attempt」给出一致答案；被框架终结的 run 不再阻挡恢复，孤儿 ready 恢复延迟从最坏一个扫描周期降到主循环精触发粒度。
- 「mtime 当生命」的同型实现点（worktree 锁活性、admin 孤儿探测）不得静默共存，须逐一书面 defer 并注明承接方。
- superseded 边界须有回归用例锁定（末行 superseded ⇒ 仍存活）。
