# human-escalation-alerts Spec

## MODIFIED Requirements

### Requirement: Dashboard 人工介入通知
人工升级告警的用户可见消费面收敛为运维页：未处理告警统一在运维页「告警记录」页签展示（含严重度、时间、项目、裁决选项信息与处置操作）；侧栏「运维」菜单项以红点数字徽标提示待裁决数（见 `ops-alert-badge` 能力）。Dashboard 概览页 MUST NOT 渲染告警横幅、告警列表或告警操作入口。标记已处理后告警从待处理视图消失、保留在已解决区可追溯。

#### Scenario: 打开 Dashboard 概览无告警横幅
- **WHEN** 存在未处理的升级告警，用户打开概览页
- **THEN** 概览页无告警横幅与告警列表（仅统计卡与项目台账）

#### Scenario: 运维页查看告警并标记已处理
- **WHEN** 用户进入运维页告警记录页签查看告警并点击「标记已处理」
- **THEN** 告警状态更新为已处理，从未处理列表消失、保留在已解决区可追溯

#### Scenario: 徽标提示待裁决数
- **WHEN** 存在未处理且携带 choices 的升级告警
- **THEN** 侧栏运维菜单项显示红点数字徽标（口径见 ops-alert-badge）

## ADDED Requirements

### Requirement: 全局清理入口随告警页签收敛

运维页「告警记录」页签 SHALL 提供「清理所有事件」入口（桌面与移动端形态均可触达）。执行前 MUST 二次确认，确认文案明示：范围为全部项目的未处理告警、操作不可撤销、AdminMonitor 不会对同一告警重新升级。确认后经既有清理通道逐条标记已处理，成功后给出提示并刷新列表。原概览横幅专属入口随横幅退役，全系统仅此一处全局清理入口。

#### Scenario: 确认后清理全部未处理告警
- **WHEN** 用户在告警记录页签点击「清理所有事件」并在确认弹层中确认
- **THEN** 全部项目未处理告警被标记已处理，待处理列表清空（已解决区保留历史），徽标计数归零隐匿

#### Scenario: 取消清理不产生副作用
- **WHEN** 用户在确认弹层点击取消
- **THEN** 不发起任何清理请求，列表与徽标保持原状
