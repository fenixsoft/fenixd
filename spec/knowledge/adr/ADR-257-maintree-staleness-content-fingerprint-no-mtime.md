# ADR-257：主树改动集滞留计时用内容指纹，禁用 mtime

date: 2026-10-08
status: accepted

## Context

主树散件 WIP（流水线外的 tracked 未提交改动）需要滞留时长判定来驱动宽限升级，实证案例（potplayer-base 主树 4 文件滞留超 6 小时无人认领）表明 mtime 不可作计时依据：merge-back 的 autostash 序列「stash→merge→pop」在合回前后腾空/回填主树，pop 会批量重写被改动文件的 mtime（四文件纳秒级同刻），既销毁滞留时长的直接证据，也会把任何基于 mtime 的计时器归零。主树的 mtime 不是可靠时钟——它是合回机制的副作用写入面。

## Decision

- 主树改动集的滞留/陈旧计时一律基于内容指纹的连续在场：指纹 = 改动路径排序集 + `git diff HEAD` 内容哈希（对 HEAD 求，含暂存+未暂存；纯 `git diff` 对纯暂存态散件为空、哈希退化为空串，故不用；路径集与哈希 NUL 分隔防拼接歧义）。首见建档记 first_seen，指纹不变沿用原 first_seen 继续计时。
- 禁止以文件 mtime、stat 签名或任何可被外部 git 操作重写的文件系统时间戳作主树改动集的滞留计时依据。内容变化即换新指纹重起算（旧条目清除），改动消失即清除计时状态。

## Consequences

- autostash pop、checkout 等批量重写 mtime 的操作不再干扰滞留计时，散件滞留时长可跨合回临界区稳定累积。
- 计时粒度从文件级粗化为改动集级：同批散件部分被处置时整体换指纹重起算，滞留时长不按文件细分——可接受，升级判断只关心「这批改动无人认领多久」。
- 后续任何对主树改动集做滞留/陈旧判定的新能力受本裁定约束，须走内容指纹。
