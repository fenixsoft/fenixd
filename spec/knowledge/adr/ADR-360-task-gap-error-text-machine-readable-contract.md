# ADR-360：task-gap error 文案是人工回炉提取器的机读载体

date: 2026-11-16
status: accepted

## Context

verified→done 门禁的 task-gap error 文案（`task-gap:` 前缀 + 任务 id 列表）不是纯人读文本：人工回炉提取器（`task_reflow._extract_gap_tasks`）按分隔符正则 `[、,，;；:：\s]+` 从文案反解 gap id 集合，作为回炉资格判定与留痕依据；提取剥离集（`。.；;`）不含全角括号。文案尾部任何扩展都可能改变提取结果——注记直接粘连会把末位 gap id 吞成 `7.2（其中` 形态（剥离后非合法 id 被弃，缺口丢失），注记罗列 id 则在回炉留痕中重复计数。前缀 `task-gap:` 是多处消费方的锚（回炉资格判定、blocker 改述、清除逻辑均只认前缀），前缀之外仍存在非前缀消费点，「error 文案可自由措辞」的默认假设不成立。

## Decision

task-gap error 文案承担机读契约：前缀段逐字不变；尾部追加任何注记必须保证提取器输出与无注记时全等。注记实现格式为「前置空格分隔 + 不罗列任务 id」（` （其中 N 项已申报不可达）`）——空格在分隔符集内且注记碎片均非合法 id，提取结果自然全等。

## Consequences

- 后续对该 error 文案的任何扩展（新注记、新上下文）合入前必须通过「回炉提取全等」核对；罗列任务 id 或以分隔符集内标点直接粘连视为契约破坏。
- 凡被机器反解的文案同属此契约面，「文案纯人读」假设仅对无读侧反解消费方的文案成立；新增文案型接口须先确认是否存在反解消费方。
- 代价：注记只到计数粒度不携带具体任务 id，人工明细需按告警证据或结果文件取。
