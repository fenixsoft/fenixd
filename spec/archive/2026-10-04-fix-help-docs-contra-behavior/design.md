2026-09-26 完成 docs/help 与代码现状的全量偏差审计（5 个领域并行取证 + 主会话自证，覆盖 spec/changes 48 项 + spec/archive 57 项与对应代码）。审计产出分三档：P0「描述与现行为相反」（11 类 16 点）、P1「重要机制零记载」、P2「结构与校准」。本 SPEC 只承载 P0：这些偏差的共性是**文档写的是旧世界行为，代码已经演进到新世界**，读者按文档处置会做出错误动作（等人工释放已被自动重试取代的批次、按串行调度模型误判并发、按 1800s 单段超时误判架构图故障）。

## Goals

- 16 个反偏差点全部改写为与代码一致，每点在 spec 中附权威代码锚点（file:line）作为核对基准。
- 零代码改动：纯 docs/help/*.md 编辑，不触碰 core/、bin/、配置模板。
- 改写遵循各章现有行文风格（表格口径、`> 注`块、交叉链接），不引入新章节骨架。

## Decisions

- **D1 分工边界（本 SPEC vs add-help-docs-mechanism-coverage）**：本 SPEC 的改动单元是「句子/表格行的替换」，判定标准为「原表述与现行为矛盾」；凡属「原表述没错但没讲全/没讲」的内容（如 env 豁免握手的完整链路、fastlane、unseal 态序）一律不进本 SPEC，避免两个 SPEC 改同一段落造成 merge 冲突。05 章流水线段只把「串行」改「并行出题已前置」一句带过，机制展开（parallel_plan.json 产物、槽位豁免）归姊妹 SPEC。姊妹 SPEC 实际交付清单覆盖 04~12，与本 SPEC 重叠文件为 05/06/07/08/09/12 六份（评审复核修正：原记四份漏了 07/12）。
- **D2 数值一律对锚点复核**：所有写进文档的缺省值/秒数/上限，实现时 MUST 以 spec 中给出的代码锚点实读为准（代码可能继续演进），禁止从本 SPEC 文本转抄后不再核对。若实现时发现锚点值与本 SPEC 记载不符，以代码为准并在该文档处采用代码值。
- **D3 旧表述必须清零**：每个反偏差点的旧表述关键词（「不同优先级之间不并行」「UU → add」「1800 秒硬超时」「保留待人工」「release_failed_batch」「十个角色」「10 状态全景」「十状态」等）在对应文档中 MUST 无残留（含交叉引用处）；`06-governance.md` 调度模型改写时同步检查 `12-faq.md` 第 1/2 条是否引用了旧口径。
- **D4 fast-track 单次收口**：全部改动为 9 份 md 的就地编辑，无相互依赖，单次实现调用可完成；验证采用 cli 形态 grep 断言（旧表述不存在 + 新口径关键值在场），不启动浏览器。

## Risks

- **R1 文档交叉引用断裂**：05/06/08/09 互有锚点链接（如 05 → 06 的修复循环熔断）。改写时 MUST 保持相对链接与锚点 id 有效；改标题会改锚点 id，故优先改段内文字、不动标题。
- **R2 帮助页缓存**：Dashboard /help 前端按需拉取 md，无服务端缓存，合并后刷新即生效；无需 daemon 重启，验证时以文件内容为准。
- **R3 与姊妹 SPEC 的同文件竞态**：若两个 SPEC 并发在飞，05/06/07/08/09/12 六份文件可能被先后修改。缓解：姊妹 SPEC 立项描述中显式声明「以合并后最新文档为基线，只增不删本 SPEC 的新口径」；框架层 wip gate / spec 目录在飞守卫已兜底合并冲突。
