# ADR-282：主树 git 写裁决动作的清单约束与信号类型绑定

date: 2026-10-26
status: accepted

## Context

裁决选项注册表此前收录的动作要么纯留痕（确认/观察/声明），要么只动 spec 状态机与项目配置，admin_actions 执行面没有任何对主树的 git 写。主树散件 WIP 滞留信号（maintree_stray_wip_stale）反复触发同型裁决（核对归属→提交散件），登记 commit_stray_wip 选项后，注册表出现了首个主树 git 写动作；同时 resolve_choice 对未注册 signal_type 存在非作用域动作全表反查放行通道，任意未注册信号（含无处置桶的姊妹 info 信号）都能触达该动作——主树写暴露面若不加约束，将从「处置会话自由裁量」扩大为「任意信号可达的注册动作」。

## Decision

commit_stray_wip 及后续一切带写副作用的裁决动作受三重收口：

1. 清单约束：只提交信号记录 evidence 文件清单与当刻 `git status --porcelain` 的交集，拒绝任意路径；清单中已不在当刻 status 的陈旧条目跳过不报错；交集为空返回明确 error，不产生空提交。
2. signal_type 绑定：执行器仅受理注册该动作的信号类型，其余（含未注册信号）一律拒绝且零 git 写——全表反查通道的可达性不是执行授权，证据解析也仅取绑定类型信号记录。
3. 非 destructive + 留痕：提交可回溯，不设确认门；执行结果在处置记录附提交 hash。

## Consequences

- 归属判断不委托给选项本身：交互会话遗留与车道漏提交的辨别仍由处置程序承担，选项只标准化「执行+留痕」，不替代判断。
- 盘点升级链路保持零写，ADR-258 的只读观察者与处置权留人工程序边界不推翻；提交动作只存在于裁决执行链，由处置程序显式发起。
- 主树 git 写的注册表暴露面有了机械上界：任意信号只能触达绑定到自己的写动作，后续 stash/discard 类姊妹动作按同型约束追加。
