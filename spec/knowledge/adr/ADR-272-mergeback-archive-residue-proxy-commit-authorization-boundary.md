# ADR-272：归档残留自愈的代理提交授权边界（成对判据 + 精确路径 + 单次尝试）

date: 2026-10-13
status: accepted

## Context

主树滞留归档半程状态（spec 目录移动已发生、收口提交未落库）时，任何无关 spec 的 merge-back 都会被 git 以「local changes would be overwritten」拒绝，既有顺延链熔断后只能烧 admin 会话等人工（同族告警一周 34 条）。由框架代为补提交归档收尾可以自动放行，但框架代提交来历不明的工作区文件风险极高：误把源码 WIP 或其它 spec 的在途草案卷进提交，会把一次悬置放大成对主树的污染。归档收口侧收口提交 fail-open、push 尾部兜底窗口有限，残留可无限期存在，自愈是必然方向，授权边界必须先钉死。

## Decision

- 框架代理提交只在「同 spec 两侧成对」特征命中时授权：`spec/changes/<spec>/` 删除态与 `spec/archive/` 新增/未跟踪态同 spec 名成对（git R 重命名行视为天然成对）。特征信号单源复用归档收口共享辅助（core/archive_commit.py），自愈授权在该宽信号（任一侧即算残留）之上另加成对校验；仅单侧的半提交形态不授权。
- 补提交 `git add` 必须限定为共享辅助返回的精确残留路径清单，禁退回 `git add -- spec` 或双前缀通配（前缀式会把其它 spec 在途草案卷进提交，code-review 88209fa06ce0 已证）。
- 任一脏文件落在 `spec/changes` 与 `spec/archive` 两类路径之外即一票否决整条授权；自动触碰面恒限于这两类路径，绝不自动提交源码路径。
- 单条 merge-back 自动收尾至多尝试一次（daemon 生命周期内进程内集合记账，重启后至多再试一次），补提交前重查工作区（收口已被并发完成则跳过补提交直接重放 merge），避免与归档自身收口重试互相踩踏。

## Consequences

- 归档收口 fail-open 语义不动：悬置残留由自愈在下次 merge-back 撞上时自动收尾，push 尾部兜底保留为双保险；「必烧 admin 会话」降为自动放行。
- 误判代价被三重封顶（成对判据 + 路径白名单 + 单次尝试），失败即回人工通道，不重试放大。
- 后续任何「框架代提交工作区文件」类自愈受同一边界约束（成对/精确/白名单/单次），放宽须显式 supersede。
