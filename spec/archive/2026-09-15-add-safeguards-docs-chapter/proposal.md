# 帮助文档新增「保障机制」专章

## Why

Fenix 框架在长期演进中沉淀了大量保障机制——声明 lint、晋升门禁、产物硬门、收工守卫、PreToolUse 拦截、boot recovery、run sweeper、watchdog、告警分级等——但它们散落在代码各处与零散的 SPEC 记录里，帮助文档（docs/help/）没有任何一章系统性回答「框架靠什么机制保证不出事、每个机制为什么存在、在哪拦截、违规后发生什么」。新人读 06 章只能看到治理参数口径（预算数值、退避秒数、告警分级），看不到机制全貌与设计原理；读 FAQ 只能按现象反查。缺这一章导致：机制被误当官僚负担、出问题时不知道框架已经防了什么/没防什么、新机制上线后无人知道它与既有机制如何衔接。

## What Changes

- 新增 `docs/help/07-safeguards.md`：以流畅散文体（非罗列、非短段落堆叠）系统讲解框架保障机制，每类机制讲清**目的**（防御哪类真实事故）、**原理**（怎么工作）、**控制点**（在哪拦截/检查什么/违规后果），组织为纵深防御叙事。
- 章节插入为第 07 章（紧随 06 章「调度与治理规则」之后），原 07–10 章顺延重命名为 08–11。
- 修订全文档 35 处交叉引用（含 `#锚点` 链接）与 README 导语、完整目录表。
- 与 06 章分工：新章讲机制的目的/原理/控制点（为什么与怎么防），06 章保留运维参数口径（数值/阈值/生效方式），两章互相交叉引用，不重复不搬家。

## Capabilities

### New Capabilities

- `docs-safeguards-chapter`: 帮助文档保障机制专章——章节内容覆盖面（lint/门禁/守卫/自愈/告警五类，以代码实证）、章节编号迁移与断链清零、与 06 章的分工边界、写作质量（散文体、段落充分展开、控制点三要素齐全）。

### Modified Capabilities

（无——`spec/specs/` 为空，归档目录亦无 docs 相关既有能力。）

## Impact

- 仅文档层：`docs/help/` 目录。新增 1 个文件、重命名 4 个文件（git mv 保留历史）、修改 README 与各章交叉链接。
- 不触及任何代码、配置、状态机与验证链路；无 UI、无数据迁移。
- 风险集中在内容质量：机制描述与代码实现失真（以代码为准原则约束）、重编号断链（grep 清零验收）、与 06 章口径漂移（交叉引用而非复制）。
