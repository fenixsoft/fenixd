# ADR-369：推送 git 环境缺位属确定性终态——预检 N/A 短路不进退避不写 error

date: 2026-11-16
status: accepted

## Context

推送步骤裸执行 git push 且目标分支硬编码 main，无任何 git 环境预检。纯本地仓库（无 remote、分支非 main）上推送属确定性必败：dsh-plugins 每日自省收尾推送连败 16 天；done 态续推通道装载后存量 done spec 集体投递必败，失败按退避重试耗尽后污染 STATE error 字段并各产一条 push_failed 升级告警——把「环境缺位」这一恒定事实当成瞬时故障反复重试，既烧重试预算，又让 error 字段（真实失败留痕与耗尽升级判定的载体）被确定性环境噪音淹没。同批实证续推通道不查 approve_mode，manual 审批语义被重启续推绕过。

## Decision

推送执行前在推送单点做 git 环境确定性预检（remote 存在性 + 目标分支存在性，纯本地探测不发网络），任一缺失即推送不执行、以结构化 N/A 标记经既有 `(bool, str)` 返回契约分流，落 entry 专用持久字段（push=N/A + 原因）终局留痕——不写 error 字段、不进退避重试、不计重试计数、不发升级告警；续推通道读该字段即终局跳过，跨重启幂等。推送目标分支去硬编码：配置键优先、缺省按仓库当前分支探测。环境缺位的消除手段是人工配置 remote（或清除 N/A 字段重推/随归档消失），框架不自动建远程。续推通道并行补审批门：approve_mode=manual（含缺省回退）且零推送记账的 done spec 不自动补投——人工审批语义不被周期扫描绕过，有记账（人工已批准后的退避重试）照常续推。

## Consequences

纯本地仓库推送零执行零噪音，error 字段恢复为真实失败与耗尽升级的专属留痕面；续推通道对 N/A spec 零投递。代价：N/A 属持久终态，「环境修复后自动恢复推送」不是默认语义——后续配置 remote 需人工清除字段或等归档；预检引入少量 git 子进程调用（仅推送路径触发，频次低可接受）。后续任何新增推送入口（新收尾通道、新车道推送）必须经同一预检单点并尊重 N/A 字段，绕过预检直推须显式推翻本裁定。
