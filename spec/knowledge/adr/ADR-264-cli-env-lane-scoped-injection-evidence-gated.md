# ADR-264：CLI 行为调参 env 走车道级注入，扩展须同构证据评估

date: 2026-10-11
status: accepted

## Context

Claude Code CLI 的行为可由环境变量调参（如 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` 后台等待上限，缺省 600 秒）。自进化复核 run 把逐条核查派给后台子代理后结束回合，CLI 按 600 秒上限强杀仍在跑的子代理：主 run 以中期文案充当终局（CLI 侧 completed、退出码 0）、产物与分片零落盘、抢救通道无从合并，框架只能整任务重跑，单次事件双倍消耗一个完整分析。给 CLI 行为调参存在两个注入层级可选：runner 全局硬注入位（全部车道生效）或车道级 env_overrides（单车道生效）。

## Decision

- CLI 行为调参 env 一律走车道级注入：注入点在各维护 run 的 env_overrides 组装处，不放 runner 全局位——全局放宽会让其他车道残留后台任务的 run 永不主动退出、烧满 run_timeout 预算。
- 扩展到其它车道必须同构证据评估而非盲改：以模板是否含子代理派发、既有转录有无后台派发与击杀 stderr 签名为准（不要求新派真实 run），「注入/不注入」的决策与理由以注释留痕；默认不注入，避免改变未发生问题的车道行为。

## Consequences

- evolution 车道子代理等待不受 600 秒上限击杀；其它车道 env 与超时行为逐位不变。
- 后续给 CLI env 调参的 SPEC 必须先回答「哪个车道需要、为什么其它车道不需要」，评估证据不足时默认不注入。
- 无限等待叠加子代理真挂死由既有 run_timeout 兜底，相比「上限击杀后整任务重跑」仍烧更少预算；CLI 变量改名或移除时归因签名随 stderr 文案漂移失效，退回现状失败文案，无副作用。
