## ADDED Requirements

### Requirement: spec 详情页长区块页签化

spec 详情页 MUST 将四个长区块——运行时间轴、场景级测试结果、Bug 列表、失败截图——改为独立页签展示，替代现有自上而下平铺。页面顶部 MUST 常驻展示验证结论、验证进度、任务清单三个区块（标题与状态信息之后、页签栏之前）。页签栏 MUST 包含「运行时间轴」「场景结果」「Bug 列表」「失败截图」四项，默认激活「运行时间轴」。点击页签 MUST 仅显示对应区块内容；页签选择为纯前端状态（不改变 URL hash），并在页面内刷新/SSE 重绘后保持。无数据的页签 MUST 显示空状态占位而非隐藏页签项（便于用户知晓该页签无内容）。

#### Scenario: 默认激活运行时间轴页签
- **WHEN** 用户打开某 spec 详情页，顶部三区块之后出现页签栏
- **THEN** 默认显示「运行时间轴」页签内容，其它三个页签内容隐藏

#### Scenario: 点击页签切换内容
- **WHEN** 用户点击「失败截图」页签
- **THEN** 页面仅显示失败截图区块，运行时间轴/场景结果/Bug 列表内容隐藏，URL 不变

#### Scenario: 空数据页签显示占位
- **WHEN** 某 spec 无 Bug 列表数据，用户点击「Bug 列表」页签
- **THEN** 该页签显示空状态占位（如「暂无 Bug」），页签项本身仍可见可点

### Requirement: 详情页顶部常驻区块

spec 详情页顶部 MUST 常驻展示验证结论（verdict）、验证进度（verify progress）、任务清单（tasks）三个区块，它们 MUST NOT 被页签栏收纳，始终位于页签栏之上、紧随标题与状态信息之后。三个区块 MUST 保持现有渲染内容与交互（任务清单进度条、验证进度条、结论摘要等）不变。

#### Scenario: 顶部区块不被页签收纳
- **WHEN** 用户切换到任意页签（如「场景结果」）
- **THEN** 验证结论、验证进度、任务清单三个区块仍完整显示在页签栏上方

#### Scenario: 常驻区块内容完整
- **WHEN** 某 spec 含任务清单与验证结论，用户打开详情页
- **THEN** 顶部可见任务进度条与验证结论摘要，与页签内容并存
