## ADDED Requirements

### Requirement: 项目页分面导航容器

SPEC 列表页（项目页，路由 `/projects/:name`）SHALL 在**项目名称下方**渲染一个 `Tabs` 分面导航容器，作为页面的主内容组织方式。

- Tabs SHALL 恰好包含三个分面，`label` 依次为「开发」「质量」「会话」（顺序固定）。
- 默认选中的分面 MUST 为「开发」。
- Tabs 的选中态 SHALL 仅保存在组件内存中，MUST NOT 持久化到 URL（刷新页面后 MUST 回到默认的「开发」分面）。
- 分面切换 MUST NOT 触发页面级整页刷新、MUST NOT 改变项目路由。
- Tabs 容器 MUST 在桌面与移动端两种视口下均渲染（`useIsMobile` 分支不影响 Tabs 本身的存在）。

#### Scenario: 页面渲染三分面

- **WHEN** 用户打开项目 `A` 的项目页
- **THEN** 项目名称下方 MUST 显示一个含「开发」「质量」「会话」三个分面的 Tabs 控件

#### Scenario: 默认分面

- **WHEN** 用户首次打开（或刷新）项目 `A` 的项目页
- **THEN** 选中的分面 MUST 为「开发」，其内容可见

#### Scenario: 切换分面不改变路由

- **WHEN** 用户点击「会话」分面
- **THEN** 页面必须原地切换到会话内容（不得整页跳转或刷新），浏览器地址仍指向 `/projects/A`

#### Scenario: 刷新回到默认分面

- **WHEN** 用户当前位于「会话」分面并刷新页面
- **THEN** 页面 MUST 回到「开发」分面（选中态不持久化）

### Requirement: 「开发」分面承载 SPEC 列表

「开发」分面 SHALL 承载既有的项目 SPEC 列表及其全部既有能力——搜索框、状态/类型/归档筛选、桌面表格与移动端卡片、行操作菜单、文档弹窗等。该分面的行为 MUST 与引入 Tabs 之前保持一致（零回归）。

#### Scenario: 开发分面展示 SPEC 列表

- **WHEN** 用户打开项目 `A` 的项目页并处于「开发」分面
- **THEN** MUST 显示该项目的 SPEC 列表（桌面表格或移动端卡片）与搜索/筛选控件

#### Scenario: 开发分面列表交互不变

- **WHEN** 用户在「开发」分面使用搜索、筛选或行操作菜单
- **THEN** 行为 MUST 与 Tabs 引入前一致（过滤、排序、打开文档、修改状态等均正常）

### Requirement: 「质量」分面空态占位

「质量」分面 SHALL 在本变更中仅渲染空态占位，MUST NOT 展示任何业务数据或控件。空态 MUST 有明确的「建设中」语义提示，MUST NOT 表现为空白无反馈。

#### Scenario: 质量分面显示建设中文案

- **WHEN** 用户点击「质量」分面
- **THEN** 内容区 MUST 显示空态占位与「建设中」类提示文案，且 MUST NOT 发起任何拉取质量数据的请求

### Requirement: 「会话」分面承载会话界面

「会话」分面 SHALL 内联承载项目级自由会话界面——消息流区（复用既有 `claude-msg` 展示控件）与输入区（多行输入 + 发送 + 停止），MUST NOT 再以 Modal 弹窗形式呈现。

- 会话未启动时该分面 MUST 显示空态与「开始会话」按钮；点击后才启动会话进程，切到本分面 MUST NOT 隐式启动进程。
- 会话界面的消息渲染 MUST 由既有 `runEventsToChatMessages()` 转换，MUST NOT 另写一套渲染。
- 会话终止事件 MUST 以明确的终态提示呈现（输入区禁用），MUST NOT 静默无响应。
- 会话界面 MUST 仅在「会话」分面被选中时拉取会话状态并订阅事件流；分面未被选中时 MUST NOT 发起会话拉取或注册事件订阅（避免在项目页首屏产生无谓请求与订阅泄漏）。
- 切离「会话」分面时 MUST 释放该分面持有的会话事件订阅，MUST NOT 遗留活跃订阅。

#### Scenario: 会话分面显示会话界面

- **WHEN** 用户点击「会话」分面
- **THEN** MUST 显示会话的消息流区与输入区（会话未启动时为空态 + 「开始会话」按钮），而非弹出 Modal

#### Scenario: 未选中时不订阅会话

- **WHEN** 用户打开项目页并停留在「开发」分面（从未切到「会话」）
- **THEN** 页面 MUST NOT 拉取会话状态或注册会话事件订阅

#### Scenario: 手动开始会话

- **WHEN** 用户在「会话」分面空态点击「开始会话」
- **THEN** 系统 MUST 调用会话启动端点，随后分面转为消息区 + 输入区

#### Scenario: 会话终止有明确提示

- **WHEN** 会话因空闲超时或进程退出而结束
- **THEN** 会话分面 MUST 显示明确的会话已结束提示，且输入区 MUST 不再接受发送

#### Scenario: 切离分面释放订阅

- **WHEN** 用户在会话进行中从「会话」分面切回「开发」分面
- **THEN** 原会话事件订阅 MUST 被释放（注销 watch / 关闭事件流），且 MUST NOT 终止会话进程本身
