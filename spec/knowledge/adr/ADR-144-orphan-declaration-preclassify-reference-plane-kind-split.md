# ADR-144：孤儿交付物声明按引用面判定，机械预分类不占人工裁决通道

date: 2026-09-23
status: accepted

## Context

仓库内零引用的孤儿交付物声明会触发守卫缺件 → 实现者异议 → blocked 待人工裁决，长时间空转占用人工与 admin 通道。判定「是否被引用」若用裸文本搜索，观测面（自省报告、admin 记录、todo.md 等框架记账文本）一旦提到该路径即出现命中，判定结果随记账行为翻转；裸 grep 扫全树在工作树体量下还会卡死同步调用的晋升链路。

## Decision

- 引用面与观测面分离：引用判定只在 tracked 源码面进行，以负向 pathspec 显式排除框架记账面（.fenix/**）、声明自身所在 spec 面（防自证非孤儿）与产物目录；观测面命中不算引用。用 git grep（只扫 tracked、关闭正则），禁裸 grep 扫全树。
- 历史判据按声明 kind 分化：`new` 不查历史（新建文件的本义即历史未出现，历史查询对 new 零信息量，且按文本内容匹配的 pickaxe 会命中任何提到该词的提交）；`modify` 以路径限定的历史存在性判定——路径曾存在而缺失更可能是拆包/改名漂移，转人工不判孤儿；`delete` 不参与孤儿预分类（delete 声明一律进人工裁决防洗白）。
- 任务清单是交付需求的第一语义位：全路径及其 basename 均零出现方可判孤儿；basename 命中只让判定更保守（回退人工，不误删真实交付物）。
- 机械删除后 MUST 续走既有守卫对账（重跑守卫、以剩余缺件续走既有处置，全清才放行 merge），不得「删完即 return/即 blocked」；声明改写后立即提交，防 merge 指纹熔断冻结；判定任一环节异常全量回退人工路径（fail-open）。任一规则有命中 → 非孤儿 → 维持人工裁决。

## Consequences

- 零引用孤儿声明不再消耗人工裁决与 admin 处置；同名多命中、语境等价、运行时产物路径等需语义判断的形态仍走人工。
- 晋升 lint 期对同类确定性形态（new + 全零引用）前置拦截，把孤儿暴露提前到起草期。
