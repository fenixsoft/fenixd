# admin-signal-consolidation — 同 spec 同类型信号状态沉淀

## 背景
add-web-ui 自 09-10 起 blocked 悬置约 9.5 小时，期间 admin_monitor 每分钟检查、cooldown 60m 节流，产生 92+ 条 blocked_stuck 节流日志与 94 条信号记录（占窗口 95 条信号绝大多数），监控信噪比被严重拉低，且节流意味着「同类信号不重复升级」——完全相同的 blocked 状态在数小时内无任何实质处置推进。

## 目标
- 同一 spec 同类型信号在状态未变时改为「状态沉淀」：仅维护一条信号记录，记录首次触发时间与最近一次发生时间，不逐轮新增/重复刷日志。
- blocked 悬置 ≥2h 时强制重复升级真人（突破节流），而不是仅在 cooldown 期满后再次节流。
- 信号记录携带状态哈希（spec 状态 + 关键字段），状态未变即判定「仍相同」。

## 非目标
- 不改 AdminMonitor 的孤儿判定与管理员处置调度本身。

## 验收
- 同一 spec 同类型信号在状态未变时，admin_alerts 信号记录不重复新增；日志仅记首次与最近时间戳。
- 状态悬置 ≥2h 且未处置时，产生一次人工升级（非节流丢弃）。
