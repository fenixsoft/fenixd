# ADR-348：grace 否决窗状态不落盘、锚推荐可用时刻读时计算

date: 2026-11-11
status: accepted

## Context

自动执行前需要给人工留否决窗（grace），两个设计约束相互牵制：窗锚点若选告警创建时刻，「告警创建与 arbiter 推荐落账异步」的升级件（实证相隔 1h40m）在推荐落账时窗已过期、否决窗归零，违背「窗内人工可否决」契约；而窗状态落盘则引入新状态文件与清理/漂移面。

## Decision

- grace 窗状态不落盘：到期时刻 = 推荐可用时刻 + grace，读时计算。推荐可用时刻取告警 `arbiter_upgrade.upgraded_at`（arbiter 调查完成、推荐落账时刻），无 upgrade 痕回退告警 `created`。
- 执行前瞬时重读 handled 与判据二次确认：grace 窗内人工处置（任一 choice 或标记已处理）先到先得，人工动作与引擎到点的竞态由重读吸收。

## Consequences

- 零新增状态文件、零清理面；daemon 重启不丢窗（窗是时间的函数不是状态）。
- 异步升级件的否决窗完整：人工在推荐落账后仍拥有完整 grace 窗。
- 后续「到点自动动作」类能力沿用「锚事件可用时刻 + 读时计算 + 执行前重读先到先得」形态；改为落盘窗状态或锚告警创建时刻须显式 supersede。
