# ADR-137：打回重派路径必须登记可继承遗产，认领单点收口

date: 2026-09-22
status: accepted

## Context

成功收工时 worktree 已被清理、仅分支留存；打回重派路径若不登记遗产线索，重派即新建 worktree、从 main HEAD 起新分支，首轮已提交成果无人认领、无 prompt 注入，整支搁浅。遗产登记的有无在各打回路径间不一致，逐点补丁无法保证不复发。

## Decision

- 全部适用打回重派路径 MUST 在状态写回与重派之前登记遗产：「run 层成功但 spec 层判失败重派」形态在 runner 侧收工前保留 worktree 现场；relint/守卫类打回在 dispatch 侧登记仅分支模式（worktree 路径为空、分支名必填）。
- 保留判定 MUST 复用既有收敛判据本体（缺口口径单点），禁止在 runner 侧自行重写一套等价推导；保留/登记属「保留现场」而非「拦截收工」，其异常 MUST fail-open 走既有 cleanup，MUST NOT 阻断 run 收工。
- 认领单点：重派统一经既有可复用认领入口取遗产（覆盖式更新，同 spec 只留最新一份）；现场保留与仅分支登记两条机制同轮命中时以后登记者为准，登记顺序 MUST NOT 导致 worktree 路径现场丢失。
- 正常成功推进路径的清理语义不变；一致性断言以「遗产在册 + 可认领」为可观测判据，不以「调用了某函数」为判据，使实现重构不破坏断言语义。

## Consequences

- 打回重派从「从零重建」变为「在既有分支上续做」，首轮成果不再搁浅；tasks.md 格式类违规在继承分支上修复即完成，且复检仍在下一轮照常执行、坏格式不因继承被放行。
- 登记义务是新增打回路径的必查项，遗漏即复发搁浅。
