# ADR-331：能力退役真相源即删不墓碑

date: 2026-11-08
status: accepted

## Context

知识真相源只装「系统现在是什么规则」，但能力整体退役后其能力页与 ADR 仍以「保留页面 + 退役注记」的墓碑形态滞留（amis 壳时代五页 + 五条 accepted ADR）：墓碑页规则已非现行，每次会话持续支付读取成本并误导实现定位。同时退役动作天然横跨多个落点（产品代码与路由、其余知识页的镜像指令、能力页、域导航表、ADR、index 计数、log 台账），无标准序列则每次退役各自发明步骤，极易留悬空交叉引用。

## Decision

能力主体从产品删除时，真相源**直接删除、不墓碑**：能力页从真相源删除（主从分片全删），历史由 git 历史 + spec/archive 承载；唯一墓碑形态是所在域 `_domain.md` 表尾一行退役注记（退役日期 + 归档/git 历史指针）。同批动作固定为：删路由与代码及死代码、其余知识页镜像/同步指令收口、删页、域表收口与尾注记、相关 accepted ADR 翻 `status: retired`（追加 `Retired: <YYYY-MM-DD> <一句话>` 注记行、三段正文逐字不动——retired 语义 = 裁定主体已退役且无取代裁定，区别于 superseded 的「被新裁定推翻」，有后继裁定时走 supersede 而非 retired）、index 能力计数同步、log.md 登记、删除前后各一次全库 grep 收口悬空引用；完整 checklist 固化在 knowledge-retirement-runbook 能力页，后续退役照单执行。

## Consequences

退役后的真相源更小且零误导，后续会话不再为墓碑页支付读取成本；代价是退役能力在真相源中不可见，溯源完全依赖 git 历史与 spec/archive（域表尾注记是唯一路标）；退役从单点删页扩张为跨多落点的同批收口义务，遗漏任一落点由既有体检病灶兜底暴露（锚点悬空⑥、ADR 状态/改写⑤、溯源悬空②）。
