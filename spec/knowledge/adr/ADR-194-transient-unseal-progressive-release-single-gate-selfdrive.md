# ADR-194：瞬断熔断解封渐进恢复——单通道闸态机 + 探针复用记账 + 定时器自驱

date: 2026-09-29
status: accepted

## Context

2026-09-22 两场 provider 瞬断风暴实证：全局熔断冻结期只挡触发，解封出口是「清零+立即唤醒派发」的一次性全量放行——per-spec 600 秒重派延迟在冻结期内已耗完，积压在解封瞬间天然同批并发重撞同一 provider（解封后 35.9 秒再吃失败、16 分 34 秒第二场，两场合计约 21 分钟全局停摆、至少 16 次失败 attempt）。指纹归一剥掉 model 名后任何同型错误收敛同一指纹，进一步放大合流。候选治理「渐进 hold」与「探针放行」最初被视为二选一。另外熔断器本身是惰性自清的：仅在被查询时才检测到期，若到期无人查询派发即停摆。

## Decision

熔断解封后的恢复必须走渐进节奏，且渐进 hold 与探针放行叠加实现而非二选一——hold 解决「解封瞬间仍是故障窗」的等价重试，探针解决「积压全量放出的并发重撞」，首条放行即探针、其余为错峰批量，二者是同一段放行逻辑的两种粒度。解封次数按归一化指纹记忆（hold=基数×次数、多指纹取最大、封顶），稳定窗后衰减减一不清零，探针失败额外 +1 加速升级。架构约束四条：

1. 解封节奏全部闸态由派发首道闸**单通道单点消费**（态序短路即优先级：冻结 > hold > 探针观察窗 > 错峰放行 > open），禁新增平行派发通道，避免双通道竞态；
2. 探针判败**复用既有瞬断指纹记账**（观察窗内同指纹新记账即败），禁引入心跳式健康探测等新探测调用；
3. hold/观察窗/错峰各到期锚点由**单飞行定时器链自驱**主动唤醒派发，禁依赖外部触发点被发现——惰性停摆缺口在每个新增时间窗上同等致命；
4. 单条准入在队列 pop 前消费，pop 后闸门回滚条目时**对称退还**名额/节拍锚点；判定与准入异常一律 fail-open 放行（节奏机制故障不放大为调度故障）。

## Consequences

恢复时延变长：解封后最长要经 hold 封顶（600 秒）+ 探针观察窗（120 秒）+ 错峰节拍（30 秒/条）才放完积压，对照收益（避免积压同批重撞引发的连场全局停摆）可接受且全部可配、可显式禁用回旧语义。探针恰逢故障持续时多烧一次 attempt（单条成本，远低于全量重蹈）。单通道态序与自驱定时器成为派发闸门新增时间窗状态的扩展模板：后续任何「到期后行为」类闸门状态必须落入该短路序并挂自驱唤醒，不得再建旁路通道或依赖轮询触发点。
