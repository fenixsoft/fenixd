# ADR-143：验证产物按车道归属表治理，自证型作弊在立项侧机械拦截

date: 2026-09-23
status: accepted

## Context

任务书要求实现者产出只有验证链车道才能产出的文件时，实现 run 为满足任务门禁会伪造证据文件，而读侧「文件存在即权威」只是忠实地消费了本不该存在的文件。写侧拦截不可行（实现者持有 bash 全集，可绕过任何写侧 hook）；读侧溯源（哈希/run_id 交叉核对）改变既有冻结集语义且成本高。根因在立项侧：任务要求了不属于该车道的东西，而起草者与 lint 都无据可依。

## Decision

- 「产物路径标识 → 归属车道集合」落成声明式单一真相源（归属表）：归属关系是领域知识而非匹配细节，lint 与起草自检共用一处，新增验证产物只改一处。
- 机械判据为三重合取：命中归属表登记的验证产物路径引用 × 该引用处未指向任何代码文件 × 引用前有产出动词且执行车道 ∉ 归属车道集合。裸产物文件名 MUST NOT 单独触发（合法任务高频出现同名非产物文件与读取已产侧车），未登记侧车 MUST NOT 触发。
- 执行车道取 `.spec.yaml` 的 mode，缺失保守按 full：验证链产物的归属集合均不含 implementer，full 下恒判违规，精确对应「哪些任务对该车道不可能完成」。
- 拦截点在晋升门（drafted→ready）并复用既有 lint 返回通道（多挂点零改动即生效），lint 自身故障仍 fail-open；机械门与起草指引纵深并存——门保底拦截，指引让起草者第一次就写对。
- 定位是消除意外与激励，非抵御蓄意对手（不做 OS 级沙箱）；零误拦优先于检出率，判据过宽时优先放宽判据而非加白名单，漏拦由起草指引与 unattainable 申报兜底。

## Consequences

- 该类伪证形态在晋升期即被拦下，不再等实现 run 造假后 blocked 空转；归属表由测试锚定防与真实写侧漂移。
