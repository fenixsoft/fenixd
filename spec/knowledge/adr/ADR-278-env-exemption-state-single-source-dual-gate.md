# ADR-278：env 豁免生效锚收拢为 spec 级 STATE 字段（双门同源消费）

date: 2026-10-15
status: accepted

## Context

ADR-212 裁定豁免最终生效以 AdminStore 的 DISPOSITION 放行记录为唯一锚。该锚点在实践中成为结构性死信：豁免落 AdminStore disposition 后，升级握手读得到、verified 白化门禁（verdict_check）读不到——同一豁免在 43ms 内遭遇「握手认可、门禁拒绝」双门矛盾（2026-10-05 potplayer 事故：豁免 granted 后白化门禁同因拒绝，一天烧 8 次裁决后 spec 冻结转人工）。且豁免无场景级粒度、无失效语义挂靠点，env 类失败在「修环境走不通」与「人工豁免死信」之间没有第三出口。

## Decision

- env 豁免以「场景 id + 归一化失败签名」为键持久化到 spec 级 STATE 字段（含场景定义 hash 与 granted_at 时效锚点），STATE 为唯一生效源；升级握手与 verified 白化门禁经同一纯函数消费同一数据源，命中即豁免该项、保持 0-pass 不可白化与「读失败=无豁免」的 fail-closed 语义。ADR-212 的「重验穷尽 + admin 确认后才生效、框架不得以豁免清单自行 verified」不变量继续成立——STATE 豁免仍仅由人工裁决动作写入。
- AdminStore disposition 降为审计镜像：grant 动作仍写放行记录但不再作生效判据；存量 disposition 不做数据回填（无 STATE 豁免即无豁免，重走一次裁决即重建）。任何一侧私藏豁免判据副本（「写入 A 校验 B」）都是机制性缺陷。
- 豁免失效双锚：场景定义 hash 变化（场景被修订）或 TTL 过期即失效，失效后恢复既有升级/冻结计数语义；豁免有效命中的 env 阻塞轮不计入 env 冻结阈值——豁免认可不得仍滑向冻结。
- 场景不可行的第三出口：凭 admin 诊断修订场景定义与夹具供给层文件（白名单限定，产品代码路径拒绝）后重验，修订次数有上限、超限转人工冻结；修订落盘成对同覆盖场景存储，防对账回填旧定义。

## Consequences

- 「握手认可、门禁拒绝」矛盾由同源消除；豁免获得场景级粒度、时效与失效语义，白名单化到场景+签名粒度防白化放大。
- 代价是存量放行记录失效（受影响 spec 需重走一次裁决重建 STATE 豁免）；双门一致性依赖共享纯函数，state_machine 层的匹配口径成为跨模块契约，演进须双侧同步。
- 修订出口是「重写验证输入」的人工通道，路径白名单与次数上限是防后门与防预算焚烧的两道闸，后续任何放宽都必须同时评估这两道闸。
