## ADDED Requirements

### Requirement: 写点断言以语义锚点动态定位

测试对被测代码中取消收尾「写点」的断言 SHALL 使用语义锚点（在指定文件内唯一命中的模式串）而非绝对行号来定位。

#### Scenario: 锚点串唯一命中并定位到写点
- **WHEN** 定位函数在某写点对应的被测文件中以锚点串检索
- **THEN** 该锚点串恰好命中 1 行，且以该行为起点的后续有限窗口内同时出现 `"_cancelled_hold": True` 与 `"error": cancelled_err`

#### Scenario: 锚点串零命中即红
- **WHEN** 锚点串在被测文件中没有任何命中（注释被改写或删除）
- **THEN** 测试失败，报错信息 MUST 包含该写点的 label 与锚点串原文

#### Scenario: 锚点串多次命中即红
- **WHEN** 锚点串在被测文件中命中 2 行及以上（不再唯一）
- **THEN** 测试失败，报错信息 MUST 包含命中次数并提示改用更精确的锚点串

### Requirement: 六处写点数量自证

测试 SHALL 通过全库扫描断言取消收尾写点恰好六处，且与锚点表条目一一对应。

#### Scenario: 写点集合与锚点表一致
- **WHEN** 全库扫描含 "hold-state" 与 "人工取消" 的代码文件
- **THEN** 命中的写点文件集合刚好六处，且与锚点表的六条条目对应（不多不少）

#### Scenario: 新增 run 类型写点未入表即红
- **WHEN** 未来新增第七处取消收尾写点而锚点表未同步新增条目
- **THEN** 数量自证与锚点表双重校验均红，提示补入新写点锚点

### Requirement: 行号漂移免疫

被测文件因合并插入行导致写点绝对行号后移时，写点断言 MUST NOT 失配。

#### Scenario: 写点前方插入行不使断言失配
- **WHEN** 被测文件在任一写点前方插入任意 N 行（写点绝对行号整体后移）
- **THEN** 写点断言仍通过（锚点串定位随行号移动而移动，无需人工重钉行号）
