# ADR-372：处置成功语义以可核验落地为唯一依据

date: 2026-11-16
status: accepted

## Context

环境阻塞族信号的处置链以自述成功语义闭环后，闭环事件对 blocked spec 无任何接续动作：环境根治提交已落地、处置链已闭环，spec 仍滞留 blocked 空等 56.74 分钟，靠 blocked_stuck 超时阈值触发的 admin run（1038 秒/166 轮/约 14.7 万 tokens）才迁回 testing——多烧 1 个 distress 信号与 1 个本可避免的 admin run，同族形态跨日三例复发。伴生缺口：复位尝试被处置在飞互斥跳过后无重评机制（永久丢失）；manual_fixed_reverify 因 blocked_stuck 未注册选项桶被 scoped-no-reverse 拒绝。处置「声称成功」与「状态落地」长期脱钩，成功语义以处置自述为据。

## Decision

环境阻塞族（verify_env_blocked / verify_env_inconclusive / blocked_stuck）的处置闭环自动接续 admin_monitor 既有复位直通道（blocked→testing + 清 error + 入队 verifier），迁移设三重前提门槛：信号属环境阻塞族 ∧ spec 处于 blocked ∧ 处置结果为已修复语义——不满足不迁移，产品缺陷不得被误迁移回 testing；frozen spec 的既有解冻语义不变。复位被处置在飞互斥跳过时登记 spec 维度待重评标记，互斥解除后的下一巡检周期重评消费，恢复不得只能等 stuck 超时兜底。同时确立回执语义裁定：「闭环 / 复位 / 入队」类处置动作写可核验句柄（预期 spec 终态、预期 run 类型、判定时间窗）并做落地校验——窗内观察到预期迁移或预期类型 run 派发才记成功；未落地发升级告警（处置声称与落地不符）、处置记录标记无效、不闭环告警链。处置成功语义以可核验落地为唯一依据，不以处置自述为据。裁决标准不受本联动影响：env 失败场景仍不得判 verified，联动只加快重验到达、不改变验证判定；后续新增处置类动作沿用句柄 + 落地校验纪律，回执只写自述不挂落地核验须显式推翻本裁定。

## Consequences

环境修复后的重验恢复从分钟级空等（最坏 stuck 超时窗）收敛到巡检周期级自动接续；处置在飞互斥跳过不再永久丢失复位机会；桶外拒绝从「事后解析拒绝」前移为「提示词词表按信号桶收窄生成」的前置防越界。残余风险与代价：判定窗与巡检周期耦合，窗过短会误报「声称与落地不符」（缺省 10 分钟覆盖巡检周期）；词表收窄改变 admin 产出分布，须与解析面同源演进防新形态越界；落地核验引入对 STATE 迁移与 run 派发的窗口观测义务。待重评标记消费后清除，标记面不新增告警噪音。
