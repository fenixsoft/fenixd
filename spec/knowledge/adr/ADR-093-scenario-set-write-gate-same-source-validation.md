# ADR-093：场景集写入门：同源校验 + 坏条目剔除继续

date: 2026-09-15
status: accepted

## Context

场景文件读端严格校验、写端零校验：非法条目落盘即被读端判失败；无理由缺场景的补齐路径自产结构性非法占位（写完即必败）；持久化集被 planner 丢场景感染成储库，孤儿跨轮复活；replan 对未消费的错误清单只记 ERROR 后照常重跑，重复成本全付。

## Decision

- 结构校验单一来源：从读端校验提取纯结构检查函数，全部写端（收编写回 / 补齐写回 / 持久化集保存 / 备份更新）前置调用；读端行为零变化。禁各写端自建校验组装（重复逻辑必然漂移）。
- 校验失败的写入策略 = 剔除坏条目继续 + 留痕（id 清单 ERROR），不整批拒绝——整批会把单条坏数据放大成整轮验证中断并触发 corrupt 升级。特例：备份文件仅当全部条目合法才更新（备份价值在「可恢复」，存毒即失去价值）。
- 补齐缺定义 → 登记剔除清单、从写回集剔除，验证以剩余场景继续；为罕见路径加升级往返不划算。
- 持久化集加载净化只动内存不动文件：读操作不带写副作用（最小意外），文件层清除交给显式清理。无法路由 Runner 的条目剔除不损失可执行性。
- 重跑消费硬门挂验收失败比对点：错误清单与上轮相同或为超集 → 判「未消费反馈」，不再自动重跑，直接分级升级（先 admin 代劳，连续冻结阈值后转人工，告警附上轮出题成本供裁决）；错误实质性消除才预算内照常重跑。
- admin 修复写回必须过写端门：拒绝信息含逐条错误清单，admin 单 run 内自迭代；双文件同源坏条目必须同步清理并在处置结果报告。

## Consequences

- 框架不再自产必败数据，孤儿无法跨轮复活。
- 剔除可能掩盖 planner 大面积产出劣化 → 兜底：剔除留痕进验证报告场景集变更小节 + 场景数骤降（剔除 >20%）ERROR 升级。
- 「一字不差」型未消费反馈从重复重跑改为升级，admin/人工往返替代无界自动烧钱。
