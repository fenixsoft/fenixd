# ADR-319：链外通道与处置链的协调以链痕单源查询口承载

date: 2026-11-03
status: accepted

## Context

处置链落地后首例真实链路事件暴露：链外的孤儿看护与链之间没有统一的「该签名正被链接管」判定入口——看护对链在办件（已转派 Arbiter 在飞调查）按 pending 超时直发人工告警，早于链终点 3 分钟重复出件；链 deferred 让行后无唤醒路径，被让行对象死亡不回喂链，链静默挂起到 daemon 重启回扫。两处缺陷同源：协调判定各自就地拼凑链/Arbiter 状态，甚至无痕可查（让行即清空登记）。

## Decision

看护升级抑制与 deferred 重派判定共用一个链痕查询函数：输入签名，输出 `{in_flight, deferred, arbiter_active}` 三态命中。in_flight/deferred 读链状态文件同名区，arbiter 在飞读 arbiter 单飞队列既有注册（只读访问，不新建注册表）；链状态文件缺失/损坏按零命中 fail-open 降级（对齐看护链缺席既有口径）。不做通道归一：孤儿看护保持链外直写人工队列（防自环豁免不动——链死了的报警不能让链自己接）。后续新增链 phase 形态或新的协调消费方，判定一律接该查询口，禁止各自就地读链/Arbiter 状态拼凑。

## Consequences

链条目形态扩展（如 deferred 的 `yield_to`/`deferred_at`）只需在查询口一处反映，新协调面（如未来第四发射通道）接单口即得全量链痕。代价：查询口成为咽喉，留痕、查询、重派三处签名必须同源构造（复用链派发器签名函数），漂移即误抑制或漏抑制；fail-open 降级窗内看护回到链盲开火，重复出件风险在状态文件损坏期间回归（宁重复不漏报的有意取舍）。
