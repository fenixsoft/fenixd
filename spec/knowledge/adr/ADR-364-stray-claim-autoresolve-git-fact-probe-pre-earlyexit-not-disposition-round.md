# ADR-364：散件升级告警认领核销=机械 git 事实判据，探测早退前插桩，自动核销非人工处置轮

date: 2026-11-16
status: accepted

## Context

maintree_stray_wip_stale 的升级条款是零触碰+逐度升级转人工，但「人工已回应」没有消费端：escalated 条目被摄取循环豁免于一切自动处置，指纹文件集被人工以提交处置后告警仍按复发口径零触碰+升级，悬置逐度累加成永久挂账，跨日空转对账消耗 admin run 处置预算。判据若依赖自然语言 evidence 全文理解则不可机械复现；若取「命中单提交」窄口径，则多波提交覆盖的在案条目（33 文件清单由多波主树提交覆盖）永不核销。

## Decision

「人工已认领」判据只认机械 git 事实：条目指纹文件集（结构化字段优先、evidence 段级解析单源回提取兜底）全部被条目基线后提交覆盖（≥1 个提交、覆盖提交数不限）且工作区该集合 clean，一问即答；任一文件未入库或集合内仍脏逐位保留原状——防半处置假闭环由「全覆盖 ∧ 集合 clean」承担，与提交数无关。探测作为纯消费端增量挂在盘点轮空集早退之前（早退不得吞掉本流判定——人工提交完指纹集后恰是 tracked 空集形态，插桩在后核销时点永不执行），不改动处置侧协议与升级节奏。核销写回独立署名 handled_by=auto-resolve-claim（白名单单族，照告警自动闭环先例只改 handled 族字段、不伪造人工记录），复发计数台账检索 MUST 按署名跳过自动核销记录——自动核销不是人工处置轮，计入会使下次同文件告警误带「已 N 度处置」根治口径。转向话术（确认是否仍需建 worktree 车道）随 resolve_note 下发，消费端核销与人工后续裁决分离。

## Consequences

悬置升级条目在人工以提交处置后自动出账，不再空转消耗 admin run 处置预算；以 stash/删除等非提交形态处置的条目不命中、继续走原升级路径（等于现状，无回归）；保守缺省下误核销风险收敛为「继续悬置」，不会吞掉真问题。后续挂盘点轮的新消费流 MUST 沿用早退前插桩红线；复发台账新增消费方 MUST 按核销署名过滤；把自动核销计入人工处置口径、或把认领判据改为语义理解形态，须显式推翻本裁定。
