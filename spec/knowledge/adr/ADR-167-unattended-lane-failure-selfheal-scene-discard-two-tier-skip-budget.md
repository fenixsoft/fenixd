# ADR-167：无人值守车道失败自愈纪律——现场即弃、两层跳过、预算内免人工

date: 2026-09-28
status: accepted

## Context

深夜无人值守的自动维护车道曾按「失败保留现场待人工」设计失败路径，与锁机制叠加成死锁：worktree 锁检查是裸内存判断、锁刷新仅在 daemon 启动首扫执行，保留现场即保留进程内锁——批失败后车道锁死至重启（实证：两次派发均在 14ms 内被「Worktree already active」拒绝，重启前无任何自愈路径）。失败条目进永久档案后唯一出口是人工释放函数；批失败即终止链使剩余整队停摆。该车道的产品定位是无人值守自动维护，人工裁决不可依赖。

## Decision

- 无人值守自动车道的失败处置 MUST NOT 以人工介入为续命前提，单批失败不得堵塞车道。落地为三条纪律：
  - **现场即弃**：凡已建树的失败路径收尾即清理 worktree 并即时释放进程内锁，锁释放不得依赖任何后续人工动作或周期刷新；处置留痕走档案记录（`branch`/`tip_sha` 作追溯线索，不承担恢复职责），不走现场保留。以一次重跑成本换车道永不锁死。
  - **两层跳过、预算分离**：瞬态失败（agent run / 网关层）只跳过本链（链内跳过集，随新链重置），不烧跨轮预算；确定性失败才入永久档案，档案带跨链重试预算（`fail_count`，上限为模块常量），预算内记录由新链启动自动释放——等效人工解除但零人工。
  - **有界止损、边沿告警**：预算用尽即永久跳过，并在用尽当时发一次性点名录告警 + 台账人工项，此后不再重试、不再重复告警（与 ADR-152 的有界回落一致）；「永久 open」条目是接受态，由一次性告警承担可见性。
- 重试预算上限不设配置键（规避配置-UI 同步义务；预算语义无需按项目调节）。

## Consequences

- 失败批的已过回归修复提交被丢弃，由下轮重试重新生成——自动车道以重跑换永不锁死，吞吐优先于单批成功率的时序优化。
- 确定性失败（如主树在批运行窗口内前进引发的整夜合回冲突）在预算内每轮重跑一次，上限兜底止损；根治（如合回窗口互斥）须凭观测数据另立 SPEC。
- 后续无人值守车道新增失败路径应复用此纪律；需人工提取现场的场景（交互式车道）不适用。
