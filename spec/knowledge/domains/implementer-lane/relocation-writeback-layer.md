# 声明修正写回层契约

交付物声明机械修正的落点铁律：写回层必须与读取基准同源，修正后必须复检读得回来；同路径复发有独立熔断兜底。

## 现行规则

- 写回层与读取基准同源：交付物声明的机械修正（`typo` 路径改写、`reference` kind 软化、条目删除）在写入时，落点必须是守卫/裁决的**声明读取基准**——即生效声明命中的那一层（`resolve_effective_declaration` 返回的 `source`）：`source == "worktree"` → 改写并提交到该 worktree（分支）；`source == "main"` → 改写并提交到主树（此时前两层均未命中，守卫读取基准就是主树，就地写入即同源，不构成错层）；`source == "branch"`（`spec_dir` 为 `None`，声明只存在于分支对象库、无落盘位置）→ 不得以主树 `tasks.md` 为落点「就地改写」并视为生效，修正交由实现方在分支上续做（走既有缺件打回/重定位凭据通道），且该条裁决落 dispute 审计流。
- 禁止错层写入：不得在「守卫读取基准为 worktree/分支」的同时把修正只写主树——那会使修正在下一轮被判读不回来（写读错层的根因形态）。
- 覆盖全部写入点：本契约覆盖 `tasks.md` 声明段的全部写入点——judge 执行的 typo/reference/删除分支、确定性软化（`_preclassify_missing`）、孤儿删除（`_preclassify_orphan`）、晋升期软化；任一写入点未按 `source` 判定落点即为漏网。
- 修正后读取一致性复检：每次声明修正执行后，以守卫读取基准（生效声明解析入口）复检被修正的旧路径不再作为生效声明的硬校验项（不再出现 `missing`）。复检不一致（读取仍是旧路径）记入该次处置的 error 明细并告警，不静默销账——静默销账会让打回循环无人可见地持续烧预算。
- 跨轮残留凭据核销：守卫读到的缺件路径，若在跨 run 持久的 dispute 审计流中已有该路径的 `typo` 裁决或重定位凭据，以**凭据核销**为收敛动作——该路径不再要求存在，不因「本轮无新凭据」而无界重派。核销不得放行「路径确从未落地」的假缺件：仅当凭据在册**且**凭据携带的替代路径在实现分支 HEAD 存在时方可核销（判定须能取得凭据中的替代路径，布尔型「是否有凭据」判定不足以完成校验）；凭据存在但替代路径无据不核销。核销作用域限于 `violation == "missing"` 条目，`undeleted`/`removed` 不被吞掉（豁免走既有收缩防护通道）。
- 复发熔断：同一 SPEC 同一路径在 `typo` 修正后连续多轮仍被判缺件（读取基准未对齐的迹象）时计数，达到配置上限后置 blocked 待人工，不再自动重派实现（error 说明「修正未生效于读取基准」）。计数使用**独立持久字段**，不复用会被恢复续做/阻塞复位清零的通用重试计数（否则每轮复位归零、熔断永不触发）；该计数不随 blocked→ready/恢复续做清零，仅在两处清零——本形态修正复检通过、或该 SPEC 退出本形态。
