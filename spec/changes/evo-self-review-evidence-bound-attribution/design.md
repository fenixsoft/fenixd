# design — self-review-evidence-bound-attribution

## 落点

- agents/self-review.md:21-24 是「调查评估」字段的质量标准段：:22 已有核实纪律（「核实不了的写明『未核实』，禁止编造或臆测」）；:23 要求「评估：根因归属（一次性失误 vs 系统性缺口）」；:24 组织顺序「已核实事实→根因→与存量工作关系→结论」。本变更在 :22-23 一带追加证据边界纪律一句。
- 链路事实：模板经 core/agent_runner/prompt_builder.py:1720-1785 `_build_self_review_prompt` 装载（:49 为 agent_type→模板映射），缺失 fail-fast；core/self_review.py:1994-2033 `_render_entry_lines` 对 LLM 产出的 analysis 字段仅格式化渲染、不生成内容（:2019「调查评估」映射）——归因层级是语义判断，代码层无可加机械校验的判定点。

## 决策

1. **模板纪律，不建校验代码**：形态→根因的边界是语义判断，机械校验（如检测「根因是」字样）误报高；依赖模板纪律加下窗观测。模板为文件化体系、缺失 fail-fast，改模板即生效。
2. **不回改历史条目**：todo.md 历史由 daily self-review 的 git 提交固定，回改破坏审计链；10-09 窗已按此口径以新条目更正（55dabdfe），本变更把该做法固化为规则条款。
3. **同时约束建议方向**：仅约束「结论」不够——错误归因的实害经由「建议」传导（本次即「预检重跑」建议）；纪律条款须一并覆盖「MUST NOT 据单因归因建议针对特定根因的修复方向」。
4. **观测验证**：无单测可写；验收观测为下一窗 daily self-review 的归因措辞——若再现「证据只覆盖形态却单因归因」即纪律未生效，届时再评估更强手段。

## 权衡

- 纪律措辞过严可能让自省在证据充分时也不敢下结论——故保留「证据足以裁决时才给单因结论」的正向分支（Scenario 2），边界是「证据层级=结论层级」而非「禁止归因」。
