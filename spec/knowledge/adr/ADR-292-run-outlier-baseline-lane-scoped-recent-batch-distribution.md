# ADR-292：run 指标离群基线车道化——归属分层推断，批量车道以近期批分布替代窗口中位

date: 2026-10-30
status: accepted

## Context

自省中途信号的量化初筛以「同 agent_type 组内窗口中位数 ×3」为离群基线，但 code-fix/code-review/evo/spec-review 等 maintenance 车道从不写带 agent_type 的富指标行（`_log_run_metrics` 仅覆盖 `_execute_agent` 家族路径），这些 run 全部落进 unknown 混合组取中位——2026-10-08 窗口实测 21 个离群里 12 个是正常交付的 code-fix 批（turns 158–826 对混合中位 42 全员越线），100% 误报；evo-1791224502 型真实离群反被噪音稀释、靠人工挑出。unknown 组 cost_usd 有效样本为 0，成本初筛对这些车道完全失明（turns 2114、cost 85.68 美元的 code-review 全仓扫描从未被成本维度看见）。另实测：仅按车道分组修复基线语义仍降不了噪——code-fix 组内中位 49×3=147 < 158，批量车道的正常长批天然越组内中位线，必须叠加车道内历史批分布基线。

## Decision

- 离群基线必须按真实车道归属分组，归属证据分层：指标行 `agent_type` 字段优先，缺失时以 run_id 前缀经共享前缀表 `RUN_ID_AGENT_PREFIXES` 推断（该表为唯一真源，dashboard 时间线归属同源受益），禁止落回无车道混合组；run_id 恒可得，推断无回退盲区。
- 批量相关车道（如 code-fix）的 turns 基线取组内近期批分布：同车道窗口内最近 N=10 个有效批（不含当前 run、按时间倒序）的 P90；有效样本不足最小样本阈值回退窗口中位，非批量车道沿用窗口中位。「同链」解析（run_id 可解析 spec 段时优先取同链批）是可选增强，不作默认依赖。
- 定向重试轮按 run_id 后缀（`-r<n>`/`-a<n>`，与 dashboard 剥后缀同口径）辨识后单独标注/排除出基线样本；无后缀不可辨时不排除、保守入基线。
- 车道指标数据源缺口以写侧补齐为主：maintenance 三车道收尾补 `_log_run_metrics` 富指标行（含 agent_type/cost_usd）、context metrics 兜底行补 agent_type；读侧交叉读成本台账（`.fenix/cost/*_tokens.json`）仅作为写点成本不可得的条件兜底。一次写入多方受益，禁止让初筛成为唯一理解某车道指标形态的读者。
- 越线倍数（3）与最小样本数（3）常量、「样本不足跳过」语义保持不变；后续触碰离群初筛基线或车道指标可得性的 SPEC 以本裁定为准，突破须显式 supersede。

## Consequences

批量车道正常长批不被窗口中位误标（基线窗口 12/12 全误报消除），真实离群不被同车道噪音稀释；成本维度对全部车道可观测。代价：基线语义两层化（分布基线/中位基线并存），批量车道判定依赖近期批样本量——冷启动窗口退回中位基线的噪音形态；重试轮排除依赖后缀约定，无后缀历史轮仍可能抬基线；前缀表补 `evo-` 使 dashboard 时间线归属 agent→evolution（同源预期变化，需回归时间线归属）。
