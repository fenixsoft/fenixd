# ADR-224：LLM 生成管线每轮请求落小上下文安全区，顺序分段磁盘交接

date: 2026-10-04
status: accepted

## Context

bigmodel 网关对「大上下文 × 长输出」请求存在静默丢弃：TCP 连接 ESTABLISHED、收发队列全零、转录零事件、进程 I/O 零变化，CLI 应用层无请求级超时只能无限等待。架构图页签的单体 `claude -p` 形态把这类危险请求密集化——SKILL.md 全文（实测约 16KB）内嵌首条 prompt、Explore 子代理取证报告（11KB+）全文回灌主 agent、主 agent 单轮生成完整候选 JSON，三轮挂点全部落在主 agent 大上下文轮，fenixd 与 fenix-desktop 双项目实测全部 1800s 超时；旁证是小上下文请求几十次零挂。`API_TIMEOUT_MS` 与重试上限只治「挂死」不治「必挂」。

## Decision

凡 spawn claude 的生成管线，LLM 的每一轮请求必须落在「小上下文 × 短输出」安全区：

1. 长任务按职责切分为顺序多段（如探索/出图），段间以磁盘文件为唯一交接面，禁中间产物经上下文携带回灌；
2. 大文本指引（vendored SKILL.md 等）禁内嵌 prompt，一律以包根绝对路径引用交付；
3. 大产物（如候选 JSON）分段小步写盘（先写骨架再逐段补全），禁单次巨量 Write；
4. 每段独立超时与判定链，判定产物实况不信 agent 自述，错误信息注明所属阶段；
5. 中间产物落盘时盖指纹头（如 repo HEAD sha），支持按指纹命中跳段复用，不引入 TTL。

## Consequences

- 编排复杂度上升：线程体从一次 communicate 变多次，失败形态组合增多，每段须独立 try/killpg/finish。
- 中间产物质量决定最终产物质量：探索不足则产物偏离真实，须在探索段 prompt 明确取证维度、出图段允许少量定向补查。
- 分段写纪律无法机械强制，靠产物硬门兜底（超时击杀 + failed 可重试，且指纹命中使重试只付出图成本）。
- 细化 ADR-219 的「指引以提示词注入原文」交付通道：大文本指引改为路径引用；vendored 整包分发与运行时零安装裁定不变。
