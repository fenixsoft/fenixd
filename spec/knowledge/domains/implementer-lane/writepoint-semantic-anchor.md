# 状态写点语义锚定

测试对被测代码中「写点」（如取消收尾的 hold-state 写入）的断言定位方式：以语义锚点动态定位替代绝对行号，实现行号漂移免疫、失配自检即红。

## 现行规则

- 语义锚点定位：写点断言使用语义锚点（在被测文件内唯一命中的模式串）定位，而非绝对行号；以锚点命中行为起点的后续有限窗口内应同时出现目标写点特征键（如 `"_cancelled_hold": True` 与 `"error": <取消原因>`）。
- 失配即红（自检内化，不依赖 daemon/hook 层）：
  - 锚点串零命中（注释被改写或删除）→ 测试失败，报错含该写点 label 与锚点串原文；
  - 锚点串命中 ≥2 行（不再唯一）→ 测试失败，报错含命中次数并提示改用更精确的锚点串。
- 数量自证：测试通过全库扫描断言取消收尾写点恰好六处，且与锚点表条目一一对应（不多不少）；新增写点未同步入锚点表时，数量自证与锚点表双重校验同时变红。
- 行号漂移免疫：被测文件在写点前方插入任意 N 行导致绝对行号整体后移时，断言仍通过——锚点定位在测试运行时动态重算，无需人工重钉行号。
