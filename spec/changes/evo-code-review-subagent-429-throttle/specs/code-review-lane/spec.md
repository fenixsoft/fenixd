# 能力规格：全仓审查车道并发与 429 韧性

## 需求

审查车道的子代理扇出必须对 provider 账户级限流（HTTP 429 / bigmodel 错误码 1302）具备记忆、退避与止损能力：

1. 在飞上限缺省值：verify.repo_code_review_concurrency 缺省从 4 降为 2；prompt_builder 注入的 fail-open 回退值同步降为 2；配置键语义不变，已显式配置的项目不受影响。
2. 429 处置契约（注入全仓审查 run prompt）：
   - 任一子代理死于 429（错误文本含 429 或 1302）后，本 run 后续子代理派发一律串行（在飞 1），不得恢复高并发；
   - 重派前按 60s、120s、240s 指数退避等待；
   - 连续 3 个及以上子代理因 429 在派发后 60 秒内死亡时，停止派发子代理，转为主循环自行逐文件审查，并在终态 result 携带 review_429_storm=true 标记。
3. 风暴告警：框架消费终态 review_429_storm=true 标记，产生一条 admin 告警（同 run 去重），evidence 含死亡分片数与时间线，建议文案包含「检查同账户并发：注意多项目全仓审查窗口重叠，建议错峰排程」。

## 验收

- prompt_builder 渲染的审查 prompt 含 429 处置条款全文。
- 未显式配置时，在飞上限取 2。
- 携带 review_429_storm=true 的终态 result 触发恰好一条 admin 告警，重复终态不重复告警。
