# ADR-371：daemon_errors 升级面自愈签名豁免注册表——压制升级不删日志可审计

date: 2026-11-16
status: accepted

## Context

daemon_errors 升级判据是纯形态级（同指纹 + 10 分钟窗内复现 2 次 + 间隔上限），不区分「daemon 自身故障」与「框架自愈链路的设计内过渡态留痕」。自带自愈消费者的链路重复 ERROR 被升级成建议重启 daemon 的 critical，属系统性误导：WIP 重叠 precheck escalate 拦截 4 天烧出 4 条 critical，实际每次都在预算内被 wip 周期消费者自动合回闭环（实证 6 分 19 秒自愈）；promotion lint 两条 ERROR 实际只召唤了一次 Administrator run。治这类误报若调阈值会放过真故障，若删日志会毁掉自愈链路的取证面。

## Decision

daemon_errors 升级判据挂单源「自愈签名注册表」（模块级常量，条目 = name / component / message 前缀 / 自愈消费者说明，形态仿 alert_lifecycle SELF_HEAL_SIGNAL_TYPES 既有注册表先例，不入 config 以规避配置项须带 Dashboard UI 的约束）：命中签名的 ERROR 序列跳过 critical 升级与重启 daemon 建议文案，但不删除日志行、不影响既有判定行为（窗口阈值/最近间隔判据、重启冷却窗、孪生指纹合并照常运转），不接任何人工复位通道（防毒对齐）。豁免覆盖窗口内复现与跨日同刻复发两个升级维度；跨日维度的可见度由消费端预算超限降级人工告警与命中审计计数兜底。灰区防线：命中审计计数可查、注册表条目注明消费者与超限降级人工语义、自愈消费者停摆后的新形态 ERROR（换签名/持续超窗）不受豁免影响仍会升级。自愈源头侧配套：merge-back precheck 同一重试窗口内的重复拦截聚合落行（首条 ERROR 作首阻取证、后续聚合 INFO 含重试序号），从源头消除复现计数。后续新自愈链路留痕被误升级时走注册表登记条目，而非调阈值、改判据或删日志；豁免面扩张须逐条目注明消费者与超限语义。

## Consequences

自愈链路的设计内留痕不再误触发「重启 daemon」误导文案，真故障漏报风险由三面兜底：豁免命中审计计数、消费端预算超限降级人工告警（既有）、每日龄期盘点对长期停摆消费者的兜底可见。签名匹配面收窄（前缀含 policy=escalate 字面与组件名）以降低误伤真实故障的概率；签名前缀过宽造成的静默是本裁定的主要残余风险，靠审计计数与每日龄期盘点暴露。豁免与既有压制分支同层共存，daemon_errors 判定行为的任何既有语义都不因注册表存在而改变。
