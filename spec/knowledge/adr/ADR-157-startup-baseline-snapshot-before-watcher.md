# ADR-157：daemon 启动先同步建 STATE 基线快照，首扫主体后台化

date: 2026-09-24
status: accepted

## Context

watcher 的变更判定以启动时建立的已知 SPEC 基线为参照：基线未建先跑 watcher，全部存量 SPEC 被判「新出现」，pushed 等 hook 事件全量重放连环触发。而把恢复首扫整体放在主循环之前同步执行，分钟级首扫使主循环——全部文件信号消费者的唯一驱动——在启动期内停摆。

## Decision

- 启动顺序不变量：事件总线启动（建立基线快照）MUST 先于 watcher 线程与首扫主体。
- 首扫拆两段：基线快照同步（毫秒级，只做已知态更新），扫描主体提交后台线程，主循环随即进入。
- 全量扫描 MUST 保留「快照+主体顺序执行」的同步组合入口供既有调用方（周期巡检等整调）；启动路径 MUST NOT 调用会等待后台线程的异步版——后台线程被同步等待吞掉即修复静默失效。
- 后台扫描线程 MUST 带 daemon 标记并纳入 stop() 收口（运行位清零+短 join）。
- 启动窗口内 watcher 先处理新变更、后台首扫处理遗留中间态，两者以基线快照隔离，属可接受并发。

## Consequences

主循环启动后数秒内可响应信号消费；基线不变量由隐式依赖显式化为两段契约；同步入口语义逐字保留，周期巡检零改动。
