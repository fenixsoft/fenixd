# ADR-027：验证失败分流用确定性规则，不进 prompt、不用 LLM

date: 2026-09-02
status: accepted

## Context

验证器把环境性失联（mock 断流 → SSE 不推 → DOM 等待超时）与产品缺陷混为一谈，大面积失败误触发修复家族链。失败归因若走 prompt 注入或 LLM 分类则不可测且烧 token；相似度启发式对已观测失败形态同样不可靠。

## Decision

- 环境性失联在判定层后置分类（非 prompt 层）：场景结算后，断言错误属纯等待类且步骤含 mock 依赖时，对被测实例发起连通性探针——探针失败判 blocked-env，探针成功维持 fail（确属真缺陷或慢场景）。规则为纯函数，可单测。
- blocked-env 从失败计数中扣除；整批失败全为 blocked-env 时判 inconclusive、状态机回 testing 重派新 attempt，且不发 repeated_failures 告警信号（抑制标记随 run 结果传递）；同一场景复验时探针通过则按真 fail 从严。
- 噪音 vs 产品缺陷以「断言从未执行」规则分流：场景失败且断言结果为空或步骤中途失败 → 工具噪音；否则 → 产品缺陷；二者并存按缺陷从严。不做内容相似度启发式、不引入 LLM 分类。
- 噪音的出路走人工告警（含场景 id 与修正指引），框架不自动修改场景文件——框架拦截、Administrator 决策的权责边界，框架代码里不长出场景编辑器。

## Consequences

- 环境故障不再误触发修复链、不烧 repeated_failures 预算；真缺陷在探针成功或复验时被从严放行。
- 分流误伤（环境类失败恰好掩盖产品错误）由从严规则与告警详情的人工复核兜底；判定逻辑全部确定性可测，验证归因不依赖模型裁量。
