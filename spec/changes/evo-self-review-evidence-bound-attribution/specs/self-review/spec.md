# self-review 变更

## ADDED Requirements

### Requirement: 根因归因的证据边界

自省条目的「调查评估」凡涉及根因归因，结论层级必须与当日可回收证据的覆盖层级一致。

#### Scenario: 证据只覆盖形态时结论写到形态层

- **When** 当日可回收证据（失败明细档/告警/日志/commit）只能证明失败形态（如 items 为空、fallback_full=true、total=0），不足以在多个根因假说间裁决
- **Then** 调查评估的结论写「根因未定、多假说并存」并列出假说，MUST NOT 给出单因确定性归因，MUST NOT 据此建议针对特定根因的修复方向（如按「模型改坏代码」假说建议预检重跑）；建议动作仍须给出，但转向取证/止损方向（如补齐失败面明细留存、加预检），不依赖未证实的根因假说

#### Scenario: 证据足以裁决时才给单因结论

- **When** 当日存在直接证据钉死单一根因（如根治提交自述、可复现的最小证伪）
- **Then** 结论可写确定性归因并附证据引用（commit/日志行/明细档字段值）

#### Scenario: 错误归因以新条目更正

- **When** 后续窗口核实出既有条目的根因归因有误
- **Then** 以新条目显式更正（写明证据与正确结论），不回改历史条目原文
