# ADR-020：provider 4xx 熔断进程内存态、状态码判据、熔断期不动状态机

date: 2026-09-02
status: accepted

## Context

provider 网关 4xx（模型下线、余额不足）按普通失败处理、走 max_retries 重试：状态机反复 ready→implementing，每次派发都 autostash，故障窗口内 stash 累积、冲突概率放大，token 持续燃烧。失效转移（ADR-004）解决「换一家继续」，本条裁定单 provider 抑制派发的熔断机制本身。

## Decision

- 熔断判据只认从 CLI 输出解析出的 HTTP 状态码：4xx（含 401 余额类）计数熔断；5xx 与网络错误属瞬态走既有 retry、不进熔断计数；解析不到状态码不计数。半开探针沿用同一解析路径，解析不到 code 视为失败。
- 熔断状态（计数、冷却时间戳）为 daemon 进程内存态 + 常量阈值，不落盘、不进配置 UI：daemon 重启即清空，最坏代价是重新探测一次（探针成本 = 一次 4xx）。
- 熔断期派发失败不调状态机回退（spec 保持原状）、重试计数不增；冷却结束由既有轮询自然重排；熔断持续超过 stuck 阈值由既有巡检唤起人工（充值/换模型）。
- 多项目 daemon 各自内存态独立判定，互不影响，符合每项目独立 daemon 架构。

## Consequences

- 故障窗口内零派发、零烧钱、零 stash 积累；4xx 属持续故障信号（下线/欠费通常远超冷却期），误熔断的代价（冷却窗口内该 provider 挂起）小于持续重试。
- 与 ADR-004 分层互补：4xx 驱动本条熔断、不驱动链前进；5xx/连接异常走链切换、不进熔断计数。
