# ADR-150：新增文件信号必须三件齐登，防滞留信号被未来消费成未请求动作

date: 2026-09-24
status: accepted

## Context

dashboard 控制平面以 `.fenix/` 下的请求文件为信号（取消/审批/唤起/触发等），由 daemon 主循环扫描消费。新信号的写入端点若只登记扫描消费点，daemon 未运行时写入的信号会永久滞留，daemon 下次启动把它消费成一次用户并未请求的动作；损坏 JSON 滞留还会卡死扫描循环。

## Decision

- 每新增一个文件信号 MUST 同时登记三件：(1) 主循环固定节拍的消费点；(2) daemon 启动/停机清扫路径（损坏文件删除防卡死、停机残留处理，与既有信号同款）；(3) 托管守卫——daemon 未运行或项目非托管态时写入端点拒绝写入：信号无人消费即不得受理，否则必然滞留并被未来消费成未请求的动作。
- 手动触发型信号消费后即时清理信号文件并幂等：重复写入/重复消费不产生重复动作。
- 新车道接入既有通用机制（取消、运行进度、产物读取）时复用既有信号与契约，不另立平行通道；新信号文件属 gitignored 运行时面，不构成交付物。

## Consequences

- 文件信号族的「写入—消费—清理」闭环完整，滞留信号不再可能被消费成未请求的动作；「三件齐登」成为新增信号的接线核对清单义务。
