# spec：stray-attribution-log-dedup

## 能力

主树散件盘点器对「tracked WIP 归因到主树活交互会话」的 info 留痕按状态变化收敛，稳定期以小时聚合行替代逐轮重写。

## 需求

### R1 状态变化驱动留痕

- 同一文件集且同一占用者会话的归因，仅在首次出现时落全量 info 行。
- 文件集变化（任一文件增删）或占用者变化（会话标识变更）视为状态变化，落一条新留痕。

### R2 稳定期小时聚合

- 状态未变的连续盘点轮次不落逐轮日志；自上次留痕起满 60 分钟落 1 条聚合行，格式含重复计数（如「近 1h 重复归因 N 次，归因未变: <文件集>」），随后计数与窗口起点重置。

### R3 归因解除闭环

- 归因解除（文件消失、占用者清空、宽限升级处置接管该文件）时补一条解除行；解除后再次归因按首次计数。

### R4 约束

- 不新增 AdminStore signal_type，不进人工队列（维持模块注释既有约束）。
- 去重状态为进程内内存态，不做持久化；重启后首轮按首次落日志（允许一条重复）。
- 日志级别维持 info。

## 验收

1. 同文件同占用者连续两轮盘点仅 1 条留痕，第三轮起无新增。
2. 跨 60 分钟窗口后恰落 1 条聚合行且含正确重复计数。
3. 文件集变化、占用者变化、归因解除三个事件各触发一条新留痕。
4. tests/test_maintree_stray_wip_sweep.py 既有用例全部回归通过。
