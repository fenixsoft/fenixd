# ADR-173：文件信号单槽位的可接受性判据=写入方把 conflict 变显式拒绝——否则多槽位化且写侧如实回报

date: 2026-09-28
status: accepted

## Context

文件信号族曾全部单槽位（信号文件在途时写入返回 conflict）：admin invoke / run cancel / approve push 的调用方都把 conflict 变成用户可见的显式拒绝（HTTP 409），单槽位可接受；唯 scheduling kick 的调用方丢弃返回值、接口报成功、前端宣称「立即恢复调度」，把静默丢弃伪装成成功——同一时间窗内不同 SPEC 的信号互相顶掉，且陈旧信号文件永久占槽锁死后续唤醒。同族缺陷（推送通道单槽位滞留锁死）此前已复发生过。

## Decision

- 单槽位的可接受性判据 = 写入方是否把 conflict 变成显式拒绝；不满足即多槽位化：目录 + 每主体一文件（文件名即主体名，kebab 白名单校验后可直接作文件名），天然消除跨主体互斥，同主体重复写入同路径覆盖幂等。append 型队列（并发防护复杂、无法对同主体去重）与「单文件+冲突覆盖」（静默吞掉先写入者）均否决。
- 写侧必须如实回报：写入失败结构化返回（ok/file/error）并经 API/CLI 透传；主体变更本身已成功时保持成功语义 + warning 如实说明兜底路径（周期扫描），禁「操作失败」误导用户重试已无操作路径，更禁假成功文案。前端与 CLI 两个动作方都须接入同一回报契约。
- 临时文件命名不得匹配消费侧扫描谓词（按后缀筛选时临时名不带该后缀），写入走 mkstemp + os.replace 原子落位。
- 陈旧信号回收挂消费方时钟：启动清扫 + 周期对账；阈值内条目先消费再删（唤醒幂等，不丢唤醒），超阈值仅删不消费（长期停机积压不得引发集中派发）；阈值为代码常量不进配置。
- 信号路径常量与写入语义落共享中性模块，写入方与消费方 import 同一定义，禁各自复制路径常量（防漂移、防分层倒置）。
- 存量旧单文件由消费侧只读兼容（受同一陈旧阈值约束，消费后自然消失），零人工迁移。

## Consequences

- 新增文件信号除 ADR-150 三件套外必须过本判据；重复唤醒由既有 handler 幂等谓词吸收，不为写入侧加锁。
