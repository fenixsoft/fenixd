# ADR-171：产物门判缺失必须穷尽同一逻辑产物的合法落点——fail-closed 只针对确实缺失，共享树候选须新鲜度守卫

date: 2026-09-28
status: accepted

## Context

实现收尾审查产物门只探测 worktree 内单一候选路径，缺失即判失败，无任何回退。而框架经 `--add-dir` 显式授权主树 verify-progress 目录、拷回机制也以主树为单向目标——「同一逻辑产物合法地存在于另一棵被授权的树」是设计上可能且合法的状态。2026-09-21 实测：实现者以主树绝对路径落盘合规报告，门恒判「报告缺失」，7 次原地重试（约 $3.4/次）全数失败。归因不是产物不存在，而是把「worktree 内没有」等同「产物不存在」。

## Decision

- 产物门判缺失前必须枚举同一逻辑产物的全部合法落点：run 专属树（worktree）优先、跨 run 共享树（主树）回退；两处皆缺才产出缺失归因，文案列出全部已探测路径。fail-closed 的正当边界是「确实缺失」，不覆盖「在另一合法位置存在」。
- 共享树候选必须过新鲜度守卫（复用既有产物校验体的存在/非空/新鲜/可解析判定，锚定本轮启动时间、resume 豁免沿用既有语义）——主树跨 run 共享、陈留风险真实；run 专属树免 mtime 硬拦（本轮写出必晚于启动，加拦无收益且在时钟/挂载边界引入伪失败）。
- 候选集工程纪律：候选路径 resolve 后去重（防同一文件被判两次新鲜度）；去重后沿用先出现者的校验模式保现状零变化；载体不可得时候选集为空，直接放行不校验（缺载体不误判缺失）；共享树候选仅在载体为真实 str/Path 时加入（替身 mock 任意属性恒 truthy，会绕过既有 except 捕获面炸测试）。
- 校验体单点：各候选读到数据后走逐字相同的校验函数，禁双实现漂移。
- 门只读不写：不把主树候选回拷补齐 worktree（写侧修正归写侧车道），同一场景下次 run 可能重复触发是接受的取舍。

## Consequences

- 「合法存在于另一棵被授权树」不再误判缺失，主树陈留报告仍被新鲜度守卫拦截；代价是 resume 轮的共享树候选只剩内容自洽判据（接受，出现误放行实测再引入更细判据）。
- 后续新增产物门一律按多候选模型设计，禁「单一候选路径 + 缺失即打回」形态复现。
