# ADR-151：门控守卫挂自动通道汇聚点并双落点覆盖，顺延零 STATE 写、陈旧锚点放行

date: 2026-09-24
status: accepted

## Context

定时拾取、在飞评审等门控若只挂单个派发入口，定时重派、恢复链、家族/裁决车道直入队列的旁路会绕过守卫（实证：绕过通道使门控失效）；事件处理器收到的 entry 是扫描期快照，按陈旧快照判定会误拦/误放；命中守卫若写 `error` 字段，事件总线会把它当状态变更自触发，形成「跳过→事件→再跳过」反馈环。

## Decision

- 守卫 MUST 挂在全部自动通道的汇聚点（handler 入口），并 MUST 以同一判据覆盖队列候选筛选与实际派发筛选双落点——直入队列的旁路不经 handler，只补 handler 一处即门控失效。
- 判定 MUST 在方法内重读当前 STATE（`read_one`），禁用调用方传入的 entry 快照；条目读不到时按该链路既有 not-found 语义处理，守卫禁抢先吞掉。
- 基础谓词保持无条件纯判定（不带配置参数）；配置维度的组合谓词单点定义、按名自明语义。组合谓词内部禁吞异常——fail-open 收口留在各调用点既有 try/except，谓词内吞异常会使调用点 except 分支与告警留痕永不可达。
- 命中顺延/跳过：零 STATE 写入、禁写 `error` 字段，审计走 `_` 前缀侧车字段随 STATE 持久化，日志 debug 级零噪音（守卫在扫描节拍上高频命中）。
- 在飞判据分层：进程表为真相，流文件「新鲜且末行非终态」兜底，判定异常 fail-open 放行；「陈旧锚点」（run 已终态、锚点残留）按「无在飞」放行并 WARNING 交既有恢复路径清理——禁顺延派发（自造死锁），禁消费点按「锚点非空」直接自清（与 fail-open 叠加可在 run 在跑时放行并发派发）。
- 人工通道（CLI/Dashboard 直调共享函数）不经 handler，MUST NOT 被守卫拦回；不经 handler 的内部直调属覆盖边界，MUST 显式登记、禁声称已覆盖。

## Consequences

新增门控的接线核对清单固化为「汇聚点+双落点+重读+零写+陈旧放行」；旁路失效与反馈环形态被结构性排除；守卫判定单点可测、既有 fail-open 用例不转红。
