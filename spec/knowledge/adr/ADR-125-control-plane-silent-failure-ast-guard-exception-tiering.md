# ADR-125：控制平面静默失效——AST 静态守卫与异常分层升级

date: 2026-09-20
status: accepted

## Context

控制平面复位路径的调用点签名写错这类缺陷呈现「CI 全绿但代码是坏的」：运行时断言只在真的执行到那一步才炸，而事故恰恰是那条路径从未被执行；测试替身签名与真实现漂移产生假阴性。同时 `except Exception` 把编程错误（重试无意义）与运维失败（重试可能有救）压成同一 WARNING，复位失效被静默降级。

## Decision

- 静态守卫用 AST 扫描 + 单元测试承载（调用点签名比对、替身保真检查），不引入重型类型检查、不靠运行时断言：AST 零依赖、确定性、可在现有 pytest 内运行，且不依赖被测代码真的被执行。
- 守卫规则只在「方法名全库唯一签名 + 无变长参数」时参与比对（跨类同名方法语义不同，「同名即同契约」只在唯一签名时成立），并断言候选集规模下限，防守卫退化成永远绿。
- 控制平面复位路径的异常分层升级：编程错误签名 `(TypeError, AttributeError, NameError)` 升级人工告警并携带 core/ 内最深调用点栈帧；运维异常（OSError/子进程/网络）保持 WARNING 降噪——全部升级会淹没在运维噪音里。
- 右关联设计不可破坏：处置记录先落盘（永不重抛），升级告警自身失败只记日志。
- 状态悬置探测为独立短阈值信号（三条件与：无活动 run 文件 + 无存活子进程 + 无待派发），不改既有 stuck 长阈值语义；testing 态补运行期恢复出口，悬置不再必须等重启兜底。

## Consequences

- 纯加地板零既有欠债（落地实测白名单外违规为 0）；静态守卫可能误报同名方法，由唯一签名约束与白名单控制，长 run 误报由三条件与与 mtime/进程双兜底排除。
