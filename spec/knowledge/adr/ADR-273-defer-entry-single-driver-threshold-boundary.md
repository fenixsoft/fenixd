# ADR-273：顺延条目单驱动不变式（周期消费者只接手无 Timer 驱动的超阈值条目）

date: 2026-10-13
status: accepted

## Context

spec 目录在飞顺延条目由 60 秒 merge-only Timer 链驱动重试；超过熔断阈值（宽限窗口或轮数上限）后顺延出口提前返回、不再排 Timer，条目陷入无人接手的悬置（Timer 链因进程重启中断时尤甚）。若让周期消费者无差别接手全部 pending 条目，会与存活的 Timer 链同拍双驱动同一分支：git index.lock 竞争产生的失败会被 bump_counters 误计入顺延轮数，制造假失败并提前熔断。

## Decision

- 一条顺延条目任一时刻至多一个驱动源，驱动权按熔断阈值分界：未超阈值条目由 Timer 链独占驱动，周期消费者必须跳过；周期消费者只接手「已超熔断阈值（与顺延出口同判式）且仍 pending」的条目——此类已无存活 Timer，接手天然无双驱动。
- 多车道并存时按标志分流：带 WIP defer 标志的条目归 WIP 消费者车道，spec 目录顺延消费者跳过。
- 消费者接手重试每条目至多一次（daemon 生命周期），失败维持既有熔断告警（去重幂等）与人工通道，不无限节拍重试。

## Consequences

- 熔断不再等于无人接手：Timer 链中断（含进程重启后的 pending 残留）由周期消费者在节拍内接手，自动兜底与人工告警分层。
- 代价是消费者与顺延出口的阈值判式必须保持同源，两处判式漂移会同时制造双驱动（判式偏松）与漏接手（判式偏紧）两类缺陷。
- 后续为各顺延链新增周期消费者受同不变式约束：先证明目标条目无存活驱动源，再接手。
