# ADR-286：场景顶层拯救单点接入 + 原子重写落地 + 读端零防御

date: 2026-10-27
status: accepted

## Context

场景规划产物 `test_scenarios.json` 的读端硬门（`load_scenarios`）对顶层非数组整份拒收，而同目录 `scenarios.json` 持久化集本身就是 dict 形态，两文件同目录形状相反且规划任务书无显式顶层契约，agent 交付 dict 包裹形态（`{"spec":…,"scenarios":[…]}`）后被整份拒收；拒收反馈硬编码「重新输出全部场景」，agent 全量重建 25 个场景，一层包裹错误放大成两轮 116 轮/$8.61 的浪费。核查证实拒收路径并不销毁产物，真正放大器是反馈文案而非产物丢失。

## Decision

- 拯救形态收窄到「顶层 dict 且含非空 scenarios 数组」唯一形态：该形态语义无歧义；解包后必须重过既有全部场景校验才采纳，等价于零成本重验；其余非数组顶层（字符串/数字/列表套列表、dict 缺 scenarios 键等）不拯救照常拒收。
- 落地 = 以解包后的纯数组**原子重写产物文件**，不是仅内存采纳：仅内存采纳会让其余 `load_scenarios` 读端（fastlane、verdict_evidence、pipeline 多处）在后续轮仍撞顶层硬门，冻结层顶层读端也会持续按「顶层非列表」告警跳过；重写为纯数组后这些读端按既有语义自然恢复。
- 拯救助手只接在验收归因路径单点，`load_scenarios` 本体与其余读端一律不接助手：全部读端恒可假设顶层为纯数组，禁止（也无需）各自加解包防御；后续新增场景文件读端受同约束。
- 解包属框架改写 agent 产物，必须留痕（解包前顶层键、条目数、落地结果）便于事后审计；契约由静态模板与运行时注入双侧明示，解包只作一次性止损，不弱化契约约束。

## Consequences

- 新增场景文件读端时不需要也不能各自实现 dict 解包防御，防御面收敛在验收归因单点，读端代码保持最小。
- 机械解包存在被 agent 依赖成「包错也无妨」的风险，以双侧契约 + 留痕 + 反馈仍指出错误类别对冲；解包仅覆盖唯一无歧义形态。
- 格式/内容失败分类按失败发生阶段判定、取宽口径（小改动可修复归格式类），不新增错误文本解析器；误判代价是多给一条修复指引，不阻塞重建路径。
- 解包重写产物文件与并发冻结写回存在理论竞态，但落地点在验收失败路径（该路径下产物本将被 replan 覆盖），竞态窗口与既有 replan 写点相同，不新增暴露面。
