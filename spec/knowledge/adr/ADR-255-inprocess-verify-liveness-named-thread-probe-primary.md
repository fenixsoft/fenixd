# ADR-255：进程内验证活性判定以命名线程探测为主判据、进度 mtime 辅证，线程臂无时间上界

date: 2026-10-08
status: accepted

## Context

全量验证以 daemon 进程内线程（`fenix-verifier-<spec>` 内 asyncio.run）执行，无 `verify-<spec>-*.jsonl` run 文件、无独立子进程；孤儿/无驱动判定四条件（run 文件 mtime、存活子进程、有意等待、派发队列）全部以「外置 run 形态」为前提，对进程内形态结构性失明。2026-10-02 cimbar-airgap-transfer 实证：验证活跃期被判孤儿态两条告警，recovery 出口与处置复位直通道先后重派，三个 23 场景全量批交错执行，另付 $1.289 admin 调查 run。写侧活性信号早已存在（verify-progress 逐场景原子写），缺的只是判定读侧消费。

## Decision

- 命名线程探测为主判据：`threading.enumerate()` 命中 `fenix-verifier-<spec>` 活线程即判有驱动，零时间窗、零调参；线程名从派发队列命名单点（`agent_worker_thread_name`）取值，判定侧与派发侧禁各自硬编码字面量。线程命名自此是进程内车道对判定读侧的显式契约——后续任何进程内车道必须按 `fenix-<agent_type>-<spec>` 命名空间注册线程，否则对无驱动判定不可见。
- 进度文件 mtime 作辅证 OR 臂，窗口按信号源节奏独立设定：`.fenix/verify-progress/<spec>.json` mtime 落入专用活动窗（缺省 900s、对齐孤儿阈值）即判有驱动，禁复用 run 文件 120s 宽限——各活性信号源写节奏不同（进度文件逐场景写、单场景可静默 4-5 分钟），借用他源窗口会把「正在长跑」误判为停滞。run 文件 120s 宽限本身保持不动。
- 线程臂不设时间上界为显式接受的取舍：挂死不退出的线程持续豁免孤儿判定并使复位直通道持续跳过重派，回收依赖验证车道既有超时与升级机制，不为线程臂另设窗口（保零调参）。AND 组合不可用（跨进程视角线程探测不可得）；OR 组合下「run 崩溃残留新鲜进度文件短暂豁免」为已接受残留风险，下一窗口超窗自愈。
- 终态口径不变量：线程退出且进度文件超窗后，判定结果与既有外置形态口径逐位一致——豁免只覆盖「确实在飞」的窗口，不产生任何永久豁免态。
- 单次消费出口不设延迟队列：处置复位直通道复核命中时只跳过本次重派（transition + 清 error 复位语义保留），不做「延后重派」——处置复位单次消费无回放机制，延迟队列无人触发；且在飞验证本身即重验，其结果路径照常推进状态，收尾后再派反而重新制造重复批。

## Consequences

验证活跃期的孤儿误报与重复验证批从判定读侧根治，三个出口（周期探测、运行期恢复、处置复位直通道）经同一 helper 收口豁免。代价：判定读侧与线程命名单点形成耦合，命名单点被改动而判定侧未同步即静默失明（以单点取值约束兜住）；挂死线程的无限期豁免是已知盲区，依赖验证车道超时兜底——与 ADR-252/253「只观测、干预交给既有机制」同一取向；进程内车道数量增长时，此线程命名契约成为新增车道的必备注册义务。
