# ADR-166：自驱动批循环收尾三态化，consumed 判据 = 条目已离开可选池

date: 2026-09-28
status: accepted

## Context

自动修复车道的批收尾是 bool：仅批成功才再投递推进下一批，任何失败都终止链，整队 `open` 条目当夜停摆。既有注释反对「失败即再投递」的理由是同步模式无限递归 / executor 模式无限空转——该理由只对「条目未离开可选池的失败」（如建树失败每轮复现同批）成立；凡条目已移出可选池的失败，重投递循环必然收敛。直接按「失败也再投递」放开，会同时放进真正会空转的那类失败。

## Decision

- 自驱动再投递的批循环，收尾 MUST 三态化：`success`（批核销）/ `consumed`（该批条目已全部离开可选池）/ `halt`（环境性失败，条目仍在可选池）。`success` 与 `consumed` 均自驱动再投递，仅 `halt` 终止并回落既有 full scan 兜底。
- consumed 与 halt 的分界判据是「该批条目是否已全部离开可选池」，不是「失败与否」：条目入失败档案、入链内跳过集、核销都构成离开；建树失败、worker 异常等条目原地不动的失败必须 halt，再投递只会逐轮复现同批。
- 收敛保证依「可选池严格单调缩小」成立：向该循环新增 consumed 失败路径时 MUST 同时给出该路径条目的出池去向，无出池去向的失败不得接入自驱动分支。
- 「选批为空」（可选条目全被排除）是 consumed 链的正常收敛出口，按排除来源给中性文案，MUST NOT 误报为故障。

## Consequences

- 单批失败不再堵塞车道，剩余条目当夜继续消费；代价是消费型失败的重试成本转嫁为下轮重跑（夜间维护车道接受此取舍）。
- 消费型失败与空转型失败获得机械分界：后续向该循环（及同构自驱动循环）新增失败路径时，分类问题是机械的——先答「条目是否出池」，再定 consumed/halt。
