# ADR-152：顺延/冷却/抑制机制必须有界回落并显式点名解除者

date: 2026-09-25
status: accepted

## Context

顺延/冷却类机制以「暂不推进」替代报错与升级：无硬上限会把真实卡死洗成健康（恢复观察被活性痕迹长期顺延），也会使 spec 永不再被处理（merge-back 顺延暂停对 spec 的唯一驱动——原事故靠系统重派收敛，换成无限顺延反而更差）。周期巡检不覆盖全部状态组合，不能指望既有告警通道兜底顺延窗口。

## Decision

- 任何顺延/冷却/抑制 MUST 设硬上限，到期回落既有升级/告警通道，禁无限顺延。
- 顺延 MUST 显式点名解除者：库内不存在自然解除通路时（无人为在飞 spec 提交该面的通道），无解除者的顺延即无限期停摆；解除条件必须落在唯一有效写入面上（主树侧提交与分支侧提交不可互替）。
- 抑制判定=窗口计数+冷却锁存双条件任一命中：窗口计数会因条目老化提前退出，锁存保证承诺时长；抑制告警按边沿落一次，禁随扫描 tick 重复堆积。
- 自触发循环检测（重启/重派由自身后果再触发）的连续计数 MUST 持久化跨进程累计——只放进程内存则单进程最多累计一次，阈值恒不可达；计数单位=重启周期而非 tick。
- 触发时聚合的上下文清单 MUST 有界（最近 N 条+截断计数），防 evidence/description 与告警存储无界增长。
- 新告警禁复用「写入即自动 mark_handled」的既有 signal_type（会被当已处置吞掉）；核销 MUST 内联在状态过期分支同步执行（库内无到期事件分发机制），候选须过滤已处理条目；跨时钟域窗口（monotonic 计的冻结时长 vs 墙钟写的 created）锚点 MUST 加偏差裕量，禁照抄等长节流窗口。

## Consequences

抑制类机制三要素固化为「有界上限+点名解除者+边沿告警」；真卡死不被活性痕迹洗白、顺延不停摆；自触发振荡可达阈值并升级人工。
