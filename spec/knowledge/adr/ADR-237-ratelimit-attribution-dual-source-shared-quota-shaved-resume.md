# ADR-237：限流重派闭环双车道化——归因双源、共享配额统一消费与剃余续跑核销覆盖门

date: 2026-10-06
status: accepted

## Context

ADR-202 确立的限流重派例外以三个前提成立：终态归因靠错误文本命中 429 分类；消费落在唯一生产调用方（code-review 周期 worker）的收场分支；重派复用原 manifest 全量重跑。2026-10-06 手动全仓审查事故（218 轮 / 13.89 美元死于账户级 429，自述 16 片仅落账 4 片）证明三个前提同时失真：stderr 经降噪后 429 文案只剩 Exit code: 1，归因恒 False、意图未登记；手动触发 worker 从不消费重派意图，「唯一消费方」前提自手动通道落地起失效；全量重跑意味着重烧全量成本，且部分覆盖一旦收场成功会白洗核销存量条目。

## Decision

- **归因双源**：限流终局归因不得单靠降噪后的异常文本。异常文本分类先行，未命中时回退 result 事件判定（异常挂载的 `api_error_status` / result 文本，仍不足再兜底重读 run jsonl 最后一条 result 事件）。归因事实源取未经降噪的事件层，是 ADR-235「留证层不过滤、降噪只作用摘要与归因消息」在终态归因上的延伸。
- **双车道共享配额统一消费**：重派意图消费收敛到单一共享入口（admin_monitor 实例的重派计数与待发 Timer 句柄），手动与周期两车道都只上交意图，共享上限 1 与单飞让位，防双车道叠加各耗额度；新增触发入口必须上交共享入口、不得各自记账。admin_monitor 未装配（fallback 宿主）时意图记日志放弃并保持告警可见，不静默丢弃。
- **剃余续跑**：重派 manifest = 原清单 − 重派链累计已覆盖（产物 `file` 字段并集对原 manifest 求补，只删不改序），`redispatch_of` 链路保留；剩余为空不重派，剃余失败回退全量重派。
- **核销覆盖门**：全仓快照核销解锁以「本轮累计覆盖 ⊇ 完整 manifest」为门（重派 run 以原 run manifest 为基准跨链累计，普通 manual_full run 以本轮 manifest 累计）；守卫唯一落点在核销执行收尾分支而非重派决策侧，manifest 缺失/为空/守卫异常一律按未覆盖锁定——宁锁勿白洗。

## Consequences

- 任一通道死于 429 都自愈一次且总重派额不变；全仓审查死中途不再重烧全量成本；部分覆盖永不白洗核销存量条目。
- 消费共享入口成为单点：admin_monitor 未装配的 fallback 宿主上限流重派不可用，只留告警取证；剃余依赖产物 `file` 字段落账质量，落账缺失会扩大重派范围（回退全量为下界）。
- ADR-202 的有界例外裁定（仅限流、仅一次、冷却到期后）与意图登记/消费拆分继续成立；其「唯一生产调用方」与「复用原 manifest 全量重跑」表述由本裁定取代。
