用户规则原话：「arbiter只修SPEC问题，不修框架缺口，发现框架缺口时，在自省的todo.md中记录，由框架自改进来统一立项修复框架缺口。」

背景：arbiter 立项通道产出两条「提案最小成文」草案（fix-scenario-revision-choice-registration-surface / fix-escalation-freeze-vs-parallel-admin-race）均被 spec-review 两轮否决冻结（一 substantive 前提被证伪、一 format 方案主体缺失），实为车道职责越界——框架缺口不该由 arbiter 立项。用户确认按上述红线治理：拆 arbiter 立项通道，框架缺口发现改记 todo.md，由自进化车道统一消费立项。
