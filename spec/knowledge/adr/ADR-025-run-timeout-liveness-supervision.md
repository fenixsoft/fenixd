# ADR-025：运行时限以活性监督取代墙钟硬杀

date: 2026-09-02
status: accepted

## Context

纯墙钟 deadline 到点无条件杀进程：长任务被定时误杀，而恢复侧不感知存活子进程与 worktree 内存锁，误杀后连锁假 ready 滞留约一小时。反向问题同样存在：纯启发式无法区分「真推进」与「循环空转」——agent 可以高频产出却无进展；全量转录喂给 LLM 判定则成本不可接受。

## Decision

- 运行时限 = 活性评估 + 受限续期 + 绝对上限：判定窗口内零事件直接判停滞（不调 LLM）；有活动才把窗口内事件摘要（工具序列去重计数、末条输出片段）交判定 LLM 出 advancing/stagnant 结论。
- 判定调用为轻量单轮 SDK 调用，复用 fallback 模型路由（无 provider 分配的默认网关路径），不落正式 run 文件，结论写被监督 run 的 jsonl 与 daemon 日志。
- 续期 = deadline 顺延，且必须同步顺延调度侧 stuck 检测基准——「agent 还活着却被 stuck 规则重置」是事故根因环，顺延基准是续期的组成部分而非可选项。续期次数与总时长双上限，命中无条件终止。
- 锁与存活的唯一真相是进程表：worktree 内存锁可按进程扫描重建（daemon 启动首扫 + 疑似陈锁回收）；存活探测 pgrep 锚定 worktree 目录字面量，以流文件新鲜度二次确认。
- 派发锁冲突走固定退避序列，不动 attempt 配额、不写 retries exhausted；恢复动作后登记观察项（镜像落盘）到期闭环复查，复查不过发人工信号；ready 滞留纳入通用巡检。

## Consequences

- 长任务不再被墙钟误杀，空转燃烧被绝对上限封顶；判定 LLM 误判 advancing 的长尾由上限与预算兜底，证据全量留痕。
- 整体能力有 enabled 开关，一键回到纯墙钟硬杀；新增监督类阈值遵循 ADR-022 的派生纪律。
