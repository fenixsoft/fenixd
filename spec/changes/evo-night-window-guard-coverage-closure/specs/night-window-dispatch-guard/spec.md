## ADDED Requirements

### Requirement: 缺省静默窗覆盖散布断窗
夜间静默窗缺省值 SHALL 为多窗「03:00-03:15,04:15-04:45」，全部消费点（code-fix 批守卫、周期审查顺延、admin 唤起避让、自进化避让）经同一解析器生效；运行时 config 显式配置仍可覆盖缺省，空串/off 禁用语义不变。

#### Scenario: 窗外断连波纳入缺省覆盖
- **WHEN** 以缺省配置在 03:05 判定 code-fix 夜间批是否可派发
- **THEN** 03:05 落入 03:00-03:15 窗、判命中顺延，不再因缺省单窗 04:15-04:45 而放行

### Requirement: 自进化车道跨窗避让
自进化检查点派发前 SHALL 做「派发时刻＋近几轮自进化归档实测时长估计」与静默窗列表的相交判定，命中任一窗即本轮跳过（写 reason=night_quiet_window_deferred 日志），SHALL NOT 消费水位或就绪标记；窗后巡检自然重触。

#### Scenario: 自进化分析 run 不再驶入断连窗
- **WHEN** 检查点于 02:16 触发、近几轮归档时长估计的预计结束落入任一静默窗
- **THEN** 本轮跳过并留痕，水位与就绪扫描状态不变，链路恢复后下轮巡检正常派出

### Requirement: 派发前连通预检
维护车道 run 派发前 SHALL 做一次轻量连通探测（API 域名解析、秒级超时）；探测失败 SHALL 顺延本轮派发并写含 reason 的跳过日志；探测自身异常 SHALL NOT 阻断派发（fail-open）；仅挂派发前，不影响在飞 run。

#### Scenario: 断连活跃期不再派发秒死 run
- **WHEN** DNS 不可用（如 03:01 链路恢复后 DNS 余波期）且车道触发派发
- **THEN** 探测失败、本轮顺延并写跳过日志，不产生秒死 run 与升级告警噪音
- **WHEN** 探测实现自身抛出异常
- **THEN** 记日志后照常派发，主派发路径不被探测故障阻断
